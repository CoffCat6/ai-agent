# 定时任务（自动化）方案

来源：docs/26 批次 H4（无定时任务/自动化）。2026-11-10 设计定稿，四项关键决策当日与
维护者确认（见 §0）。本方案维持 docs/26 §8 的边界：不做任意 cron 表达式、不做任务依赖
编排、错过的周期不补跑——把「到点以指定模型跑一个提示词、结果落会话」做扎实，而不是
把应用做成半成品调度平台。

## 0. 决策记录

| # | 决策 | 结论 |
| --- | --- | --- |
| D1 | 执行载体 | **无头 AIAgent**（独立会话、独立 SQLite 连接），不走 tab/controller 路径 |
| D2 | 无人值守权限 | 任务权限档**默认 `plan_only`**，可放宽到 `auto_edit` / `full_access`；AIAgent 新增 `setUnattended` 把确认分支改为直接拒绝（不挂起）；另有全局墙钟上限兜底 |
| D3 | UI 入口 | **侧栏工具条第五按钮 + 独立对话框**（知识库同款模式）；侧栏最小宽度 180 → 208 |
| D4 | 调度形态 | 三种：每天 HH:mm / 每周 X HH:mm / 每 N 小时（1–168），**不做 cron** |
| D5 | 错过策略 | 到期时应用未运行（或休眠）→ 跳过并记 `missed` run 留痕，**不补跑**（docs/26 既定） |

## 1. 现状地基核查（2026-11-10，决定设计的四个事实）

| # | 事实 | 证据 | 影响 |
| --- | --- | --- | --- |
| 1 | 工具确认**没有超时、没有自动拒绝**：无人值守时触发 RequiresConfirm 会永久挂起在 `AwaitingToolConfirm`，队列不再推进 | `AIAgent.cpp:3290-3309`（挂起）、`:3201`（挂起期间不开新轮） | 无人值守执行必须有防挂起策略，不能"沿用权限档然后祈祷" |
| 2 | 任务墙钟超时机制**已存在但默认关闭**（`kDefaultTaskTimeoutMs = 0`，对应设置键已移除）；开启后到期 `stop()` 并把挂起确认一并封口 | `AIAgent.h:60`、`AIAgent.cpp:450-457` | 免费的安全网：给定时任务强制开超时即可 |
| 3 | `PlanOnly` 档**天然不挂起**：Safe/只读直通，其余直接拒绝（不弹窗、回灌可读原因 + `tool_blocked` 审计） | `AIAgent.cpp:3259-3275` | 默认权限档选 `plan_only` 即"永不挂起" |
| 4 | **没有静默建会话入口**：`addTab`/`openConversation` 都会激活 tab；打开的会话上限 12 | `AgentViewModel.cpp:591-596`、`AgentViewModel.h:195` | 定时任务不走 tab 路径（占额度、抢焦点、确认进全局模态队列） |

可复用的现成件：

- **agent 工厂**（`main.cpp:604-629`）：每 agent 独立 `SqliteMemory` 连接 + 协议服务 + Episodic + 自动标题，多 tab 并发写已验证——抽出为共享函数，调度器复用
- **托盘通知门控**（`main.cpp:1202-1216`）：偏好开关 →「主窗不在前台才打扰」→ 托盘可用性，三层门控后 `showMessage`
- **自动备份定时器**（`main.cpp:1353-1377`）：QTimer + 偏好驱动 + `aboutToQuit` 置旗标限时等待，是调度器的停机样板

## 2. 范围

**做**：任务 CRUD（名称 / 提示词 / 模型 profile / 调度规则 / 权限档 / 通知开关 / 启停）；
三种调度形态；到点新建会话执行、结果落 `sessions`/`messages`/`trace_nodes`/`audit_log`
全套（既有持久化链路零改动）；完成托盘通知；执行历史（状态/耗时/摘要/跳转会话）；
「立即运行」便于验证；全局单次运行时长上限。

**不做**（§12 有 v1.5 候选）：cron 表达式；任务依赖编排；错过补跑；应用未运行时的云端
触发（定时只在应用运行期间生效，UI 明示）；托盘通知点击跳转会话（现有托盘根本没连
`messageClicked`，v1 不捎带）。

## 4. 数据模型

按 `file_checkpoints` / `session_todos` 惯例：`CREATE TABLE IF NOT EXISTS` 进
`createTables()`，**不动 `user_version`**（`SqliteMemory.cpp:658-662` 注释点名的路径）。

```sql
CREATE TABLE IF NOT EXISTS scheduled_tasks (
  id TEXT PRIMARY KEY,              -- UUID
  name TEXT NOT NULL,
  prompt TEXT NOT NULL,
  profile_id TEXT NOT NULL,         -- 触发时按 id 解析；失效 → run=failed，可读原因
  profile_name TEXT NOT NULL,       -- 创建时快照，列表展示/诊断
  schedule_kind TEXT NOT NULL,      -- 'daily' | 'weekly' | 'interval'
  schedule_value TEXT NOT NULL,     -- JSON（见 §5）
  permission_mode TEXT NOT NULL DEFAULT 'plan_only',
  enabled INTEGER NOT NULL DEFAULT 1,
  notify INTEGER NOT NULL DEFAULT 1,
  last_fired_at INTEGER,            -- 上次触发时刻（无论成败），due 计算锚点
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL
);
CREATE INDEX idx_scheduled_tasks_enabled ON scheduled_tasks(enabled);

CREATE TABLE IF NOT EXISTS scheduled_task_runs (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  task_id TEXT NOT NULL,
  session_id TEXT,                  -- 产生的会话，「打开会话」用
  status TEXT NOT NULL,             -- 'running'|'success'|'failed'|'timeout'|'stopped'|'missed'|'skipped_busy'
  trigger_source TEXT NOT NULL DEFAULT 'schedule',  -- 'schedule' | 'manual'（列名避开 SQL 关键字 TRIGGER）
  started_at INTEGER NOT NULL,
  finished_at INTEGER,
  error TEXT NOT NULL DEFAULT '',   -- 失败原因（profile 失效/超时/停机）；null QString 须归一空串再绑定
  summary TEXT NOT NULL DEFAULT ''  -- 首条助手回答截断 ~120 字符
);
CREATE INDEX idx_scheduled_task_runs_task ON scheduled_task_runs(task_id, started_at DESC);
```

- DDL 经 `execDdl`，索引命名 `idx_<表>_<列>`（同 `SqliteMemory.cpp:654-656`）
- 保留：每任务留最近 30 条 run（`kMaxRunsPerTask = 30`），插入时清理；删任务级联删 run
- `profile_name` 是展示快照，运行时**只认 `profile_id`**——profile 删除/改名后任务不静默
  失效，下次触发记 failed 并在通知与历史中给出「模型配置已不存在」的可读原因

## 5. 调度设计

### 5.1 ScheduleSpec（`src/core/schedule/ScheduleSpec.h`，纯 core）

```cpp
struct ScheduleSpec {
    enum Kind { Daily, Weekly, Interval };
    Kind kind;
    QTime time;      // daily/weekly：本地时间 HH:mm
    int weekday;     // weekly：1-7（Qt::Monday..Sunday）
    int hours;       // interval：1-168
    static std::optional<ScheduleSpec> fromJson(const QJsonObject&);
    QJsonObject toJson() const;
    QString validationError() const;   // 非法值给可读原因（UI 与导入共用）
    QDateTime nextOccurrence(const QDateTime& anchor, const QDateTime& after) const;
};
```

- `daily`：严格晚于 `after` 的下一个本地 HH:mm（含跨午夜）
- `weekly`：严格晚于 `after` 的下一个匹配星期
- `interval`：`anchor + k*hours > after` 的最小值；anchor = `last_fired_at`（空则
  `created_at`）。绝对秒数推进，无时区问题
- 时间语义一律**本地时区**；DST 空档/重叠按 `QDateTime` 规范化结果处理，测试矩阵固化
  实际行为（不引入自造的 DST 规则）

### 5.2 调度循环（Manager）

- 单个 30s `QTimer`（`Qt::CoarseTimer`），tick 在 GUI 线程对每个启用任务算
  `due = spec.nextOccurrence(last_fired_at, last_fired_at)`（即「上一锚点之后的下一次」）：
  - `now - 120s ≤ due ≤ now` → **触发**（2 分钟宽限吸收 tick 粒度与定时器粗糙度）
  - `due < now - 120s` → 记一条 `missed` run（「应用未运行/休眠期间错过」），推进锚点，不执行
  - 其余 → 未到期，跳过
- **时钟注入**：Manager 构造参数带 `std::function<QDateTime()>`，默认
  `QDateTime::currentDateTime`——单测冻结时间跑完整矩阵（含 DST）
- 系统休眠：QTimer 睡眠期间不触发，唤醒后下一次 tick 按上面的宽限/错过规则收敛，不会
  补发一串
- 时钟回拨（NTP 校时）：due 以 `last_fired_at` 为锚重算，回拨最多造成一次延后或 missed，
  可接受；审计留痕
- CRUD / 启停变更后立即手动 tick 一次（下次触发时间即时反映，不等 30s）

## 6. 执行链路

### 6.1 无人值守防挂起（三层，对应 §1 事实 1–3）

| 层 | 机制 | 改动量 |
| --- | --- | --- |
| 默认权限 | 任务权限档默认 `plan_only`（永不挂起，`AIAgent.cpp:3259` 路径） | 0 |
| 自动拒绝 | `AIAgent::setUnattended(bool)`：`processNextToolCall` 的确认分支（`AIAgent.cpp:3290-3309`）在 unattended 下改为 PlanOnly 式直接拒绝——回灌可读原因（「定时任务无人值守，确认级工具已拒绝」）+ `tool_blocked` 审计（detail 标 `scheduled_unattended`）；Dangerous 同样直接拒绝。默认 false，tab 路径零影响 | ~15 行（唯一 core 行为改动） |
| 墙钟兜底 | 执行前 `setTaskTimeoutMs(prefs schedule.maxRunMinutes * 60000)`，复用 `AIAgent.cpp:450-457` 既有封口机制，超时 run 记 `timeout` | 0（现成机制） |

放宽到 `auto_edit` / `full_access` 的任务靠第二、三层不挂死；编辑器在非 `plan_only` 时
显警示文案。

### 6.2 单次执行序列（全部 GUI 线程发起）

```
tick 判定到期 → 写 run(status=running, trigger) + 推进 last_fired_at
→ 并发闸：全局同时最多 1 个 scheduled run（含手动「立即运行」）
   · 计划触发撞闸 → 记 skipped_busy，本轮放弃
   · 手动触发撞闸 → 返回失败并 toast，不落 run
→ 共享工厂造无头 agent（独立 SqliteMemory 连接，协议服务/Episodic/自动标题全配齐）
→ 按 profile_id 解析配置（复用 configureModel 的解析口径）
   · 解析不到 → run=failed：「模型配置已删除或不可用」
→ setPermissionMode(任务档) + setUnattended(true) + setTaskTimeoutMs(全局上限)
→ agent->startTask(prompt)   // 会话惰性创建（AIAgent.cpp:1633-1654），持久化/审计/配额全走既有链路
→ 终态（finished/failed/timeout）：
   · loadMessages 取首条 assistant 回答截 ~120 字符做 run.summary
   · run 落终态 → emit runFinished(taskId, name, success, summary)
   · emit sessionsMayHaveChanged()
```

- 终态判定与 `ensureTab` 的 busy→非 busy 边沿同型（`AgentViewModel.cpp:433-461`）
- `checkQuota` 配额闸照常生效（无人值守的 token 消耗防线）；用量沿既有链路入
  `token_usage`，run 行不重复记账
- 自动标题免费获得（工厂含标题生成链）：定时会话在侧栏有正常标题，无需额外处理

### 6.3 退出停机

Manager 自连 `aboutToQuit`（仿自动备份样板 `main.cpp:1341-1351`）：停 timer → 对在跑
run `stop()` → 限时 2s 等终态 → run 记 `stopped`。注意：托盘「退出」走
`stopAllTabs()`（`main.cpp:1173-1180`），但**直接关窗（未开关闭到托盘）不经过它**，所以
必须挂 `aboutToQuit`，不能复用退出菜单路径。

### 6.4 通知与会话可见性

- `runFinished` → main.cpp：把 `main.cpp:1202-1216` 的三层门控抽成小函数
  `maybeTrayNotify(title, body)`（tab 完成通知与定时任务通知共用），通过后
  `tray->showMessage`；任务 `notify=0` 时 Manager 不发信号即静默
- 通知文案：`定时任务完成：<名称>` + summary（或失败原因）；不含长正文
- 侧栏刷新：`sessionsMayHaveChanged()` → main.cpp 接 AgentVM 会话列表重载入口
  （title 生成链已证明 DB 写后可触达刷新；实施时核对具体方法，若仅有内部信号则补一个
  `Q_INVOKABLE refreshSessions()`）

## 11. 风险

- **多连接并发写**：无头 agent 是第 N+1 条 SQLite 连接；`busy_timeout` 串行化在多 tab
  场景已验证，风险低，但回归必须含「tab 任务 + 定时任务同跑」
- **侧栏最小宽上调**：存量 180–207 的 sidebarWidth 会被抬升——加载路径 clamp 必须核实
  （§7.1），并在 P3 验收里手动确认窄侧栏布局不破
- **无人值守 token 消耗**：`checkQuota` 照常拦截；run 记录沿既有用量链路可查
- **托盘菜单不可动态增删**（重建会栈溢出，`main.cpp:1131-1145` 注释）：不在托盘菜单加
  「下次任务」动态项，避免踩坑
- **时钟注入遗漏**：Manager 所有时间取值必须走注入时钟，任何直调
  `QDateTime::currentDateTime()` 的漏网都会让冻结时钟测试失真——评审时盯这一点

## 12. 明确不做 / v1.5 候选

**不做**（docs/26 §8 维持）：cron 表达式；任务依赖编排；云端触发（应用未运行也能跑）；
团队协作/云同步。
