## 3. 关键技术决策与坑（后续开发必读）

1. **`ELECTRON_RUN_AS_NODE` 继承崩溃**（用户报告的 Markdown 打不开）：VSCode 系终端注入该变量 → ShellExecute 拉起的 Electron 处理器退化为纯 Node → 文档被当 JS 执行。修复：正常路径 `openUrl` 前从系统环境移除；应急路径 `startDetached` 传剔除后的环境副本。**从 VSCode 终端启动本应用测试外部打开功能时必须模拟此环境。**
2. **注册表三坑**：`RegGetValueW` 拒绝 HKCR；`RegQueryValueExW` 的 value 名不能带子键路径（`shell\open\command` 是子键 + 默认值）；`REG_EXPAND_SZ` 需 `ExpandEnvironmentStringsW` 展开。
3. **空 QString 绑定为 SQL NULL**：NOT NULL 列（`source_path`）必须绑显式空串。
4. **`QTextLayout` 惰性布局**：不渲染则 `lineCount()` 恒 1；`visualLineSpans` 内部自建 layout 且须设 `QTextOption::WrapAnywhere`。document 的 `textWidth` 不跟随编辑器视口，**必须由调用方传入宽度**。
5. **`TextEdit` 无 `lineHeight`**：用 `contentHeight / lineCount` 反推；尾随换行会多出空末行且真实渲染，行号须照常编号否则错位。
6. **增量构建 ODR 陷阱**：`AgentViewModel.h` 被 6 个编译单元包含，改头文件后若出现"只加成员变量就崩溃"，先清理重建再查逻辑（本轮实测发生过一次）。
7. **QML 属性变化处理器内读派生绑定拿旧值**：`onProjectRootChanged` 里读 `hasProject` 还是 false，须直接读 `projectRoot.length > 0`。
