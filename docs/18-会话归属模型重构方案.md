## 0. 问题陈述

### 0.1 现象

| # | 现象 | 状态 |
|---|------|------|
| 1 | 点开项目中的会话后再点普通对话，顶栏仍带项目标识 | 已修（`c4febf5`） |
| 2 | 在项目里点「新会话」得到的是项目会话，而非期望的普通对话 | 已修（`13c110e`） |
| 3 | 切换标签页时顶栏徽标不跟随 | **未修** |
| 4 | 在项目里点「新会话」会把全局项目清空，**其他标签页**的 agent 也失去项目上下文 | **未修** |

现象 1、2 的修补都只是在补判断条件，3、4 暴露出同一个根因。

### 0.2 根因

「活动项目」（`AgentViewModel::m_activeProjectId`）是一个**隐藏的全局可变状态**，
它同时决定 5 件事：

1. 新会话的归属（`AIAgent.cpp:346-349` 用 `m_activeProjectId` 标记 `sessions.project_id`）
2. 沙箱的可读根（`Sandbox::setProjectDir`，唯一调用点 `AgentViewModel.cpp:414`）
3. 系统提示里的项目上下文（`AIAgent::projectContextBlock()`）
4. 顶栏徽标（`TopBar.qml:42`）
5. 侧栏高亮与展开态（`Sidebar.qml:260`、`Sidebar.qml:550`）

由此产生三个结构性矛盾：

- **浏览与模式耦合**：打开一条旧会话会改它（`loadSession` 同步），新建会话也会改它
  （`newLocalChat` 清空）。模式随浏览行为乱跳。
- **全局 vs 多标签**：模式是全局的，标签是独立的。切标签不改模式 → 徽标必然可能撒谎。
- **新建目标不可见**：顶部「新会话」悬在两棵树之上，不表达会把会话放进哪。

### 0.3 结论

**这不是单点缺陷，而是模型缺了一层。** 把「会话的归属」这件本属于每条会话的
事实，提升成了全局可变状态；只要这层不拆，同类 bug 会持续冒出。

## 1. 目标与原则

| 编号 | 原则 | 可验证判据 |
|------|------|-----------|
| G1 | 归属可见、可预期 | 建会话之前就能知道它会放进哪 |
| G2 | 浏览不改上下文 | 打开一条旧会话，其他标签页的沙箱与上下文不变 |
| G3 | 归属属于会话/标签，不是应用模式 | 不存在可被 UI 任意改写的全局项目状态 |
| G4 | 入口即语义 | 想建到哪，就从哪建；目标写在入口上 |
| G5 | 不确定时给选择，确定后变只读 | 空标签可点选目标；发出首条消息后归属落定且只读 |

## 2. 新模型

### 2.1 状态归属

| 状态 | 现在 | 新模型 |
|------|------|--------|
| 会话归属 | `sessions.project_id` | **不变**（无数据库改动） |
| 标签归属 | 无（每次从全局继承） | 每个 agent 的 `m_activeProjectId/Name/Root`（**已存在**），补只读 getter |
| 全局活动项目 | `AgentViewModel::m_activeProjectId`（可变） | **取消** |
| `activeProjectId()` | 返回全局值 | **派生**：活动标签 agent 的项目 id |
| `projects/activeId` | 沙箱模式 + 启动恢复 | 降级为「侧栏上次浏览位置」，仅用于恢复侧栏展开态与选中项 |

**改造基础已经具备**：每个标签的 agent 本就各自持有 `m_activeProjectRoot`，
且 `AIAgent::dispatchToolExecution` 已用 `Sandbox::ExecutionScope(projectRoot)`
（docs/17 P1-5）把项目根钉在工具执行线程上。真正要改的是**别再往所有 agent
广播同一个值**。

### 2.2 交互规则

| 动作 | 现在 | 新模型 |
|------|------|--------|
| 项目行的「+」 | 激活项目 + 开标签 | 在该项目下新建（**唯一**的项目会话入口） |
| 「对话」头的「+」 | 清空全局 + 开标签 | 新建无项目对话 |
| 顶部「新会话」 | 继承全局项目 | 新建无项目对话；文案改为「新对话」 |
| 标签栏「+」 | 继承全局项目 | 新建无项目对话 |
| 点开一条旧会话 | 改全局项目 | 只改**这个标签**的归属 |
| 切换标签 | 不动项目 | 徽标 = 该标签会话的归属 |
| 点击顶栏徽标 | 清空全局项目 | 空标签：打开项目选择；已有会话：只读（不改变归属） |

### 2.3 徽标语义（G5 的落点）

- **空标签**（尚无会话）：徽标显示当前目标，可点击切换项目。这把「不确定性」
  收敛到唯一真正需要它的时刻 —— 发出首条消息之前。
- **已有会话**：徽标为**只读指示**，显示该会话归属。点击不再改变归属 ——
  否则它又变成了一个隐藏开关，正是本轮要消除的东西。

## 3. 改动清单

### 3.1 `src/core/agent/AIAgent.{h,cpp}`

- 新增只读 getter：`activeProjectId()` / `activeProjectName()` / `activeProjectRoot()`
  （现只有 `setActiveProject`，测试与派生属性都需要读取）。
- `setActiveProject` 语义不变。
- `projectContextBlock()`、`beginSession` 归属标记逻辑不变。

### 3.2 `src/viewmodels/ChatSessionController.{h,cpp}`

- 新增 `activeProjectId()`，转发到 `m_agent`（无 agent 时返回空串）。

### 3.3 `src/viewmodels/AgentViewModel.{h,cpp}`（改动主体）

- **删除**成员 `m_activeProjectId`；`activeProjectId()` 改为派生（读活动标签
  的 agent）。新增成员 `m_pendingProjectId`，**仅服务启动回灌**：main.cpp 在
  `setAgent` 之前调用 `setActiveProjectId`（此时活动标签还没有 agent），先
  暂存、首次挂接时应用、随后清空。
- `setActiveProjectId(id)` → 语义收窄为**只作用于活动标签**，同时保留作为
  `activeProjectId` 属性的 WRITE 端。
  **它同时就是期 2 徽标点选要用的入口** —— 原设计的
  `Q_INVOKABLE setActiveTabProject(id)` 与它完全重复，属冗余，**实施时已删除**。
- 新增私有 `addTab(projectId)`：新建标签并**显式**指定归属；`openTab()` /
  `newLocalChat()` / `newProjectChat()` 与 `loadSession()` 的忙碌分支都走它。
- 新增 `applyProjectTo(agent, projectId)` 取代 `pushActiveProject`（后者已删）；
  新增 `syncSandboxMirror()` 把全局沙箱基准同步为活动标签的镜像。
- `setAgent`：重新挂接会换掉 agent（新 agent 无归属），改为**先记下本标签归属、
  挂接后原样还原**，不再用"全局活动项目"覆盖（否则会冲掉其他标签的项目）。
- 新增私有 `ChatSessionController* addTab(const QString& projectId)`：
  建标签时**显式**把归属推给该标签的 agent；`openTab()` / `newLocalChat()` /
  `newProjectChat()` 都走它。
- `loadSession`：归属同步只作用于当前标签。
- `importProject` / `removeProject` / `renameProject`：去掉对全局的读写；
  `removeProject` 若**活动标签**属于被删项目则回落本地。
- 清理：`applyToAgents` 与 `m_templateAgent` 的双重推送 —— `m_templateAgent`
  即 tab 0 的 agent，`applyToAgents` 已覆盖，重复推送需一并理顺。
- 删除 QSettings 直写 `projects/activeId`（改由 QML 侧栏浏览位置写入）。

### 3.4 `src/core/tools/Sandbox.h`

- **实施时先确认**：全局 `s_projectDir` 是否还有非 `ExecutionScope` 的读取路径。

## 5. 迁移与兼容

- **无数据库迁移**：`sessions.project_id` 与 `projects` 表结构不变。
- `projects/activeId` 语义变更：旧值仍可读，作为侧栏浏览位置，不再驱动沙箱。
- **用户可感知的变化**：顶部按钮文案「新会话」→「新对话」；顶栏徽标由「可点击
  清空」变为「空标签可点选 / 有会话只读」。
- 不需要数据回填：历史会话的归属本就存在 `sessions.project_id`。

## 6. 风险与取舍

1. **派生属性的通知可靠性**。`activeProjectId` 变为派生后，`activeProjectIdChanged`
   必须在「切标签」与「会话归属变化」两处都发出，否则 UI 会显示陈旧值。
   建议：由 `activateTab` 与会话归属变更统一触发，并补 T1 用例兜底。
2. **`m_templateAgent` 的双重身份**（tab 0 的 agent + 新标签模板）需要理顺，
   否则「推给模板」与「推给所有标签」会重复作用到同一个对象。
3. **空标签切换目标的入口放在徽标**，可发现性依赖视觉提示；若发现率低，
   退路是在输入框上方补一个显式的「归属」选择器。
4. **行为变更需要用户重新适应**：徽标不再能「点一下回到本地」。若用户仍需要
   该快捷动作，应改由侧栏「对话」头承担（它本就是本地视图入口）。
5. **本轮不做**：项目级别的会话分页（当前 `listSessions(500)` 全量拉取）、
   跨项目的会话移动（把一条会话从项目 A 移到 B）。
