# 45. 对话文本排版优化方案（行间距 / 标题渲染 / 代码块）

> 状态：**已实施并独立验证（2026-11-07）**：行距/标题/代码块全部落地；全量 ctest 61/61、qmllint Error 0、离屏冒烟干净、独立验证 VERDICT PASS。关键载体偏差：`TextEdit` 无 `lineHeight` 属性，行距由 `DocumentLineHeight` 行为组件实现（见 §3.2）。
> 用户点名三项：输出文本加行间距、标题与正文渲染优化、代码块显示优化。
> 范围：`AssistantMessage.qml`（正文渲染）、`CodeBlock.qml`（代码块）、`ThemeProvider.h`（2 个行高 token）、配套 QML 测试。**不改**解析架构（segments 围栏扫描保留）、不改交互（选中/复制/流式光标/滚轮语义均不动）。

## 1. 现状与根因（file:line 证据）

| # | 痛点 | 根因 | 证据 |
|---|------|------|------|
| P1 | 正文行间距过密 | 所有散文 TextEdit 无 `lineHeight` 设置，Qt 默认 1.0；CJK 在 1.0 行高下视觉密度极高 | `AssistantMessage.qml:173`（mdText）、`:247/:288`（segment 散文两处）；全仓 grep `lineHeight` = 0 处 |
| P2 | 标题观感弱 | 标题混在 `TextEdit.MarkdownText` 内置渲染：字号按基础字体内置缩放（不使用 `Theme.fontSizeH1/H2`），颜色继承正文 `textPrimary` 无层级，标题上下间距不可控 | `AssistantMessage.qml:179`（textFormat: MarkdownText）；`ThemeProvider.h:306-310` 的 H1/H2 token 无人消费 |
| P3 | 代码块局促 | 行距 1.0、字号 `fontSizeCaption`、内边距仅 8/12/8，视觉密度高于正文 | `CodeBlock.qml:84-99`（margins: 8、leftMargin: 12、无 lineHeight） |
| P4 | 段间呼吸感不足 | 正文段与代码块间距 `spaceSm`(8px) | `AssistantMessage.qml:218`（segmentCol spacing） |

## 2. 设计决策（已拍板，含理由）

| # | 决策 | 理由 |
|---|------|------|
| D1 | 行距取值：正文 **1.4**、代码 **1.5**（ProportionalHeight） | 中文正文公认舒适区 1.4（1.3 偏紧、1.5 偏松）；等宽代码符号稀疏，GitHub 网页代码行高约 1.5 |
| D2 | 行高走 Theme token（`lineHeightBody` / `lineHeightCode`，qreal） | 4 处消费点收口一处定义，将来统一调行距不动业务文件；主题无关但有 `themeChanged` 通知 |
| D3 | 标题采用**片段级拆分渲染**（非替换 Markdown 引擎） | 非流式路径已有 segments 扫描器，加一类 `heading` 成本最低且完全受 Theme 控制；换富文本管线是超标的大工程 |
| D4 | 拆分规则：ATX 标题（1-6 个 `#` + 空格）且**不在围栏内**、整行匹配 | 与 CommonMark 一致；setext 式（下划线）标题罕见，保留内置渲染不拆 |
| D5 | 标题行内 markdown（`**bold**` 等）按纯文本渲染 | 标题内嵌强调是低频场景；纯文本避免引入第二个行内解析器 |
| D6 | 代码块保持 `WrapAnywhere` 软换行 | 用户未点名长行问题；改横向滚动是交互变更，超出本次范围（如需另立方案） |
| D7 | 流式路径（单 TextEdit）同样加 lineHeight | 流式期间正是用户盯着看的阶段，是主要观感路径 |

## 3. 实施规格

### 3.1 ThemeProvider.h（+2 token）

```cpp
Q_PROPERTY(qreal lineHeightBody READ lineHeightBody NOTIFY themeChanged FINAL)
qreal lineHeightBody() const { return 1.4; }
Q_PROPERTY(qreal lineHeightCode READ lineHeightCode NOTIFY themeChanged FINAL)
qreal lineHeightCode() const { return 1.5; }
```

### 3.2 AssistantMessage.qml

1. **行距**：`mdText`、segment 散文两处 TextEdit 挂 `DocumentLineHeight` 行为组件（`document` + `lineHeight: Theme.lineHeightBody`）。
   > 实施偏差说明：Qt 6.9 的 `TextEdit` 没有 `lineHeight` 属性（仅 `Text` 元素有），故行距经 `DocumentLineHeight`（`ThemeProvider.h` 内 QML 组件，内部 `QTextBlockFormat::setLineHeight(percent, ProportionalHeight)`）落到 QTextDocument，效果等价。
2. **segments 扫描器扩展**（`:90` 的逐行扫描）：非围栏行若匹配 `^(#{1,6})\s+.*$`（行首空白已剥离）→ 先 `pushText()`，再 `out.push({kind:"heading", level, text})`；围栏内 `#` 开头行仍是代码内容。
3. **delegate 新增 heading 分支**：
   - level 1 → `fontSizeH1` + `Font.DemiBold`；level 2 → `fontSizeH2` + DemiBold；level 3 → `fontSizeBody + 1` + DemiBold；level 4-6 → `fontSizeBody` + DemiBold
   - 颜色一律 `textPrimary`；`fontSans`
   - 间距：上方 `spaceMd`(12)、下方 `spaceXs`(4)；**首个 segment 无上方间距**（避免与消息起点叠加）
   - 纯文本渲染（strip 掉 `#` 前缀与首空格）
4. **段间距**：`segmentCol.spacing` `spaceSm`(8) → `spaceMd`(12)。
5. **行内代码底色（2026-11-07 追加）**：`MarkdownText` 只把 `` `code` `` 变等宽、不给底色（实测 code span 的 `fontFixedPitch=true`、`styleHint=Monospace`、背景为空）。新增 `DocumentInlineCode` 后处理组件（`ThemeProvider.h`，与 `DocumentLineHeight` 同构）：监听 `contentsChange`，遍历 `QTextDocument` 的 fragment，把等宽片段补 `background`/`foreground`；挂在流式 `mdText`、segment `textSeg`、徽标流 `prosePiece` 三处。

   | 令牌 | 暗色 | 亮色 |
   |---|---|---|
   | `inlineCodeBackground` | `#1C1C28`（比 `bgPrimary` 亮一档） | `#E9EDF2`（比 `bgPrimary` 深一档） |
   | `inlineCodeForeground` | `#8FE3FF`（品牌青） | `#0052D9`（品牌蓝） |

   **限制**：`QTextCharFormat` 不支持圆角，行内代码是紧贴文字的矩形底；GitHub 式圆角胶囊需自绘富文本管线（会丢选中/复制），不做。后台任务详情用 `Text` 渲染报告（无 `textDocument`），暂不覆盖。

### 3.3 CodeBlock.qml

1. `codeText` 挂 `DocumentLineHeight`（`lineHeight: Theme.lineHeightCode`，与散文同组件同机制）。
2. 内边距：`margins: 8` → 10；`leftMargin: 12` → 14（右侧随 margins 10，收窄左右不对称差）。
3. `bodyHeight` 计算同步：`contentHeight + 16` → `contentHeight + 20`。
4. **背景投影（2026-11-07 追加）**：卡片外层加三层同心矩形投影，向外逐层扩大、透明度按 1 / 0.55 / 0.30 递减；卡片自身 `clip: true` 裁出圆角，根 `Item` 不裁剪，投影才不会被裁掉。取值全走 Theme 令牌，深浅两套自动对应：

   | 令牌 | 暗色 | 亮色 | 说明 |
   |---|---|---|---|
   | `codeBlockShadowColor` | `#000000` | `#1F2A37` | 暗色纯黑下沉；亮色冷灰蓝，避免白底发脏 |
   | `codeBlockShadowOpacity` | 0.30 | 0.12 | 最内层不透明度，外两层按 0.55 递减 |
   | `codeBlockShadowBlur` | 10 | 7 | 向外扩的总像素（三层各占 1/3） |
   | `codeBlockShadowOffsetY` | 4 | 2 | 顶部少扩的位移，形成向下重量感 |

   **实现取舍（重要）**：不使用 `QtQuick.Effects`——`RectangularShadow` 需 Qt 6.7+，而项目 `CMakeLists.txt:20` 为 `REQUIRES 6.5`；`MultiEffect` 挂在会变高的节点上每帧重缓存，docs/19 V7-c 已否决。三层矩形是零特效分层，无 FBO、无重缓存，兼容 6.5，也符合 docs/19 的「零特效退路」决策。
   **布局**：投影底部外扩计入 `implicitHeight`（`shadowFootprint = codeBlockShadowBlur + codeBlockShadowOffsetY`），避免投影压到下一段正文。

### 3.4 测试（QML 套件，复用既有 harness 惯例）

1. segments 拆分：含 `# 标题` / `## 副标` / 围栏内 `#` 行 / 无空格 `#tag` 的输入 → kind/level/text 断言（`#tag` 不是标题，保留 text）。
2. lineHeight：mdText 与 codeText 的 `lineHeight` 等于 token 值。
3. heading delegate：fontSize/字重/上下间距（首个 segment 上间距为 0）。
4. CodeBlock padding 与 bodyHeight 同步。
5. 回归：`test_chat_workflows` 全量 + 新用例先红后绿。

## 5. 风险

| # | 风险 | 缓解 |
|---|------|------|
| R1 | heading 拆分改变既有会话的渲染高度，`test_chat_workflows` 既有断言可能依赖旧高度 | 先跑定向再全量；断言若脆断言几何，按新几何更新并留注释 |
| R2 | segments 数量增多影响 citeMode 切片（citation 解析按段进行） | heading 段不做 citation 切片（标题内引用记号罕见）；citeMode 仅在 text 段启用（现状即如此） |
| R3 | 行距增大导致长回复总高度上升 | 可接受（正是用户诉求方向）；滚轮/滚动条行为不变 |
| R4 | `lineHeight` 在 `NativeRendering` 下度量差异 | CodeBlock 用 NativeRendering，需实测断言 `contentHeight` 同步正确（bodyHeight 公式随行距自动含入 contentHeight） |

## 6. 不做清单

- 不替换 Markdown 渲染引擎（富文本/HTML 管线）；不做 setext 标题拆分；不做标题内行内 markdown；不改代码块软换行为横向滚动；不动选中/复制/光标交互；不做正文段内段距（MarkdownText 内置，改不动）。
