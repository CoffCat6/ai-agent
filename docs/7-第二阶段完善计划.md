## 2. 第二阶段问题清单（G = Gap，P0 → P3）

> 每条含：问题 / 证据 / 影响 / 建议。编号 G1 起，与第一阶段 P0-1 等编号区分。

### G1【P0】已启动工具无法真正取消（第一阶段遗留 P1-2）

- **问题**：`stop()` 能封口消息序列、取消 LLM 流，但对已在线程池上执行的工具无能为力——副作用继续发生。
- **证据**：`ITool.h:45-50` 接口仅有 `definition()`/`execute()`，无 cancel/deadline；`AIAgent.cpp:904-916` 的 `QFutureWatcher::finished` 仅按 epoch 标记 trace 节点为 cancelled，`QtConcurrent::run` 的 future（`AIAgent.cpp:920-923`）必然跑完；唯一有内部超时的是 `shell_exec`（`ToolRegistry.cpp:198-215`，1-60 秒）。
- **影响**：用户停止后 `write_file` 仍写文件、`shell_exec` 仍执行外部命令；长任务工具（如未来的网络工具）无界占用线程池。
- **建议**：Batch 13——`ITool` 增加协作式取消接口；Agent 持有 in-flight 工具句柄并在 `stop()` 传播；shell 类工具用 `QProcess::kill`。

### G2【P0】仅本地模式未落地，知识库内容无条件上送云端

- **问题**：FIX-505 只完成了 UI 声明（"文档内容会发送给当前模型服务"），没有提供强制手段。
- **证据**：`search_knowledge_base` 在 `main.cpp:115` 无条件注册且为 `ToolLevel::Safe`（自动执行）；全代码库无 `localOnly`/`local_only` 实现（仅 `5-完善计划.md:486` 的规划文本）。
- **影响**：即使开启"隐私声明"，模型仍可自动检索本地文档并随 messages 外送；用户预期与实际不符。
- **建议**：Batch 14——设置项 + 工具注册门控 + 运行时即时生效。

### G3【P1】生成参数不可配置，Provider 间行为不一致

- **问题**：Profile 无 temperature/max_tokens 字段；Anthropic 输出硬编码 4096；OpenAI/Ollama 请求体不含任何采样参数。
- **证据**：`SettingsService.h:105`（Profile 为 QVariantMap，仅 `{id, displayName, provider, baseUrl, apiKey, model, models}`，无任何采样参数字段）；`AnthropicService.h:72`（`int m_maxTokens{4096}` 硬编码常量；【v1.1】补真实锚点，`.cpp:192` 为消费点 `body["max_tokens"] = m_maxTokens`）；OpenAI/Ollama 服务文件中 grep `temperature|max_tokens|num_ctx` 零命中。仅有一个全局 `contextTokens`（`SettingsService.h:30`）。
- **影响**：无法控制输出长度与随机性；Anthropic 长回答被 4096 截断；Ollama 本地模型不受 `num_ctx` 控制。
- **建议**：Batch 15——Profile 扩展 + 三 Provider 请求体接线 + 设置页编辑。

### G4【P1】zh_CN 翻译近乎为空

- **问题**：i18n 基础设施完整（`qt_add_translations`、启动加载 .qm、回退原文），但翻译内容缺失；【v1.1 新发现】既有 2 条翻译方向反向——source 为中文字面量、translation 为英文，zh_CN locale 下这两条通知反而渲染英文。
- **证据**：`translations/nexus_ai_zh_CN.ts` 共 15 行、仅 2 条 `<message>`（AgentViewModel 通知文案，如 `<source>已导入 %1（%2 段）</source>` → `<translation>Imported %1 (%2 chunks)</translation>`）；QML 中数十个 `qsTr()` 字符串未入 .ts。
- **影响**：中文用户看到中英混合界面；既有 2 条通知在中文环境下显示英文（方向反向）；第一阶段 Batch 8 的 FEAT-804 只建了管线未填内容。
- **建议**：Batch 16——lupdate 全量提取 + 全部条目翻译（含修正既有 2 条反向条目）+ 覆盖率检查。

### G5【P2】workspace_id 预留未启用（第一阶段 P0-3 延续）

- **证据**：三表 `workspace_id` 列仅写入常量 `'local'`（`SqliteMemory.cpp:449,620,746`），全库无 `WHERE workspace_id` 查询；`user_id` 列不存在。
- **影响**：桌面单用户形态可接受；若未来引入多窗口/账号/远程 API，需要二次迁移。
- **建议**：暂不实现，维持"预留"决策；仅当多用户立项时启用（列入 Phase 16 评估项）。

### G6【P2】Episodic Memory 建而未用（第一阶段 MEM-703 有意搁置）

- **证据**：`saveEpisodic`/`searchEpisodic` 生产路径零调用方（定义于 `SqliteMemory.cpp:488,503`，src/ 内无任何调用点；【v1.1 修正】仅 `tests/test_memory.cpp:145-151` 作为单元测试触达，不影响"未接入 Agent"的结论）；`SqliteMemory.h:19` 自述 "currently NOT wired into the agent"；`episodic_fts` 虚表与同步触发器已建（`SqliteMemory.cpp:111-127`），会话清理删除 `episodic` 行（`SqliteMemory.cpp:533-536,598-601`）后 FTS 影子行经触发器同步清空——因 `episodic` 从未被写入，FTS 实际为空表。
- **影响**：长期记忆能力空缺；表结构与 FTS 触发器维护成本白白付出。
- **建议**：Phase 16 产品决策——接入（会话摘要注入 system 提示）或删除表结构止损。Batch 17 的消息搜索可部分复用其 FTS5 经验。

### G7【P2】打包部署与 CI 双缺

- **证据**：`CMakeLists.txt:157-162` 的"Windows deploy"仅有 `WIN32_EXECUTABLE TRUE`；仓库内无 windeployqt 调用、无 install 规则、无安装包脚本、无 `.github/workflows`；qmllint 门禁仅存在于本地 ctest。
- **影响**：无法交付给开发者机器之外的用户；回归依赖开发者本地手动 `ctest`。
- **建议**：Batch 21——windeployqt 部署脚本 + 可选安装包 + GitHub Actions CI。

### G8【P3】外部风险：上游网关瞬态工具粘滞

- **证据**：`5-完善计划.md` 第 4 节——127.0.0.1:8317 网关（gemini 兼容代理）存在瞬态粘滞，客户端不可修复，仅靠死循环终止器限损。
- **建议**：用户侧更换端点或升级网关；客户端维持 Batch 1 修复 + 通道判定纪律，不新增工作。

#### Batch 13 — 工具协作式取消

- **Task ID**：SEC-1301（ITool 取消接口）、SEC-1302（Agent 取消传播）、SEC-1303（shell 进程终止）、SEC-1304（回归测试）
- **Current Problem**：G1。
- **Implementation**：
  1. `ITool` 增加虚方法 `virtual void cancel() {}`（默认空实现，协作式语义：仅置原子标志/终止子进程，绝不阻塞、绝不跨线程触碰 execute 内部可变状态）；接口注释说明"cancel 从 GUI 线程调用，execute 在线程池执行"。
  2. `AIAgent`：`dispatchToolExecution` 记录 in-flight 工具（call_id → {tool 指针, QFutureWatcher}）到 request 级容器；`stop()` 遍历调用 `cancel()`，future 完成后按现有 epoch 路径丢弃结果；任务结束/封口时清空容器。
  3. `shell_exec`：将 `QProcess` 指针存为成员（或经执行上下文传入），`cancel()` 实现 `kill()` + `waitForFinished(2000)`；既有 `timeout_ms` 逻辑保留。
  4. `read_file`/`list_dir`/`write_file`/`search_knowledge_base` 执行均在秒级，使用默认空实现即可，文档说明不逐个改造。
- **Files**：`src/core/tools/ITool.h`、`ToolRegistry.{h,cpp}`、`src/core/agent/AIAgent.{h,cpp}`、`tests/`。
- **Dependencies**：无。
- **Risk**：中高（线程安全）。cancel 路径必须只触碰原子量与进程句柄；QProcess 亲和线程问题需以 `moveToThread` 或信号跨线程验证。
- **Testing**：新增阻塞工具（sleep 类 AnomalyTool 扩展）：执行中 stop → cancel 被调用、trace 节点 cancelled、无悬空 tool_calls（复用 Batch 2 封口断言）；shell_exec 真实子进程被终止；`test_agent`/`test_sandbox` 既有断言回归。
- **验收（Batch 出口）**：执行中 stop 后 ≤2 秒工具副作用终止（进程退出）；`ctest` 全绿零警告。

## 7. 执行纪律（沿用第一阶段 10.2 节，第二阶段补充三则）

2. 不为过测而改测试；不删功能绕问题；不做无理由重构；最小修改、不碰无关代码。

4. 临时 workaround 必须标注"由 Batch X 收敛"，禁止无主 workaround。
5. 不伪造结果：未验证不得声称完成；验证命令与输出随 Batch 报告提交。
6. **【新增】跨线程工具改造（Batch 13）必须先写线程时序说明再动代码**；cancel 路径禁止阻塞调用与跨线程对象直触。
