## 2. 需要新增的

### 2.1 数据层：目录展开式读取（唯一真正的缺口）

`scan()` 返回的是**扁平全量列表**，对 `@` 补全正合适，但对文件树有两个问题：

| 问题 | 说明 |
|---|---|
| 一次性 2 万条 | `buildRows()` 会把全部文件塞进一棵树，`ListView` 只虚拟化渲染，但 JS 侧建树是 O(n)，2 万文件会有明显卡顿 |
| 无法表达空目录 | 扁平列表里空目录不存在，而文件管理器需要显示它们 |

**建议新增** `ProjectFileIndex::listDir(root, relPath)`：

```cpp
struct DirEntry {
    QString name;        // 显示名
    QString relPath;     // 相对项目根，'/' 分隔
    bool isDir;
    qint64 size;         // 文件字节数，目录为 0
    qint64 modifiedMs;   // 目录取自身 mtime
};

// 只读一层。过滤规则与 scan() 共用 ignoredDirNames / isSensitiveFile。
// relPath 为空 = 项目根；越界（含 ..、绝对路径）返回空并置 error。
QVector<DirEntry> listDir(const QString& root, const QString& relPath,
                          QString* error);
```

理由：一次只读一层，UI 展开时才请求下一层，天然避免大目录卡顿，也让空目录可见。过滤函数复用同一套，不会出现"树里看得到但 `@` 搜不到"或反之的不一致。

**代价**：`isIndexableFile()` 是后缀白名单，目录视图若严格套用会隐藏 `README`（无后缀）、`LICENSE`、`.gitignore` 等。需要在 `listDir` 里放宽为"排除敏感文件 + 排除 ignore 目录"，与 `scan()` 的"只收可索引"区分开。这个差异必须写进注释，否则以后会有人来"统一"它。

### 2.2 ViewModel：`ProjectFileViewModel`（新单例）

不建议塞进 `AgentViewModel`（该文件已 2100+ 行，且职责是会话/agent 编排）。新单例 `ProjectFileVM`：

| 成员 | 类型 | 说明 |
|---|---|---|
| `root` | Q_PROPERTY QString | 当前项目根，由 QML 从 `AgentVM.activeProjectRoot` 传入 |
| `children(root, relPath)` | Q_INVOKABLE QVariantList | 读一层，结果带缓存 |
| `preview(root, relPath)` | Q_INVOKABLE QVariantMap | `{text, truncated, bytes, error}`，读取上限 512KB |
| `openInDefaultApp(root, relPath)` | Q_INVOKABLE bool | 复用 `absolutePath` 的校验思路 |
| `revealInExplorer(root, relPath)` | Q_INVOKABLE bool | Windows 上选中该文件（可选） |
| `loading` / `error` | Q_PROPERTY | 状态 |

**缓存策略**：按 `(root, relPath)` 缓存目录项，切根时整体失效；文件内容不缓存（避免看到过期内容）。

**线程**：目录读取是同步磁盘 IO，单层通常 < 5ms，可留在 GUI 线程。若实测某目录慢（网络盘、超大目录），再改 `QtConcurrent`。这条建议写进注释，避免过早优化。

### 2.3 UI：`ProjectFilesPanel.qml`

嵌入 `ContextPanel` 作为第三个分区（`activeSection == 2`）。

│ [🔍 过滤路径…]         [⟳] [⊞] │   过滤输入 + 刷新 + 折叠全部
├───────────────────────────────┤

交互决定：

| 行为 | 选择 | 理由 |
|---|---|---|

### 2.4 与 Git 分区的分工

必须明确，否则两个树会互相抢位置：

| 分区 | 语义 | 数据源 |
|---|---|---|
| **文件** | 项目**全部**文件，只读浏览 | `ProjectFileIndex::listDir` |
| **Git** | **有改动**的文件 + 历史 | `git status` / `git log` |

文件分区不做任何写操作，也不显示 git 状态标记 —— 那是 Git 分区的职责。**"文件"是只读视图**，这条要写进组件头注释。

## 3. 边界与风险

### 3.1 必须处理的

| 项 | 处理 |
|---|---|
| 本地会话（无项目根） | 与 Git 分区一致：标签隐藏 + `activeSection` 回落，不得显示"加载中"空等 |
| 敏感文件 | 数据层已排除（`isSensitiveFile`），UI 不得用其他扫描路径绕过 |
| 超大文件 | 预览超过 512KB 只显示前 512KB + 明确提示，**不静默截断** |
| 二进制文件 | 后缀白名单外的文件不在树里；若放宽（见 2.1），预览要检测 NUL 字节并显示"二进制文件，无法预览" |
| 符号链接 | 不跟随（`scan()` 既有行为），避免环形遍历 |
| 路径越界 | 所有 `relPath` 入参过 `QDir::cleanPath` + 前缀比对 |

### 3.2 明确不做的

- **文件编辑**：只读预览。写操作走审阅（agent 写入）或外部编辑器。
- **新建/删除/重命名**：破坏性操作，不在本轮范围。
- **文件监听**（inotify/`QFileSystemWatcher`）：整个项目树监听成本高、事件噪音大。改为手动刷新 + 打开分区时懒刷新。
- **与 `@` 引用联动**：文件树与补全是两条独立路径，共享 `ProjectFileIndex` 的过滤规则即可，不强行合并。

### 3.3 已知的取舍

**`listDir` 与 `scan()` 的过滤规则不同**（见 2.1）。这是有意的：补全只要"可索引的代码文件"，文件管理要"看得见所有文件"。风险是后人误以为不一致而统一它们，**必须在两处函数注释里互相指明**。

## 5. 验收标准

- 项目会话打开文件分区，能看到目录树，展开有内容，本地会话标签不可见且不发起扫描
- 点击文件能预览前 512KB，超过时明确提示
- 双击文件能用系统默认程序打开
- 二进制文件/超大文件/读取失败各有明确提示，不显示空白
- `.env`、`id_rsa` 不出现在树里
- 目录读取失败（权限/已删除）显示错误而不是空列表
- 全量 `ctest` 通过，双语 0 unfinished

## 6. 待你确认的三个决定

1. **预览放面板内还是弹窗？** 我建议面板内可折叠（侧栏宽度有限，弹窗遮挡对话）。若你更希望大窗口预览，需要另做一个 `FilePreviewDialog`。
2. **是否显示文件大小？** 我建议显示（220px 下只放得下一列辅助信息）。
3. **是否需要"在资源管理器中显示"？** 纯 Windows 便利项，跨平台要分别处理（macOS `open -R`、Linux 无统一方案），成本高于收益。
