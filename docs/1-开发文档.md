### 对话历史数据结构

AI 服务的核心区别是**对话历史**。每条消息是一个 JSON 对象：

```json
[
  {"role": "user",      "content": "你好",           "timestamp": "14:30"},
  {"role": "assistant", "content": "你好！有什么可以帮你的？", "timestamp": "14:30"},
  {"role": "user",      "content": "解释一下 MVVM",  "timestamp": "14:31"}
]
```

这个数组在 ViewModel 中维护（`m_conversationHistory`），每次发请求时完整传给 Service。
Service 负责把它转换为 API 需要的格式。

## 3. 逐层代码走读

### 3.1 接口层 — IAIService.h

**文件：** `src/services/ai/IAIService.h`

```cpp
class IAIService {
public:
    using Ptr = std::shared_ptr<IAIService>;
    using MessageCallback = std::function<void(Result<QString>)>;

    virtual ~IAIService() = default;

    // 核心方法：异步发送消息
    // 参数 conversationHistory 是完整对话历史（包含刚添加的用户消息）
    // Service 需要自行从历史中构建 API 请求
    virtual void sendMessageAsync(const QString& message,
                                  const QJsonArray& conversationHistory,
                                  MessageCallback callback) = 0;

    // 同步发送（测试用）
    [[nodiscard]] virtual Result<QString>
    sendMessageSync(const QString& message) = 0;

    // 取消当前请求（用户点击"停止"时调用）
    virtual void cancelRequest() = 0;

    // 是否正在加载
    [[nodiscard]] virtual bool isLoading() const = 0;
};
```

**与翻译接口的关键差异：**
- 多了 `conversationHistory` 参数 — Service 需要理解对话上下文
- 多了 `cancelRequest()` — AI 响应可能很长，用户需要能中途取消
- 返回值是简单的 `QString` 而非结构体 — AI 的回复就是纯文本

### 3.3 ViewModel 层 — AIAssistantViewModel

**文件：** `src/viewmodels/AIAssistantViewModel.h/.cpp`

ViewModel 做了三件关键的事：

**① 维护对话历史（这是与翻译 ViewModel 最大的区别）：**

```cpp
// AIAssistantViewModel.cpp:48-97
void AIAssistantViewModel::sendMessage(const QString& message) {
    if (message.trimmed().isEmpty()) return;

    // 1. 先把用户消息加入历史
    QJsonObject userMessage;
    userMessage["role"]      = "user";
    userMessage["content"]   = message;
    userMessage["timestamp"] = QDateTime::currentDateTime().toString("hh:mm");

    m_conversationHistory.append(userMessage);
    emit conversationHistoryChanged();   // QML 立即显示用户消息

    // 2. 调用服务，传入完整历史
    auto svc = ensureService();
    svc->sendMessageAsync(message, m_conversationHistory,
        [this](Result<QString> result) {
            if (result.isErr()) {
                setLastError(QString::fromStdString(result.error().message));
                emit errorOccurred();
                return;
            }

            // 3. 把 AI 回复也加入历史
            const QString response = std::move(result).value();
            QJsonObject aiMessage;
            aiMessage["role"]      = "assistant";
            aiMessage["content"]   = response;
            aiMessage["timestamp"] = QDateTime::currentDateTime().toString("hh:mm");

            m_conversationHistory.append(aiMessage);
            emit conversationHistoryChanged();   // QML 显示 AI 回复
            emit messageReceived(response);
        });
}
```

**② 管理上传文件列表：**

```cpp
// AIAssistantViewModel.cpp:100-135
void AIAssistantViewModel::uploadFile(const QString& filePath) {
    QFileInfo fileInfo(filePath);
    if (!fileInfo.exists()) {
        setLastError("File not found: " + filePath);
        emit errorOccurred();
        return;
    }

    QJsonObject fileObj;
    fileObj["fileName"]   = fileInfo.fileName();
    fileObj["filePath"]   = filePath;
    fileObj["fileSize"]   = formatFileSize(fileInfo.size());
    fileObj["uploadTime"] = QDateTime::currentDateTime().toString("hh:mm");

    m_uploadedFiles.append(fileObj);
    emit uploadedFilesChanged();
    emit fileUploaded(fileInfo.fileName());
}
```

**③ 支持取消请求：**

```cpp
// AIAssistantViewModel.cpp:154-159
void AIAssistantViewModel::cancelRequest() {
    auto svc = ensureService();
    svc->cancelRequest();
    setLoading(false);
}
```

## 4. 当前架构问题与修复方案

### 4.1 问题描述

当前 `AIAssistantPage.qml` 存在两处违反 MVVM 架构的问题：

**问题 1：QML 自己管理对话列表，没有使用 ViewModel**

```qml
// ❌ 当前实现：QML 本地 ListModel
ListModel { id: conversationModel }

// 发送时直接 append 到本地 model
conversationModel.append({
    role: "user",
    content: messageInput.text,
    timestamp: new Date().toLocaleTimeString()
})

// AI 响应也由本地 Timer 生成
Timer {
    id: aiResponseTimer
    interval: 1000
    onTriggered: {
        conversationModel.append({
            role: "assistant",
            content: randomResponse,
            ...
        })
    }
}
```

这意味着 ViewModel 的 `sendMessage()`、`conversationHistory`、`isLoading` 全部没有被使用。

**问题 2：文件上传没有调用 ViewModel**

```qml
// ❌ 当前实现：直接操作本地 model
FileDialog {
    onAccepted: {
        uploadedFilesModel.append({...})
    }
}
```

`viewModel.uploadFile()` 和 `viewModel.uploadedFiles` 完全没有被使用。

### 4.2 修复方案

将 QML 改为纯 UI 层，所有数据和逻辑交给 ViewModel：

**Step 1：对话列表改为绑定 ViewModel**

```qml
// ✅ 修复后：绑定 ViewModel 的 conversationHistory
Repeater {
    model: root.viewModel.conversationHistory

    delegate: ColumnLayout {
        required property int index
        required property var modelData
        // ... 渲染逻辑不变
    }
}
```

**Step 2：发送按钮改为调用 ViewModel**

```qml
// ✅ 修复后
AppButton {
    text: root.viewModel.isLoading ? qsTr("停止") : qsTr("发送")
    onClicked: {
        if (root.viewModel.isLoading) {
            root.viewModel.cancelRequest()
        } else {
            root.viewModel.sendMessage(messageInput.text)
            messageInput.text = ""
        }
    }
}
```

**Step 3：文件上传改为调用 ViewModel**

```qml
// ✅ 修复后
FileDialog {
    onAccepted: {
        var filePath = selectedFile.toString().replace("file:///", "")
        root.viewModel.uploadFile(filePath)
    }

// 文件列表绑定 ViewModel
Repeater {
    model: root.viewModel.uploadedFiles
    // ...
}
```

**Step 4：监听 ViewModel 信号**

```qml

    target: root.viewModel

    function onMessageReceived(response) {
```

```cpp
// src/services/ai/OpenAIService.h
#pragma once

#include <QObject>
#include <QNetworkAccessManager>
#include <QNetworkReply>
#include <QJsonArray>
#include <QJsonObject>
#include <memory>

/// OpenAI 兼容 API 服务实现
///
/// 支持：
/// - OpenAI 官方 API (api.openai.com)
/// - 任何 OpenAI 兼容 API（通过 baseUrl 配置）
/// - 多轮对话（携带完整 conversationHistory）
/// - 可取消的请求
///
/// 配置项：
///   apiKey    — API Key（必填）
///   baseUrl   — API 地址（默认 https://api.openai.com/v1）
///   model     — 模型名称（默认 gpt-4o）
///   systemPrompt — 系统提示词（可选）
///   maxTokens — 最大回复 token 数（默认 2048）
///   temperature — 温度参数（默认 0.7）
class OpenAIService final : public QObject, public IAIService {
    Q_OBJECT

public:
    struct Config {
        QString apiKey;
        QString baseUrl{QStringLiteral("https://api.openai.com/v1")};
        QString model{QStringLiteral("gpt-4o")};
        QString systemPrompt;
        int     maxTokens{2048};
        double  temperature{0.7};
    };

    explicit OpenAIService(Config config, QObject* parent = nullptr);
    ~OpenAIService() override = default;

    // ── IAIService ──────────────────────────────────────────────────────────
    void sendMessageAsync(const QString& message,
                          const QJsonArray& conversationHistory,
                          MessageCallback callback) override;

    [[nodiscard]] Result<QString>
    sendMessageSync(const QString& message) override;

    void cancelRequest() override;
    [[nodiscard]] bool isLoading() const override;

    // ── 运行时配置 ──────────────────────────────────────────────────────────
    void setSystemPrompt(const QString& prompt);
    void setModel(const QString& model);

private:
    /// 构建 OpenAI API 请求体
    [[nodiscard]] QJsonObject buildRequestBody(
        const QJsonArray& conversationHistory) const;

    /// 将内部消息格式转换为 OpenAI messages 数组
    [[nodiscard]] QJsonArray convertMessages(
        const QJsonArray& conversationHistory) const;

    /// 解析 OpenAI API 响应
    [[nodiscard]] Result<QString> parseResponse(
        const QByteArray& responseData) const;

    Config                  m_config;
    QNetworkAccessManager   m_network;
    QNetworkReply*          m_activeReply{nullptr};  // 当前活跃的请求（用于取消）
    bool                    m_loading{false};
};
```

### 5.3 Step 2：实现 OpenAIService

**新建文件：** `src/services/ai/OpenAIService.cpp`

```cpp
// src/services/ai/OpenAIService.cpp
#include "services/ai/OpenAIService.h"

#include <QJsonDocument>
#include <QJsonArray>
#include <QJsonObject>
#include <QElapsedTimer>

#include "core/log/Logger.h"
#include "core/log/LogModules.h"

OpenAIService::OpenAIService(Config config, QObject* parent)
    : QObject(parent)
    , m_config(std::move(config)) {
    TB_LOG_INFO(LogModule::AI,
        "OpenAIService created | model={} baseUrl={} systemPrompt={}",
        m_config.model.toStdString(),
        m_config.baseUrl.toStdString(),
        m_config.systemPrompt.isEmpty() ? "(none)" : "(set)");
}

void OpenAIService::setSystemPrompt(const QString& prompt) {
    m_config.systemPrompt = prompt;
    TB_LOG_DEBUG(LogModule::AI, "System prompt updated | len={}", prompt.length());
}

void OpenAIService::setModel(const QString& model) {
    m_config.model = model;
    TB_LOG_DEBUG(LogModule::AI, "Model changed to '{}'", model.toStdString());
}

QJsonArray OpenAIService::convertMessages(
    const QJsonArray& conversationHistory) const {

    QJsonArray messages;

    // 1. 添加 system prompt（如果有）
    if (!m_config.systemPrompt.isEmpty()) {
        QJsonObject sysMsg;
        sysMsg[QStringLiteral("role")]    = QStringLiteral("system");
        sysMsg[QStringLiteral("content")] = m_config.systemPrompt;
        messages.append(sysMsg);
    }

    // 2. 遍历对话历史，提取 role 和 content
    for (const auto& item : conversationHistory) {
        const auto obj = item.toObject();
        const QString role = obj[QStringLiteral("role")].toString();

        // 只取 user 和 assistant 角色，跳过 timestamp 等附加字段
        if (role == QStringLiteral("user") ||
            role == QStringLiteral("assistant")) {
            QJsonObject msg;
            msg[QStringLiteral("role")]    = role;
            msg[QStringLiteral("content")] = obj[QStringLiteral("content")];
            messages.append(msg);
        }
    }

    return messages;
}

QJsonObject OpenAIService::buildRequestBody(
    const QJsonArray& conversationHistory) const {

    QJsonObject body;
    body[QStringLiteral("model")]       = m_config.model;
    body[QStringLiteral("messages")]    = convertMessages(conversationHistory);
    body[QStringLiteral("max_tokens")]  = m_config.maxTokens;
    body[QStringLiteral("temperature")] = m_config.temperature;
    body[QStringLiteral("stream")]      = false;  // 非流式，第 6 节讲解流式

    return body;
}

Result<QString> OpenAIService::parseResponse(
    const QByteArray& responseData) const {

    QJsonParseError parseErr;
    const auto doc = QJsonDocument::fromJson(responseData, &parseErr);
    if (parseErr.error != QJsonParseError::NoError) {
        return Result<QString>::err(
            TB_MAKE_ERROR(ErrorCode::NetworkError,
                          "Invalid JSON response from OpenAI API"));
    }

    const auto root = doc.object();

    // 检查 API 错误
    if (root.contains(QStringLiteral("error"))) {
        const auto errorObj = root[QStringLiteral("error")].toObject();
        const QString errMsg = errorObj[QStringLiteral("message")].toString();
        const QString errType = errorObj[QStringLiteral("type")].toString();

        TB_LOG_ERROR(LogModule::AI,
            "OpenAI API error | type={} message={}",
            errType.toStdString(), errMsg.toStdString());

        // 根据错误类型返回不同错误码
        if (errType == QStringLiteral("invalid_request_error") ||
            errType == QStringLiteral("authentication_error")) {
            return Result<QString>::err(
                TB_MAKE_ERROR(ErrorCode::TranslateAuthError,
                              errMsg.toStdString()));
        }

        return Result<QString>::err(
            TB_MAKE_ERROR(ErrorCode::NetworkError, errMsg.toStdString()));
    }

    // 解析正常响应
    const QJsonArray choices = root[QStringLiteral("choices")].toArray();
    if (choices.isEmpty()) {
        return Result<QString>::err(
            TB_MAKE_ERROR(ErrorCode::NetworkError,
                          "Empty choices in OpenAI response"));
    }

    const auto firstChoice = choices[0].toObject();
    const auto messageObj = firstChoice[QStringLiteral("message")].toObject();
    const QString content = messageObj[QStringLiteral("content")].toString();

    if (content.isEmpty()) {
        return Result<QString>::err(
            TB_MAKE_ERROR(ErrorCode::NetworkError,
                          "Empty content in OpenAI response"));
    }

    // 可选：记录 token 使用量
    if (root.contains(QStringLiteral("usage"))) {
        const auto usage = root[QStringLiteral("usage")].toObject();
        TB_LOG_DEBUG(LogModule::AI,
            "Token usage | prompt={} completion={} total={}",
            usage[QStringLiteral("prompt_tokens")].toInt(),
            usage[QStringLiteral("completion_tokens")].toInt(),
            usage[QStringLiteral("total_tokens")].toInt());
    }

    return Result<QString>::ok(content);
}

    const QUrl url(m_config.baseUrl + QStringLiteral("/chat/completions"));

    const QByteArray bodyData = QJsonDocument(body).toJson(QJsonDocument::Compact);

    TB_LOG_DEBUG(LogModule::AI,
        "OpenAI request | model={} messages={} bodySize={}B",
        m_config.model.toStdString(),
        convertMessages(conversationHistory).size(),
        bodyData.size());

    QElapsedTimer timer;
    timer.start();

    m_activeReply = m_network.post(request, bodyData);

    QObject::connect(m_activeReply, &QNetworkReply::finished, this,
        [this, callback, timer]() {
            if (!m_activeReply) return;

            m_activeReply->deleteLater();
            const int latencyMs = static_cast<int>(timer.elapsed());

            // 检查是否被取消
            if (m_activeReply->error() == QNetworkReply::OperationCanceledError) {
                m_activeReply = nullptr;
                m_loading = false;
                callback(Result<QString>::err(
                    TB_MAKE_ERROR(ErrorCode::Cancelled,
                                  "Request cancelled by user")));
                TB_LOG_INFO(LogModule::AI, "OpenAI request cancelled | latency={}ms",
                    latencyMs);
                return;
            }

            // 检查网络错误
            if (m_activeReply->error() != QNetworkReply::NoError) {
                const QString errStr = m_activeReply->errorString();
                m_activeReply = nullptr;
                m_loading = false;

                TB_LOG_ERROR(LogModule::AI,
                    "OpenAI HTTP error | code={} msg={}",
                    static_cast<int>(m_activeReply->error()),
                    errStr.toStdString());

                callback(Result<QString>::err(
                    TB_MAKE_ERROR(ErrorCode::NetworkError,
                                  errStr.toStdString())));
                return;
            }

            // 解析响应
            auto result = parseResponse(m_activeReply->readAll());
            m_activeReply = nullptr;
            m_loading = false;

            if (result.isOk()) {
                TB_LOG_INFO(LogModule::AI,
                    "OpenAI response OK | latency={}ms responseLen={}",
                    latencyMs, result.value().length());
            }

            callback(std::move(result));
        });
}
```

## 6. 实现流式响应（SSE）

### 6.1 为什么需要流式

OpenAI 的完整响应可能需要 5-30 秒。如果等全部完成再显示，用户会看到长时间的空白。

流式模式（Server-Sent Events）让 AI 的回复逐字出现，体验好得多：

```
非流式：用户等待 10 秒 → 一次性显示完整回复
流式：  用户等待 0.5 秒 → "你" → "好" → "，" → "我" → "是" → ...
```

```cpp
void OpenAIService::sendMessageStream(const QString& message,
                                       const QJsonArray& conversationHistory,
                                       StreamCallback     onToken,
                                       StreamDoneCallback onDone) {
    if (message.trimmed().isEmpty()) {
        onDone(Result<QString>::err(
            TB_MAKE_ERROR(ErrorCode::InvalidArgument, "Message cannot be empty")));
        return;
    }

    m_loading = true;

    // 关键：设置 stream = true
    QJsonObject body = buildRequestBody(conversationHistory);
    body[QStringLiteral("stream")] = true;

    QUrl url(m_config.baseUrl + QStringLiteral("/chat/completions"));
    QNetworkRequest request(url);
    request.setHeader(QNetworkRequest::ContentTypeHeader,
                      QStringLiteral("application/json"));
    request.setRawHeader("Authorization",
                         ("Bearer " + m_config.apiKey).toUtf8());

    m_activeReply = m_network.post(
        request, QJsonDocument(body).toJson(QJsonDocument::Compact));

    QString fullResponse;

    // SSE 数据通过 readyRead 信号逐步到达
    QObject::connect(m_activeReply, &QNetworkReply::readyRead, this,
        [this, &fullResponse, onToken]() {
            if (!m_activeReply) return;

            // SSE 格式：每行以 "data: " 开头
            while (m_activeReply->canReadLine()) {
                QByteArray line = m_activeReply->readLine().trimmed();

                if (line.isEmpty()) continue;
                if (!line.startsWith("data: ")) continue;

                QByteArray data = line.mid(6);  // 去掉 "data: "

                // 流结束标记
                if (data == "[DONE]") continue;

                QJsonParseError err;
                auto doc = QJsonDocument::fromJson(data, &err);
                if (err.error != QJsonParseError::NoError) continue;

                auto root = doc.object();
                auto choices = root[QStringLiteral("choices")].toArray();
                if (choices.isEmpty()) continue;

                auto delta = choices[0].toObject()
                    [QStringLiteral("delta")].toObject();

                if (delta.contains(QStringLiteral("content"))) {
                    QString token = delta[QStringLiteral("content")].toString();
                    fullResponse += token;
                    onToken(token);
                }
            }
        });

    // 请求完成
    QObject::connect(m_activeReply, &QNetworkReply::finished, this,
        [this, &fullResponse, onDone]() {
            m_loading = false;
            m_activeReply->deleteLater();

            if (m_activeReply->error() == QNetworkReply::OperationCanceledError) {
                m_activeReply = nullptr;
                onDone(Result<QString>::err(
                    TB_MAKE_ERROR(ErrorCode::Cancelled, "Request cancelled")));
                return;
            }

            if (m_activeReply->error() != QNetworkReply::NoError) {
                QString errStr = m_activeReply->errorString();
                m_activeReply = nullptr;
                onDone(Result<QString>::err(
                    TB_MAKE_ERROR(ErrorCode::NetworkError, errStr.toStdString())));
                return;
            }

            m_activeReply = nullptr;
            onDone(Result<QString>::ok(fullResponse));
        });
}
```

### 6.6 流式响应中的工具调用处理（⚠️ 实战必读）

> 当 `stream: true` 且同时传了 `tools` 时，**工具调用以分片（delta）形式到达**，
> 需要手动累积拼接。这是 OpenAI 流式 + 工具的最大坑点，照搬 §6.4 的纯文本流式代码会导致工具调用丢失。

#### 6.6.1 问题分析

纯文本流式中，每个 chunk 携带一个完整的 token：

```
data: {"choices":[{"delta":{"content":"你"}}]}
data: {"choices":[{"delta":{"content":"好"}}]}
data: {"choices":[{"delta":{"content":"，我是 AI 助手"}}]}
→ 简单拼接 content 即可
```

但开启工具调用后，**同一个 `tool_call` 的字段会跨多个 chunk 分片到达**：

```
// Chunk 1：首次出现 tool_call，只有 id 和 name
data: {"choices":[{"delta":{"tool_calls":[{"index":0,"id":"call_abc","type":"function","function":{"name":"read_file"}}]}}]}

// Chunk 2：arguments 开始（可能不全）
data: {"choices":[{"delta":{"tool_calls":[{"index":0,"function":{"arguments":"{\"file"}}]}}]}

// Chunk 3：arguments 继续
data: {"choices":[{"delta":{"tool_calls":[{"index":0,"function":{"arguments":"Path\": \"C:"}}]}}]}

// Chunk 4：arguments 结尾
data: {"choices":[{"delta":{"tool_calls":[{"index":0,"function":{"arguments":"\\\\test.txt\"}"}}]}}]}

// Chunk 5：空 delta，表示 tool_call 结束
data: {"choices":[{"delta":{}}]}

// Chunk 6：[DONE]
data: [DONE]
```

> **关键**：必须在客户端按 `index` 累积 `id`、`name`、`arguments`，
> 直到收到 `finish_reason: "tool_calls"` 才算一个完整的工具调用。

#### 6.6.2 流式工具调用的完整实现

```cpp
// 流式工具调用的累积状态
struct PendingToolCall {
    QString id;           // 工具调用 ID
    int     index{0};     // tool_calls 数组中的位置
    QString name;         // 函数名
    QString arguments;    // 累积中的 JSON 参数（分片拼接）
    bool    complete{false};
};

class StreamToolCallParser {
public:
    /// 接收一个 SSE chunk 的 delta 数据，累积工具调用
    ///
    /// @return 如果某个 tool_call 刚刚完成，返回它；否则返回 nullptr
    std::optional<ToolCall> feedDelta(const QJsonObject& delta) {

        // 1. 检查是否有纯文本内容（tool_call 期间 content 通常为空）
        QString contentToken;
        if (delta.contains(QStringLiteral("content"))) {
            contentToken = delta[QStringLiteral("content")].toString();
        }

        // 2. 处理 tool_calls 分片
        const auto toolCallsDelta = delta[QStringLiteral("tool_calls")].toArray();
        for (const auto& tcDelta : toolCallsDelta) {
            const auto tcObj = tcDelta.toObject();
            const int index = tcObj[QStringLiteral("index")].toInt();

            // 确保有对应位置的累积区
            if (index >= (int)m_pending.size()) {
                m_pending.resize(index + 1);
                m_pending[index].index = index;
            }

            auto& pending = m_pending[index];

            // 累积 id（只在第一个 chunk 中出现）
            if (tcObj.contains(QStringLiteral("id"))) {
                pending.id = tcObj[QStringLiteral("id")].toString();
            }

            // 累积 function.name（只在第一个 chunk 中出现）
            const auto funcObj = tcObj[QStringLiteral("function")].toObject();
            if (funcObj.contains(QStringLiteral("name"))) {
                pending.name = funcObj[QStringLiteral("name")].toString();
            }

            // 累积 arguments（可能跨多个 chunk 分片到达）
            if (funcObj.contains(QStringLiteral("arguments"))) {
                pending.arguments += funcObj[QStringLiteral("arguments")].toString();
            }
        }

        return std::nullopt;  // 工具调用尚未完成
    }

    /// 当收到 finish_reason 时调用，返回所有完整的工具调用
    ///
    /// @param finishReason 来自 choices[0].finish_reason
    std::vector<ToolCall> finalize(const QString& finishReason) {

        std::vector<ToolCall> result;

        if (finishReason == QStringLiteral("tool_calls")) {
            for (auto& pending : m_pending) {
                pending.complete = true;

                // 解析累积完成的 arguments
                QJsonParseError parseErr;
                QJsonDocument doc = QJsonDocument::fromJson(
                    pending.arguments.toUtf8(), &parseErr);

                ToolCall call;
                call.id        = pending.id;
                call.name      = pending.name;
                call.arguments = (parseErr.error == QJsonParseError::NoError)
                    ? doc.object() : QJsonObject();

                result.push_back(call);
            }
        }

        // 重置累积状态，准备下一轮
        m_pending.clear();
        return result;
    }

private:
    std::vector<PendingToolCall> m_pending;
};
```

#### 6.6.4 finish_reason 的精确捕获

由于 SSE 没有显式的"流结束包"，`finish_reason` 出现在**最后一个有内容的 chunk** 中：

```json
// 最后一个 chunk（同时包含最后一个 token 和 finish_reason）
data: {"choices":[{"delta":{"content":"。"},"finish_reason":"stop"}]}

// 工具调用时的最后一个 chunk
data: {"choices":[{"delta":{},"finish_reason":"tool_calls"}]}
```

因此需要缓存 `finish_reason`，在 `finished` 信号中使用：

```cpp
QString m_streamFinishReason;  // 在流式处理中缓存

// readyRead 中：
auto choice = choices[0].toObject();
if (choice.contains(QStringLiteral("finish_reason"))) {
    m_streamFinishReason = choice[QStringLiteral("finish_reason")].toString();
}

// finished 信号中：
auto toolCalls = toolParser.finalize(m_streamFinishReason);
```

```
    │              .arguments = "{\"file"           │  ← arguments 分片1
    │  chunk 5: delta.tool_calls[0].function       │
    │              .arguments = "Path\":\"test\"}"   │  ← arguments 分片2
    │  chunk 6: delta = {}, finish_reason =        │  ← 工具调用结束
    │              "tool_calls"                     │
    │  chunk 7: [DONE]                              │
    └────────┬─────────────────────────────────────┘
             │
             ▼
    ┌─────────────────────────────────┐
    │  StreamToolCallParser.finalize   │
    │  → ToolCall { id="call_1",      │
    │    name="read_file",            │
    │    arguments={filePath:"test"}} │
    └────────┬────────────────────────┘
             │
             ▼
    ┌─────────────────────────────────┐
    │  ViewModel 执行工具              │
    │  → 追加 tool_call 消息到历史     │
    │  → 执行 ITool.execute()         │
    │  → 追加 tool_result 消息到历史   │
    │  → 再次调用 sendMessageStream     │
    │    WithTools(...) 进入下一轮     │
    └─────────────────────────────────┘
```

## 8. 常见问题与注意事项

### 8.1 API Key 安全

```
❌ 错误做法：API Key 硬编码在源码中
   aiConfig.apiKey = "sk-abc123...";

✅ 正确做法：
   1. 从环境变量读取
      aiConfig.apiKey = qEnvironmentVariable("OPENAI_API_KEY");

   2. 从配置文件读取（加密存储）
      aiConfig.apiKey = configManager->getDecrypted("ai.apiKey");

   3. 在设置页面让用户输入，保存到本地配置
```

### 8.2 与翻译服务的对比总结

```
翻译服务的"引擎"概念：
  ┌─────────────────────────────────┐
  │  TranslateService (调度层)       │
  │    ├── YoudaoEngine             │
  │    ├── DeepLEngine              │
  │    └── GoogleEngine             │
  └─────────────────────────────────┘
  多个引擎，用户可切换，接口统一。

AI 服务没有"引擎"概念：
  ┌─────────────────────────────────┐
  │  OpenAIService                  │
  │    → 通过 baseUrl + model 配置  │
  │    → 同一个接口，不同参数        │
  └─────────────────────────────────┘
  一个服务，通过配置适配不同 API 提供商。
```

这是因为所有 LLM API 都遵循 OpenAI 的接口规范，不需要像翻译那样为每个引擎写单独的实现。

### 8.3 对话历史的内存管理

```
问题：长时间对话，history 会越来越大，最终超出模型的 context window。

解决方案（按优先级）：
1. 设置 maxTokens 限制回复长度
2. 限制 history 最大条数（如保留最近 50 条）
3. 当 history 超过阈值时，丢弃最早的非 system 消息
4. （高级）对旧消息做摘要压缩

实现示例：
QJsonArray trimmedHistory(const QJsonArray& history, int maxMessages = 50) {
    if (history.size() <= maxMessages) return history;
    // 保留最近的 maxMessages 条
    QJsonArray result;
    for (int i = history.size() - maxMessages; i < history.size(); ++i) {
        result.append(history[i]);
    }
    return result;
}
```

## 9. 多模型提供商架构

> 打造一个真正的**本地化 AI 助手**，首先需要支持多种 LLM 后端 —— 既要能接入云端 API，也要能运行本地模型。

### 9.1 为什么需要多提供商支持

单一 OpenAIService 的实现只能对接 OpenAI 兼容的 API。但本地化 AI 助手需要：

```
场景 1：日常使用云端大模型
  OpenAI GPT-4o / Claude / DeepSeek → 能力强、速度快、付费

场景 2：隐私敏感数据
  本地 Ollama（Llama 3 / Qwen 2） → 数据不出本机、免费、可离线

场景 3：混合使用
  普通对话走云端，涉及本地文件分析走本地模型
  或：用小模型做意图识别，大模型做深度推理
```

### 9.2 提供商抽象层

与翻译服务的"多引擎"模式不同，AI 服务不需要为每个提供商写独立的 SDK —— 几乎所有 LLM 都兼容 OpenAI 的 `/v1/chat/completions` 接口。差异主要体现在：

| 方面 | OpenAI | Ollama（本地） | DeepSeek / 通义千问 |
|------|--------|---------------|-------------------|
| API 地址 | `api.openai.com/v1` | `localhost:11434/v1` | 各厂商提供 |
| 鉴权 | Bearer Token | 无需鉴权 | Bearer Token |
| 模型名 | `gpt-4o`, `gpt-4o-mini` | `llama3.1`, `qwen2.5` | `deepseek-chat` 等 |
| 函数调用 | ✅ 原生支持 | ⚠️ 部分模型支持 | ✅ 原生支持 |
| 流式 | ✅ | ✅ | ✅ |

因此，我们可以在 **不修改 IAIService 接口** 的前提下，通过配置实现多提供商支持：

```cpp
// AI 服务配置（扩展 ConfigSchema）
struct AIConfig {
    // 当前使用的提供商
    QString provider{QStringLiteral("openai")};  // "openai" | "ollama" | "custom"

    // 各提供商配置
    QString openaiApiKey;
    QString openaiBaseUrl{QStringLiteral("https://api.openai.com/v1")};
    QString openaiModel{QStringLiteral("gpt-4o")};

    QString ollamaBaseUrl{QStringLiteral("http://localhost:11434/v1")};
    QString ollamaModel{QStringLiteral("llama3.1")};

    QString customBaseUrl;
    QString customApiKey;
    QString customModel;

    // 通用参数
    int     maxTokens{4096};
    double  temperature{0.7};
    QString systemPrompt;
    int     maxHistoryMessages{50};
};
```

### 9.3 运行时切换提供商

ViewModel 层的 `sendMessage()` 无需关心当前使用哪个提供商 —— 这一层由 Service 抽象屏蔽。但用户需要在界面上自由切换：

```cpp

               NOTIFY currentProviderChanged FINAL)
```

实现逻辑：

```cpp
void AIAssistantViewModel::switchProvider(const QString& provider) {
    // 1. 更新 ConfigManager 中的 provider 设置
    // 2. 重新创建 IAIService 实例（使用新配置）
    // 3. 清空对话历史（可选，不同模型间的上下文不互通）
    // 4. emit currentProviderChanged()

    m_config->update<AppConfig>([&](AppConfig& cfg) {
        cfg.aiConfig.provider = provider;
    });

    // 重新创建服务
    m_service = createServiceForProvider(provider);
    clearConversation();
    emit currentProviderChanged();
    emit currentModelChanged();
}
```

### 9.4 创建不同提供商的 Service

```cpp
// AIAssistantViewModel 中的工厂方法
IAIService::Ptr AIAssistantViewModel::createServiceForProvider(
    const QString& provider) {

    const auto cfg = m_config->get<AppConfig>();

    if (provider == QStringLiteral("openai")) {
        OpenAIService::Config openaiCfg;
        openaiCfg.apiKey    = cfg.aiConfig.openaiApiKey;
        openaiCfg.baseUrl   = cfg.aiConfig.openaiBaseUrl;
        openaiCfg.model     = cfg.aiConfig.openaiModel;
        openaiCfg.maxTokens = cfg.aiConfig.maxTokens;
        return std::make_shared<OpenAIService>(openaiCfg);

    } else if (provider == QStringLiteral("ollama")) {
        // Ollama 也兼容 OpenAI API，所以复用 OpenAIService
        OpenAIService::Config ollamaCfg;
        ollamaCfg.apiKey  = QString();  // Ollama 无需鉴权
        ollamaCfg.baseUrl = cfg.aiConfig.ollamaBaseUrl;
        ollamaCfg.model   = cfg.aiConfig.ollamaModel;
        return std::make_shared<OpenAIService>(ollamaCfg);

    } else if (provider == QStringLiteral("custom")) {
        OpenAIService::Config customCfg;
        customCfg.apiKey  = cfg.aiConfig.customApiKey;
        customCfg.baseUrl = cfg.aiConfig.customBaseUrl;
        customCfg.model   = cfg.aiConfig.customModel;
        return std::make_shared<OpenAIService>(customCfg);
    }

    return std::make_shared<MockAIService>();
}
```

> **💡 核心思路**：Ollama 从 v0.5.5 起提供 `/v1/chat/completions` 兼容端点，因此我们不需要为它编写独立的 Service 类，只需改变 `baseUrl` 和 `model` 即可。对于完全不兼容 OpenAI 接口的本地引擎（如 llama.cpp 的原始接口），才需要新建 `LocalLLMService` 类。

## 10. 函数调用与工具系统

> 真正的 AI 助手不只是"对话机器人"，它应该能**读取你的文件**、**执行操作**、**完成任务**。
> 本节设计一个类似于 LangChain 的工具（Tool）系统。

### 10.1 为什么需要工具系统

纯文本对话的 AI 能力有限：

```
用户："帮我找到桌面上最近修改的 Python 文件，告诉我里面有没有 API Key"

❌ 纯对话模型：无法访问文件系统，只能给出建议
✅ 接入工具的 AI：可以搜索文件 → 读取内容 → 分析 → 给出结论
```

### 10.2 工具接口设计

```cpp
// src/core/ai/ITool.h
#pragma once

#include <QString>
#include <QJsonObject>
#include <functional>

#include "core/error/Error.h"

/// 工具参数定义（用于告知 LLM 此工具的参数格式）
struct ToolParameter {
    QString name;            // 参数名
    QString description;     // 参数描述
    QString type;            // "string" | "number" | "boolean" | "array" | "object"
    bool    required{false}; // 是否必填
};

/// 工具定义（描述一个工具的信息）
struct ToolDefinition {
    QString              id;           // 工具唯一 ID，如 "read_file"
    QString              name;         // 工具显示名称
    QString              description;  // 工具描述（LLM 通过此描述决定是否调用）
    std::vector<ToolParameter> parameters;  // 参数列表
};

/// 工具调用结果
struct ToolResult {
    bool    success{false};     // 是否成功
    QString output;             // 工具输出的文本内容
    QJsonObject extraData;      // 额外的结构化数据（可选）
};

/// 工具抽象接口
class ITool {
public:
    virtual ~ITool() = default;

    /// 获取工具定义（用于告知 LLM 此工具的存在和参数）
    [[nodiscard]] virtual ToolDefinition definition() const = 0;

    /// 执行工具
    ///
    /// @param arguments 从 LLM 解析出的参数 JSON 对象
    /// @return 工具执行结果
    [[nodiscard]] virtual ToolResult execute(
        const QJsonObject& arguments) = 0;

    /// 工具是否需要用户确认（危险操作建议设为 true）
    [[nodiscard]] virtual bool requiresConfirmation() const { return false; }
};
```

## 11. 本地 RAG 实现

> RAG（Retrieval-Augmented Generation）让 AI 助手能够**理解你的本地文档**，
> 回答关于本地文件内容的问题，而不需要把文件全部上传到云端。

### 11.1 分层方案

根据项目当前阶段，RAG 实现按复杂度分为三个层级，逐步演进：

```
层级 1：Prompt 注入（已部分实现）
  ┌──────────────────────────────────────────┐
  │  用户上传文件 → 读取文件内容              │
  │  → 注入到 System Prompt → AI 参考回答     │
  └──────────────────────────────────────────┘
  优点：零额外依赖，立即可用
  缺点：受限于 context window，大文件无法处理

层级 2：关键词检索（短期目标）
  ┌──────────────────────────────────────────┐
  │  本地文档 → SQLite FTS5 全文索引          │
  │  → 用户提问 → 关键词匹配 → 检索相关段落    │
  │  → 注入 Context → AI 参考回答             │
  └──────────────────────────────────────────┘
  优点：高效、可控、离线可用
  缺点：无法理解语义（"车"搜不到"汽车"）

层级 3：语义检索（远期目标）
  ┌──────────────────────────────────────────┐
  │  本地文档 → 文本分块 → Embedding 向量化    │
  │  → 向量存储 → 语义搜索 → 检索 Top-K 段落   │
  │  → 注入 Context → AI 参考回答             │
  └──────────────────────────────────────────┘
  优点：理解语义，召回率高
  缺点：需要 Embedding 模型，额外依赖
```

### 11.2 层级 1：Prompt 注入（当前实现）

**检索与 RAG 流程：**

```cpp
class DocumentRetriever {
public:
    /// 根据用户问题检索相关文档段落
    struct RetrievedChunk {
        QString filePath;
        QString fileName;
        QString content;
        double  score{0.0};     // 相关性分数（FTS5 的 bm25）
        int     chunkIndex{0};  // 在原文档中的块序号
    };

    /// 检索 Top-K 相关段落
    [[nodiscard]] std::vector<RetrievedChunk> retrieve(
        const QString& query, int topK = 5) const {

        std::vector<RetrievedChunk> results;

        // 使用 FTS5 全文搜索
        QSqlQuery q(m_db);
        q.prepare(QStringLiteral(
            "SELECT file_path, file_name, content, rank "
            "FROM docs_fts "
            "WHERE docs_fts MATCH :query "
            "ORDER BY rank "
            "LIMIT :limit"
        ));
        q.bindValue(QStringLiteral(":query"), query);
        q.bindValue(QStringLiteral(":limit"), topK);
        q.exec();

        while (q.next()) {
            results.push_back({
                .filePath   = q.value(0).toString(),
                .fileName   = q.value(1).toString(),
                .content    = q.value(2).toString(),
                .score      = q.value(3).toDouble(),
            });
        }

        return results;
    }

    /// 将检索结果格式化为上下文文本
    [[nodiscard]] QString formatContext(
        const std::vector<RetrievedChunk>& chunks) const {

        QString context;
        context += QStringLiteral("以下是用户本地文档中与问题相关的内容，请参考这些信息回答：\n\n");

        for (size_t i = 0; i < chunks.size(); ++i) {
            context += QStringLiteral("[文档 %1] %2 (%3)\n```\n%4\n```\n\n")
                .arg(i + 1)
                .arg(chunks[i].fileName)
                .arg(chunks[i].filePath)
                .arg(chunks[i].content);
        }

        return context;
    }
};
```

**内存向量存储：**

由于项目暂时没有引入 FAISS/ChromaDB/HNSWLib，建议用简单的内存向量存储起步：

```cpp
// src/core/ai/VectorStore.h
#pragma once

#include <QString>
#include <vector>
#include <cmath>
#include <algorithm>

/// 向量存储条目
struct VectorEntry {
    QString              id;        // 唯一 ID
    QString              filePath;  // 来源文件路径
    QString              content;   // 原始文本
    std::vector<float>   embedding; // 嵌入向量
    int                  chunkIndex{0};
};

/// 内存向量存储
///
/// 用暴力搜索（Brute Force）实现 Top-K 检索。
/// 数据量 < 10,000 条时性能可接受。
/// 后续可替换为 HNSWLib / FAISS 以获得更好的扩展性。
class VectorStore {
public:
    /// 添加向量条目
    void addEntry(VectorEntry entry) {
        m_entries.push_back(std::move(entry));
    }

    /// 批量添加
    void addEntries(std::vector<VectorEntry> entries) {
        for (auto& entry : entries) {
            m_entries.push_back(std::move(entry));
        }
    }

    /// 余弦相似度搜索
    [[nodiscard]] std::vector<std::pair<size_t, double>>
    search(const std::vector<float>& queryEmbedding, int topK = 5) const {

        std::vector<std::pair<size_t, double>> scores;

        for (size_t i = 0; i < m_entries.size(); ++i) {
            double similarity = cosineSimilarity(queryEmbedding, m_entries[i].embedding);
            scores.emplace_back(i, similarity);
        }

        // 按相似度降序排列，取 Top-K
        std::partial_sort(scores.begin(),
                          scores.begin() + std::min(topK, (int)scores.size()),
                          scores.end(),
                          [](const auto& a, const auto& b) {
                              return a.second > b.second;
                          });

        if (scores.size() > (size_t)topK) {
            scores.resize(topK);
        }

        return scores;
    }

    /// 获取条目
    [[nodiscard]] const VectorEntry& getEntry(size_t index) const {
        return m_entries[index];
    }

    /// 条目数量
    [[nodiscard]] size_t size() const { return m_entries.size(); }

    /// 清空所有条目
    void clear() { m_entries.clear(); }

private:
    /// 余弦相似度计算
    static double cosineSimilarity(
        const std::vector<float>& a,
        const std::vector<float>& b) {

        double dotProduct = 0.0, normA = 0.0, normB = 0.0;
        for (size_t i = 0; i < a.size(); ++i) {
            dotProduct += a[i] * b[i];
            normA += a[i] * a[i];
            normB += b[i] * b[i];
        }
        if (normA == 0.0 || normB == 0.0) return 0.0;
        return dotProduct / (std::sqrt(normA) * std::sqrt(normB));
    }

    std::vector<VectorEntry> m_entries;
};
```

**步骤 2：实现 OllamaEmbeddingService**

```cpp
// src/services/ai/OllamaEmbeddingService.h
#pragma once

#include <QObject>
#include <QNetworkAccessManager>
#include <QNetworkReply>
#include <QJsonDocument>
#include <QJsonObject>
#include <QJsonArray>
#include <vector>

#include "core/ai/IEmbeddingService.h"
#include "core/error/Error.h"

/// 基于 Ollama 本地 API 的 Embedding 服务
///
/// 零额外依赖：只要本机运行了 Ollama 即可使用。
/// 数据完全本地处理，不上传云端。
class OllamaEmbeddingService final : public QObject, public IEmbeddingService {
    Q_OBJECT

public:
    struct Config {
        QString baseUrl{QStringLiteral("http://localhost:11434")};
        QString model{QStringLiteral("nomic-embed-text")};  // 默认 768 维
        int     timeoutMs{30000};
    };

    explicit OllamaEmbeddingService(Config config, QObject* parent = nullptr)
        : QObject(parent), m_config(std::move(config)) {}

    [[nodiscard]] Result<std::vector<float>> embed(const QString& text) override {

        QUrl url(m_config.baseUrl + QStringLiteral("/api/embeddings"));
        QNetworkRequest request(url);
        request.setHeader(QNetworkRequest::ContentTypeHeader,
                          QStringLiteral("application/json"));
        request.setTransferTimeout(m_config.timeoutMs);

        QJsonObject body;
        body[QStringLiteral("model")]  = m_config.model;
        body[QStringLiteral("prompt")] = text;  // Ollama 用 "prompt" 不是 "input"
        // 可选参数
        QJsonObject options;
        options[QStringLiteral("temperature")] = 0.0;  // embedding 不需要温度
        body[QStringLiteral("options")] = options;

        QNetworkReply* reply = m_network.post(
            request, QJsonDocument(body).toJson(QJsonDocument::Compact));

        // 同步等待（embedding 通常在 100-500ms 内完成）
        QEventLoop loop;
        QObject::connect(reply, &QNetworkReply::finished, &loop, &QEventLoop::quit);
        loop.exec();

        reply->deleteLater();

        if (reply->error() != QNetworkReply::NoError) {
            return Result<std::vector<float>>::err(
                TB_MAKE_ERROR(ErrorCode::NetworkError,
                              reply->errorString().toStdString()));
        }

        // 解析响应
        QJsonParseError parseErr;
        QJsonDocument doc = QJsonDocument::fromJson(reply->readAll(), &parseErr);
        if (parseErr.error != QJsonParseError::NoError) {
            return Result<std::vector<float>>::err(
                TB_MAKE_ERROR(ErrorCode::NetworkError, "Invalid JSON from Ollama"));
        }

        const auto root = doc.object();
        const auto embeddingArray = root[QStringLiteral("embedding")].toArray();

        std::vector<float> result;
        result.reserve(embeddingArray.size());
        for (const auto& val : embeddingArray) {
            result.push_back(static_cast<float>(val.toDouble()));
        }

        return Result<std::vector<float>>::ok(std::move(result));
    }

    [[nodiscard]] Result<std::vector<std::vector<float>>>
    embedBatch(const std::vector<QString>& texts) override {

        // Ollama 的 /api/embeddings 不支持 batch
        // 逐个调用（可以优化为并发请求）
        std::vector<std::vector<float>> results;
        results.reserve(texts.size());

        for (const auto& text : texts) {
            auto result = embed(text);
            if (result.isErr()) {
                return Result<std::vector<std::vector<float>>>::err(
                    TB_MAKE_ERROR(ErrorCode::NetworkError,
                                  "Batch embedding failed"));
            }
            results.push_back(std::move(result).value());
        }

        return Result<std::vector<std::vector<float>>>::ok(std::move(results));
    }

    [[nodiscard]] int dimension() const override {

        if (m_config.model == QStringLiteral("bge-m3")) return 1024;
        if (m_config.model == QStringLiteral("mxbai-embed-large")) return 1024;
        return 768;  // 默认

    Config                m_config;
    QNetworkAccessManager m_network;
};
```

### 11.4.2 VectorStore 持久化存储

> 当前 §11.4 的 `VectorStore` 是纯内存实现，应用重启后**所有索引丢失**。
> 需要在退出时序列化到磁盘、启动时恢复加载。

**方案对比：**

| 方案 | 实现复杂度 | 恢复速度 | 存储体积 | 推荐场景 |
|------|-----------|---------|---------|---------|
| SQLite BLOB | 低 | 快 | 紧凑 | 数据量 < 10万条 |
| 原始二进制文件 | 最低 | 最快 | 紧凑 | 快速原型 |
| ChromaDB / Qdrant | 高（需独立服务） | 中 | 大 | 生产级海量数据 |

**推荐方案：SQLite BLOB + JSON 元数据**

向量数据存在 SQLite 的 BLOB 列中，元数据（filePath、content）存为 TEXT 列：

```cpp
// src/core/ai/PersistentVectorStore.h
#pragma once

#include <QSqlDatabase>
#include <QSqlQuery>
#include <QSqlError>
#include <QVector>
#include <cstring>
#include <optional>

#include "core/ai/VectorStore.h"
#include "core/log/Logger.h"
#include "core/log/LogModules.h"

/// 可持久化的向量存储
///
/// 使用 SQLite BLOB 存储向量，TEXT 存储元数据。
/// 启动时从 SQLite 加载全部向量到内存（数据量 < 10万条时可行）。
class PersistentVectorStore : public VectorStore {
public:
    explicit PersistentVectorStore(const QString& dbPath = QString()) {
        const QString path = dbPath.isEmpty()
            ? QStandardPaths::writableLocation(QStandardPaths::AppDataLocation)
              + QStringLiteral("/vector_store.db")
            : dbPath;

        m_db = QSqlDatabase::addDatabase(
            QStringLiteral("QSQLITE"), QStringLiteral("vector_store_connection"));
        m_db.setDatabaseName(path);

        if (!m_db.open()) {
            TB_LOG_ERROR(LogModule::AI,
                "Failed to open vector store DB: {}",
                m_db.lastError().text().toStdString());
            return;
        }

        createSchema();
        loadFromDb();
    }

    ~PersistentVectorStore() override {
        if (m_db.isOpen()) {
            m_db.close();
        }
    }

    /// 添加条目并持久化
    void addEntry(const VectorEntry& entry) {
        VectorStore::addEntry(entry);  // 先加到内存
        persistEntry(entry);           // 再写入 SQLite
    }

    /// 批量添加并持久化
    void addEntries(const std::vector<VectorEntry>& entries) {
        m_db.transaction();  // 事务批量写入，大幅提升速度
        for (const auto& entry : entries) {
            VectorStore::addEntry(entry);
            persistEntry(entry);
        }
        m_db.commit();
    }

    /// 删除条目
    void removeEntry(const QString& id) {
        QSqlQuery q(m_db);
        q.prepare(QStringLiteral("DELETE FROM vectors WHERE id = :id"));
        q.bindValue(QStringLiteral(":id"), id);
        q.exec();

        // 同时从内存移除
        auto& entries = const_cast<std::vector<VectorEntry>&>(getAllEntries());
        entries.erase(std::remove_if(entries.begin(), entries.end(),
            [&id](const VectorEntry& e) { return e.id == id; }),
            entries.end());
    }

    /// 清空所有数据
    void clearAll() {
        QSqlQuery q(m_db);
        q.exec(QStringLiteral("DELETE FROM vectors"));

        VectorStore::clear();
    }

    /// 从数据库重新加载（用于索引重建后）
    void reload() {
        VectorStore::clear();
        loadFromDb();
    }

private:
    void createSchema() {
        QSqlQuery q(m_db);
        q.exec(QStringLiteral(
            "CREATE TABLE IF NOT EXISTS vectors ("
            "  id          TEXT PRIMARY KEY,"
            "  file_path   TEXT NOT NULL,"
            "  content     TEXT NOT NULL,"
            "  embedding   BLOB NOT NULL,"    // std::vector<float> 序列化
            "  chunk_index INTEGER DEFAULT 0,"
            "  created_at  TEXT DEFAULT (datetime('now'))"
            ")"
        ));

        // 加速按 file_path 查询
        q.exec(QStringLiteral(
            "CREATE INDEX IF NOT EXISTS idx_vectors_file_path "
            "ON vectors(file_path)"
        ));
    }

    void persistEntry(const VectorEntry& entry) {
        QSqlQuery q(m_db);
        q.prepare(QStringLiteral(
            "INSERT OR REPLACE INTO vectors "
            "(id, file_path, content, embedding, chunk_index) "
            "VALUES (:id, :file_path, :content, :embedding, :chunk_index)"
        ));
        q.bindValue(QStringLiteral(":id"),         entry.id);
        q.bindValue(QStringLiteral(":file_path"),  entry.filePath);
        q.bindValue(QStringLiteral(":content"),    entry.content);
        q.bindValue(QStringLiteral(":embedding"),  serializeEmbedding(entry.embedding));
        q.bindValue(QStringLiteral(":chunk_index"), entry.chunkIndex);

        if (!q.exec()) {
            TB_LOG_ERROR(LogModule::AI,
                "Failed to persist vector entry: {}",
                q.lastError().text().toStdString());
        }
    }

    void loadFromDb() {
        QSqlQuery q(m_db);
        q.exec(QStringLiteral(
            "SELECT id, file_path, content, embedding, chunk_index FROM vectors"
        ));

        int count = 0;
        while (q.next()) {
            VectorEntry entry;
            entry.id         = q.value(0).toString();
            entry.filePath   = q.value(1).toString();
            entry.content    = q.value(2).toString();
            entry.embedding  = deserializeEmbedding(q.value(3).toByteArray());
            entry.chunkIndex = q.value(4).toInt();

            VectorStore::addEntry(entry);
            count++;
        }

        TB_LOG_INFO(LogModule::AI,
            "Loaded {} vectors from persistent store", count);
    }

    /// 将 std::vector<float> 序列化为 QByteArray（BLOB）
    static QByteArray serializeEmbedding(const std::vector<float>& vec) {
        QByteArray data;
        data.resize(static_cast<int>(vec.size() * sizeof(float)));
        std::memcpy(data.data(), vec.data(), vec.size() * sizeof(float));
        return data;
    }

    /// 从 QByteArray（BLOB）反序列化为 std::vector<float>
    static std::vector<float> deserializeEmbedding(const QByteArray& data) {
        const size_t count = data.size() / sizeof(float);
        std::vector<float> result(count);
        std::memcpy(result.data(), data.constData(), data.size());
        return result;
    }

    QSqlDatabase m_db;
};
```

### 12.2 Agent 状态机与数据结构

真正能跑起来的 Agent，比原设计多了三类状态：**等待用户确认**、**被取消**、**检测到重复调用**。
用一个显式状态机来表达，比散落的 `bool` 标志位更不容易出 bug：

```cpp
// src/core/ai/AIAgent.h
#pragma once

#include <QObject>
#include <QJsonArray>
#include <QJsonObject>
#include <QElapsedTimer>
#include <QHash>
#include <memory>
#include <optional>

#include "services/ai/IAIService.h"
#include "core/ai/ToolRegistry.h"

/// Agent 运行状态
enum class AgentState {
    Idle,                  // 空闲
    Thinking,              // 等待 LLM 响应
    ExecutingTool,         // 正在执行工具
    WaitingConfirmation,   // 等待用户确认危险工具

/// 一次挂起的工具调用（等待用户确认时使用）
struct PendingConfirmation {
    ToolCall     call;
    QJsonArray   messagesBeforeCall;  // 确认后需要基于这个消息列表继续

};

/// 智能 AI 代理
///
/// 整合 LLM + 工具系统 + RAG，实现自主任务完成。
/// 设计目标：云端模型（原生 function calling）和本地 Ollama 模型
/// （原生或 Prompt 注入两种模式，见 §12.4）使用**同一套循环逻辑**，

    QElapsedTimer     m_iterationTimer;
```

### 12.3 Agent 主循环完整实现（补全 TODO）

这是原文档里唯一停在 `// TODO` 的地方，也是整个 Agent 系统的心脏。完整实现如下：

```cpp
// src/core/ai/AIAgent.cpp
#include "core/ai/AIAgent.h"

#include <QJsonDocument>
#include <QCryptographicHash>

#include "core/log/Logger.h"
#include "core/log/LogModules.h"

AIAgent::AIAgent(IAIService::Ptr service, ToolRegistry::Ptr toolRegistry, QObject* parent)
    : QObject(parent)
    , m_service(std::move(service))
    , m_toolRegistry(std::move(toolRegistry)) {
}

void AIAgent::setService(IAIService::Ptr service) {
    m_service = std::move(service);
}

void AIAgent::setState(AgentState s) {
    m_state = s;
    emit stateChanged(s);
}

QString AIAgent::callFingerprint(const ToolCall& call) {
    // 用排序后的 key 生成规范化 JSON，避免 {"a":1,"b":2} 和 {"b":2,"a":1}
    // 被误判为"不同调用"
    QJsonObject sorted;
    QStringList keys = call.arguments.keys();
    keys.sort();
    for (const auto& k : keys) sorted[k] = call.arguments[k];

    const QByteArray canonical = call.name.toUtf8() + '|' +
        QJsonDocument(sorted).toJson(QJsonDocument::Compact);
    return QString::fromUtf8(
        QCryptographicHash::hash(canonical, QCryptographicHash::Sha1).toHex());
}

void AIAgent::processMessage(const QString& message,
                              const QJsonArray& history,
                              const QString& context) {
    m_cancelled = false;
    m_callFingerprints.clear();
    m_pending.reset();

    // 构建完整消息（系统提示词 + 工具描述 + RAG 上下文 + 历史 + 本次输入）
    QJsonArray messages;

    QJsonObject sysMsg;
    QString sysContent = QStringLiteral(
        "你是一个运行在用户本机的智能 AI 助手，可以使用工具访问本地文件系统。"
        "请仔细理解用户的需求，选择合适的工具来完成任务，一次只调用一个工具，"
        "拿到工具结果后再决定下一步。如果任务已经可以回答，直接给出自然语言回复，"
        "不要再调用工具。"
    );

    if (m_toolRegistry) {
        sysContent += QStringLiteral("\n\n## 可用工具\n");
        for (const auto& def : m_toolRegistry->allDefinitions()) {
            sysContent += QStringLiteral("- %1：%2\n").arg(def.name, def.description);
        }
    }

    if (!context.isEmpty()) {
        sysContent += QStringLiteral("\n\n## 参考信息\n%1").arg(context);
    }

    sysMsg[QStringLiteral("role")]    = QStringLiteral("system");
    sysMsg[QStringLiteral("content")] = sysContent;
    messages.append(sysMsg);

    for (const auto& msg : history) messages.append(msg);

    QJsonObject userMsg;
    userMsg[QStringLiteral("role")]    = QStringLiteral("user");
    userMsg[QStringLiteral("content")] = message;
    messages.append(userMsg);

    // §12.6：历史 + 本次消息可能已经超出本地模型的上下文预算，进入循环前先裁剪一次
    messages = ContextBudgetManager::instance().enforceBudget(
        messages, m_service->contextWindowTokens());

    emit agentThinking(QStringLiteral("正在理解您的需求..."));
    executeLlmCall(messages, 0);
}

void AIAgent::executeLlmCall(const QJsonArray& messages, int iterationCount) {
    if (m_cancelled) {
        setState(AgentState::Cancelled);
        emit agentCancelled();
        return;
    }

    if (iterationCount >= m_maxIterations) {
        TB_LOG_WARN(LogModule::AI, "Agent | max iterations reached ({})", iterationCount);
        setState(AgentState::Error);
        emit agentMaxIterationsReached(iterationCount);
        return;
    }

    setState(AgentState::Thinking);
    emit agentThinking(iterationCount == 0
        ? QStringLiteral("正在理解您的需求...")
        : QStringLiteral("正在根据工具结果继续思考..."));

    const auto tools = m_toolRegistry ? m_toolRegistry->allDefinitions()
                                       : std::vector<ToolDefinition>{};

    m_iterationTimer.start();

    // §12.4：chatComplete() 对云端原生 function calling、
    // 本地原生 function calling、本地 Prompt 注入三种模式统一封装，
    // Agent 这一层完全不需要关心底层是哪种模式。
    m_service->chatComplete(messages, tools,
        [this, messages, iterationCount](Result<ChatResponse> result) {
            // 回调可能在超时之后才到达（本地模型推理慢时常见），
            // 用 elapsed 只做日志记录，不在这里做超时判定——
            // 真正的超时判定由 §12.3.1 的看门狗定时器负责。
            handleChatResponse(result, messages, iterationCount);
        });
}

void AIAgent::handleChatResponse(const Result<ChatResponse>& result,
                                  const QJsonArray& messagesSoFar,
                                  int iterationCount) {
    if (m_cancelled) {
        setState(AgentState::Cancelled);
        emit agentCancelled();
        return;
    }

    if (result.isErr()) {
        TB_LOG_ERROR(LogModule::AI, "Agent | LLM call failed: {}",
            result.error().message);
        setState(AgentState::Error);
        emit agentError(QString::fromStdString(result.error().message));
        return;
    }

    const ChatResponse& response = result.value();

    // 情况 1：模型给出了最终文本回复，没有工具调用 → 结束
    if (response.toolCalls.empty()) {
        setState(AgentState::Done);
        emit responseReady(response.content);
        return;
    }

    // 情况 2：模型请求调用工具。本地小模型有时会一次性"抢跑"输出多个
    // tool_calls；为了让 Agent 的确认/重试逻辑保持简单可预测，
    // 这里固定策略：只处理第一个，其余丢弃并记录日志。
    if (response.toolCalls.size() > 1) {
        TB_LOG_WARN(LogModule::AI,
            "Agent | model returned {} tool_calls in one turn, only executing the first",
            response.toolCalls.size());
    }

    const ToolCall& call = response.toolCalls.front();

    // 把 "assistant 发起了工具调用" 这条消息追加进历史，
    // 下一轮请求必须带上它，否则模型看不到自己上一步做了什么。
    // ⚠️ 注意 arguments 在这里要重新序列化成字符串，
    // 因为 OpenAI 协议里 tool_calls[].function.arguments 是字符串而不是对象。
    QJsonArray updatedMessages = messagesSoFar;
    QJsonObject assistantMsg;
    assistantMsg[QStringLiteral("role")]    = QStringLiteral("assistant");
    assistantMsg[QStringLiteral("content")] = response.content;  // 可能为空字符串

    QJsonObject toolCallObj;
    toolCallObj[QStringLiteral("id")]   = call.id;
    toolCallObj[QStringLiteral("type")] = QStringLiteral("function");
    QJsonObject funcObj;
    funcObj[QStringLiteral("name")]      = call.name;
    funcObj[QStringLiteral("arguments")] =
        QString::fromUtf8(QJsonDocument(call.arguments).toJson(QJsonDocument::Compact));
    toolCallObj[QStringLiteral("function")] = funcObj;

    QJsonArray toolCallsArr{toolCallObj};
    assistantMsg[QStringLiteral("tool_calls")] = toolCallsArr;
    updatedMessages.append(assistantMsg);

    // 重复调用检测：同一个"工具名+参数"连续出现达到阈值，
    // 说明模型很可能陷入了死循环（本地小模型尤其容易出现这种情况）
    const QString fingerprint = callFingerprint(call);
    const int repeatCount = m_callFingerprints.value(fingerprint, 0) + 1;
    m_callFingerprints[fingerprint] = repeatCount;

    if (repeatCount >= kLoopDetectionThreshold) {
        TB_LOG_WARN(LogModule::AI,
            "Agent | loop detected: tool '{}' called {} times with identical arguments",
            call.name.toStdString(), repeatCount);
        setState(AgentState::Error);
        emit agentLoopDetected(call.name, repeatCount);
        return;
    }

    executeToolCall(call, updatedMessages, iterationCount);
}

void AIAgent::executeToolCall(const ToolCall& call,
                               const QJsonArray& messagesSoFar,
                               int iterationCount) {
    auto tool = m_toolRegistry ? m_toolRegistry->findTool(call.name) : nullptr;

    if (!tool) {
        // 模型"幻觉"出一个不存在的工具名——把这个错误当作工具结果反馈给模型，
        // 让它自己纠正，而不是直接终止整个 Agent（这是本地小模型的常见故障模式）
        ToolResult errResult{
            .success = false,
            .output  = QStringLiteral("错误：不存在名为 '%1' 的工具，请从可用工具列表中选择。")
                           .arg(call.name),
        };
        appendToolResultAndContinue(call, errResult, messagesSoFar, iterationCount);
        return;
    }

    if (tool->requiresConfirmation()) {
        setState(AgentState::WaitingConfirmation);
        m_pending = PendingConfirmation{call, messagesSoFar, iterationCount};

        const QString desc = QStringLiteral("%1 即将执行：%2")
            .arg(tool->definition().name)
            .arg(QString::fromUtf8(
                QJsonDocument(call.arguments).toJson(QJsonDocument::Compact)));

        emit toolRequiresConfirmation(call.name, desc, call.arguments);
        return;  // 暂停在这里，等待 confirmPendingTool()
    }

    setState(AgentState::ExecutingTool);
    emit agentExecutingTool(call.name, call.arguments);

    const ToolResult result = tool->execute(call.arguments);
    emit agentToolResult(call.name, result.success, result.output);

    appendToolResultAndContinue(call, result, messagesSoFar, iterationCount);
}

void AIAgent::confirmPendingTool(bool approved) {
    if (!m_pending) {
        TB_LOG_WARN(LogModule::AI, "Agent | confirmPendingTool() called with no pending tool");
        return;
    }

    PendingConfirmation pending = *m_pending;
    m_pending.reset();

    if (m_cancelled) {
        setState(AgentState::Cancelled);
        emit agentCancelled();
        return;
    }

    if (!approved) {
        ToolResult rejected{
            .success = false,
            .output  = QStringLiteral("用户拒绝执行此操作。请说明原因或改用其他方式完成任务。"),
        };
        appendToolResultAndContinue(pending.call, rejected,
                                     pending.messagesBeforeCall, pending.iterationCount);
        return;
    }

    auto tool = m_toolRegistry->findTool(pending.call.name);
    setState(AgentState::ExecutingTool);
    emit agentExecutingTool(pending.call.name, pending.call.arguments);

    const ToolResult result = tool->execute(pending.call.arguments);
    emit agentToolResult(pending.call.name, result.success, result.output);

    appendToolResultAndContinue(pending.call, result,
                                 pending.messagesBeforeCall, pending.iterationCount);
}

void AIAgent::appendToolResultAndContinue(const ToolCall& call,
                                           const ToolResult& result,
                                           const QJsonArray& messagesSoFar,
                                           int iterationCount) {
    QJsonArray updatedMessages = messagesSoFar;

    QJsonObject toolMsg;
    toolMsg[QStringLiteral("role")]         = QStringLiteral("tool");
    toolMsg[QStringLiteral("tool_call_id")] = call.id;
    // 单条工具结果的长度上限交给 ContextBudgetManager 统一控制（§12.6），
    // 避免 read_file 之类的工具一次性把小模型的上下文窗口挤爆
    toolMsg[QStringLiteral("content")] =
        ContextBudgetManager::instance().truncateToolOutput(result.output);
    updatedMessages.append(toolMsg);

    // 每次追加完工具结果都重新做一次预算裁剪
    updatedMessages = ContextBudgetManager::instance().enforceBudget(
        updatedMessages, m_service->contextWindowTokens());

    if (m_cancelled) {
        setState(AgentState::Cancelled);
        emit agentCancelled();
        return;
    }

    executeLlmCall(updatedMessages, iterationCount + 1);
}

void AIAgent::cancelRequest() {
    if (m_state == AgentState::Idle || m_state == AgentState::Done ||
        m_state == AgentState::Cancelled) {
        return;
    }

    m_cancelled = true;
    m_pending.reset();
    m_service->cancelRequest();  // 中断正在进行的网络请求（本地或云端一致）

    TB_LOG_INFO(LogModule::AI, "Agent | cancelled by user at state={}",
        static_cast<int>(m_state));

    // 状态切换和 agentCancelled 信号会在当前挂起的回调触发时统一 emit
    // （避免和尚未返回的异步回调产生竞态），若当前处于 WaitingConfirmation
    // 这种没有挂起网络请求的状态，则立即切换
    if (m_state == AgentState::WaitingConfirmation) {
        setState(AgentState::Cancelled);
        emit agentCancelled();
    }
}
```

**⚠️ 实战必读：为什么取消要"软取消"而不是直接销毁 Agent？**

工具执行（尤其是 `execute_command`）一旦开始就无法真正"打断"——`QProcess` 可以被
`kill()`，但已经写到磁盘的文件写不回去。`m_cancelled` 标志位的作用是：**在每一个安全的
检查点（即将发起下一次 LLM 调用之前）拦截住流程**，而不是试图去打断正在执行的工具本身。
这也是为什么 `cancelRequest()` 不会立即 `emit agentCancelled()`——真正的信号要等当前挂起的
回调（LLM 请求或工具执行）跑完、走到下一个检查点时才发出。

### 12.4 IAIService::chatComplete 完整实现

原文档定义了 `chatComplete()` 接口，但没有给出实现。这一节把它补全，并且刻意把**云端原生
function calling**、**本地 Ollama 原生 function calling**、**本地不支持工具调用的模型
（Prompt 注入兜底）**三种情况统一到同一个方法里，让 §12.3 的 Agent 循环不需要关心底层差异。

```cpp
// src/services/ai/IAIService.h — 扩展
class IAIService {
public:
    // ... 现有接口（sendMessageAsync / sendMessageSync / cancelRequest / isLoading）...

    /// 工具感知的异步调用（支持 function calling）
    ///
    /// @param messages 完整消息列表（system + user + assistant + tool，
    ///                 由调用方 [AIAgent] 直接构造好传入，Service 不再做二次转换）
    /// @param tools    可用的工具定义列表
    virtual void chatComplete(const QJsonArray& messages,
                               const std::vector<ToolDefinition>& tools,

    /// 云端模型通常固定（如 GPT-4o=128000），本地 Ollama 模型
    /// 通过 §12.5 的能力探测在运行时确定，探测失败时应返回一个保守默认值（如 4096）

/// 工具调用（模型请求执行的一次函数调用）
```

#### 12.4.1 ⚠️ 实战必读：不要复用 `convertMessages()`

§5.3 里的 `OpenAIService::convertMessages()` 是为**纯文本多轮对话**设计的：它只提取
`role == user/assistant` 的消息，把其余字段（包括 `tool_calls`、`tool_call_id`）全部丢弃。

如果 `chatComplete()` 偷懒复用了它，会出现一个非常隐蔽的 bug：**第一轮工具调用能成功，
但第二轮开始模型会"失忆"**——因为它上一步发起的 `tool_calls` 请求和你追加的 `tool` 结果消息，
在转发给 API 之前已经被 `convertMessages()` 悄悄吞掉了。这是工具调用场景下最容易踩、
也最难排查的坑（现象是"模型反复问同一个问题"，很容易被误判为是模型能力不够）。

正确做法是给 `chatComplete()` 写一个专用的请求体构造函数，**原样透传** `messages`：

```cpp
// src/services/ai/OpenAIService.cpp — 新增
QJsonObject OpenAIService::buildChatCompleteBody(
    const QJsonArray& messages,
    const std::vector<ToolDefinition>& tools) const {

    QJsonObject body;
    body[QStringLiteral("model")]       = m_config.model;
    body[QStringLiteral("messages")]    = messages;   // ⚠️ 原样透传，不经过 convertMessages()
    body[QStringLiteral("max_tokens")]  = m_config.maxTokens;
    body[QStringLiteral("temperature")] = m_config.temperature;
    body[QStringLiteral("stream")]      = false;

    if (!tools.empty() && m_config.toolCallingMode == ToolCallingMode::Native) {
        body[QStringLiteral("tools")] = buildToolsArray(tools);  // 见 §10.5
    }

    return body;
}

Result<ChatResponse> OpenAIService::parseChatResponse(const QByteArray& data) const {
    QJsonParseError parseErr;
    const auto doc = QJsonDocument::fromJson(data, &parseErr);
    if (parseErr.error != QJsonParseError::NoError) {
        return Result<ChatResponse>::err(
            TB_MAKE_ERROR(ErrorCode::NetworkError, "Invalid JSON response"));
    }

    const auto root = doc.object();
    if (root.contains(QStringLiteral("error"))) {
        const auto errObj = root[QStringLiteral("error")].toObject();
        return Result<ChatResponse>::err(TB_MAKE_ERROR(
            ErrorCode::NetworkError,
            errObj[QStringLiteral("message")].toString().toStdString()));
    }

    const auto choices = root[QStringLiteral("choices")].toArray();
    if (choices.isEmpty()) {
        return Result<ChatResponse>::err(
            TB_MAKE_ERROR(ErrorCode::NetworkError, "Empty choices"));
    }

    const auto choice     = choices[0].toObject();
    const auto messageObj = choice[QStringLiteral("message")].toObject();
    const QString finishReason = choice[QStringLiteral("finish_reason")].toString();

    ChatResponse response;
    response.finishReason = finishReason;
    response.content      = messageObj[QStringLiteral("content")].toString();
    response.toolCalls    = parseToolCalls(messageObj);  // 复用 §10.5 已有的解析函数

    return Result<ChatResponse>::ok(std::move(response));
}

void OpenAIService::chatComplete(const QJsonArray& messages,
                                  const std::vector<ToolDefinition>& tools,
                                  std::function<void(Result<ChatResponse>)> callback) {

    // 本地模型不支持原生 function calling 时，走 Prompt 注入适配器（§12.4.2），
    // 对外呈现的 chatComplete() 签名和行为完全一致
    if (!tools.empty() && m_config.toolCallingMode == ToolCallingMode::PromptInjection) {
        PromptInjectionToolAdapter::chatComplete(*this, messages, tools, std::move(callback));
        return;
    }

    if (m_activeReply) {
        m_activeReply->abort();
        m_activeReply->deleteLater();
        m_activeReply = nullptr;
    }
    m_loading = true;

    const QUrl url(m_config.baseUrl + QStringLiteral("/chat/completions"));
    QNetworkRequest request(url);
    request.setHeader(QNetworkRequest::ContentTypeHeader, QStringLiteral("application/json"));
    if (!m_config.apiKey.isEmpty()) {
        request.setRawHeader("Authorization", ("Bearer " + m_config.apiKey).toUtf8());
    }

    const QJsonObject body = buildChatCompleteBody(messages, tools);
    m_activeReply = m_network.post(
        request, QJsonDocument(body).toJson(QJsonDocument::Compact));

    QObject::connect(m_activeReply, &QNetworkReply::finished, this,
        [this, callback]() {
            if (!m_activeReply) return;
            m_activeReply->deleteLater();

            if (m_activeReply->error() == QNetworkReply::OperationCanceledError) {
                m_activeReply = nullptr;
                m_loading = false;
                callback(Result<ChatResponse>::err(
                    TB_MAKE_ERROR(ErrorCode::Cancelled, "Request cancelled")));
                return;
            }
            if (m_activeReply->error() != QNetworkReply::NoError) {
                const QString err = m_activeReply->errorString();
                m_activeReply = nullptr;
                m_loading = false;
                callback(Result<ChatResponse>::err(
                    TB_MAKE_ERROR(ErrorCode::NetworkError, err.toStdString())));
                return;
            }

            auto result = parseChatResponse(m_activeReply->readAll());
            m_activeReply = nullptr;
            m_loading = false;
            callback(std::move(result));
        });
}
```

#### 12.4.2 本地模型的 Prompt 注入适配器（健壮解析版）

§10.5 给出的正则 `TOOL_CALL:\s*\{([^}]+)\}` 只能匹配**不含嵌套大括号**的参数，
一旦工具参数本身是个对象或数组（比如 `write_file` 的 `content` 里恰好包含代码片段中的 `{}`），
正则就会在第一个 `}` 处提前截断，解析出损坏的 JSON。本地模型（尤其是量化后的小模型）
输出格式也不总是规整，需要一个更健壮的、支持括号配对的解析器：

```cpp
// src/services/ai/PromptInjectionToolAdapter.h
#pragma once
#include <QString>
#include <optional>
#include "services/ai/IAIService.h"

/// 为不支持原生 function calling 的本地模型，
/// 通过系统提示词注入工具描述 + 括号配对解析文本输出，
/// 模拟出与原生 chatComplete() 一致的行为。
class PromptInjectionToolAdapter {
public:
    static void chatComplete(class OpenAIService& service,
                              const QJsonArray& messages,
                              const std::vector<ToolDefinition>& tools,
                              std::function<void(Result<ChatResponse>)> callback);

    /// 在纯文本回复中查找 "TOOL_CALL:" 之后第一个配对完整的 {...} 块
    /// 使用括号计数而非正则，天然支持任意深度的嵌套 JSON
    [[nodiscard]] static std::optional<QString> extractBalancedToolCallJson(
        const QString& text);
};
```

```cpp
// src/services/ai/PromptInjectionToolAdapter.cpp
#include "services/ai/PromptInjectionToolAdapter.h"
#include "services/ai/OpenAIService.h"
#include <QJsonDocument>

std::optional<QString> PromptInjectionToolAdapter::extractBalancedToolCallJson(
    const QString& text) {

    const QString marker = QStringLiteral("TOOL_CALL:");
    const int markerPos = text.indexOf(marker);
    if (markerPos < 0) return std::nullopt;

    int i = markerPos + marker.length();
    // 跳过 "TOOL_CALL:" 后面的空白，定位到第一个 '{'
    while (i < text.length() && text[i].isSpace()) ++i;
    if (i >= text.length() || text[i] != QLatin1Char('{')) return std::nullopt;

    int depth = 0;
    bool inString = false;
    bool escaped  = false;
    const int start = i;

    for (; i < text.length(); ++i) {
        const QChar c = text[i];
        if (inString) {
            if (escaped)              escaped = false;
            else if (c == '\\')       escaped = true;
            else if (c == '"')        inString = false;
            continue;
        }
        if (c == '"')      { inString = true; continue; }
        if (c == '{')      { ++depth; continue; }
        if (c == '}') {
            --depth;
            if (depth == 0) return text.mid(start, i - start + 1);
        }
    }
    return std::nullopt;  // 括号未闭合——模型输出被截断（常见于 max_tokens 设置过小）
}

void PromptInjectionToolAdapter::chatComplete(
    OpenAIService& service,
    const QJsonArray& messages,
    const std::vector<ToolDefinition>& tools,
    std::function<void(Result<ChatResponse>)> callback) {

    // 1. 把工具描述追加进最后一条 system 消息（§10.5 已给出模板文本）
    QJsonArray promptMessages = injectToolDescriptions(messages, tools);

    // 2. 走普通的纯文本对话（不带 tools 参数），本地模型完全当作对话来处理
    service.sendRawChatAsync(promptMessages,
        [callback](Result<QString> textResult) {
            if (textResult.isErr()) {
                callback(Result<ChatResponse>::err(textResult.error()));
                return;
            }

            const QString text = textResult.value();
            ChatResponse response;

            const auto jsonBlock = extractBalancedToolCallJson(text);
            if (!jsonBlock) {
                // 没有工具调用标记 → 当作最终文本回复
                response.content      = text;
                response.finishReason = QStringLiteral("stop");
                callback(Result<ChatResponse>::ok(std::move(response)));
                return;
            }

            QJsonParseError parseErr;
            const auto doc = QJsonDocument::fromJson(jsonBlock->toUtf8(), &parseErr);
            if (parseErr.error != QJsonParseError::NoError || !doc.isObject()) {
                // 模型输出了畸形 JSON——把错误当作"工具调用失败"反馈给 Agent，
                // 而不是直接把整段原始文本当成回复展示给用户
                response.content      = QStringLiteral(
                    "（模型输出的工具调用格式有误，已忽略：%1）").arg(jsonBlock->left(200));
                response.finishReason = QStringLiteral("stop");
                callback(Result<ChatResponse>::ok(std::move(response)));
                return;
            }

            const auto obj = doc.object();
            ToolCall call;
            call.id        = QStringLiteral("local_%1")
                                  .arg(QDateTime::currentMSecsSinceEpoch());
            call.name      = obj[QStringLiteral("name")].toString();
            call.arguments = obj[QStringLiteral("arguments")].toObject();

            response.toolCalls.push_back(call);
            response.finishReason = QStringLiteral("tool_calls");
            callback(Result<ChatResponse>::ok(std::move(response)));
        });
}
```

> **提示**：`sendRawChatAsync()` 是 `OpenAIService` 内部新增的一个私有辅助方法，
> 逻辑与 §5.3 的 `sendMessageAsync()` 几乎一致，区别只是直接接收构造好的 `messages`
> 数组（不经过 `convertMessages()`），供 `chatComplete()` 内部两条路径复用。

### 12.5 本地模型工具调用能力探测（Ollama）

`ToolCallingMode`（Native / PromptInjection）不应该让用户手工配置——不同的 Ollama 模型
支持情况差异很大，写死配置会导致换个模型就得改代码。Ollama 的 `POST /api/show` 接口会在
返回结果里带一个 `capabilities` 字段，列出该模型支持的能力（如 `completion`、`tools`、
`vision`），可以据此在运行时自动探测：

```cpp
// src/services/ai/OllamaCapabilityProbe.h
#pragma once
#include <QObject>
#include <QNetworkAccessManager>
#include <functional>
#include "services/ai/OpenAIService.h"  // ToolCallingMode

/// 探测本地 Ollama 模型是否支持原生 function calling
class OllamaCapabilityProbe : public QObject {
    Q_OBJECT
public:
    explicit OllamaCapabilityProbe(QString ollamaHost, QObject* parent = nullptr);

    /// @param model 模型名，如 "llama3.1" / "qwen2.5"
    /// 探测失败（Ollama 未运行、模型不存在等）时保守地返回 PromptInjection，
    /// 保证 Agent 至少能以兜底模式工作，而不是直接报错
    void detect(const QString& model,
               std::function<void(ToolCallingMode, int contextWindow)> callback);

private:
    QString                m_ollamaHost;  // 默认 http://localhost:11434
    QNetworkAccessManager  m_network;
};
```

```cpp
// src/services/ai/OllamaCapabilityProbe.cpp
#include "services/ai/OllamaCapabilityProbe.h"
#include <QNetworkRequest>
#include <QJsonDocument>
#include <QJsonObject>
#include "core/log/Logger.h"
#include "core/log/LogModules.h"

OllamaCapabilityProbe::OllamaCapabilityProbe(QString ollamaHost, QObject* parent)
    : QObject(parent), m_ollamaHost(std::move(ollamaHost)) {}

void OllamaCapabilityProbe::detect(
    const QString& model,
    std::function<void(ToolCallingMode, int contextWindow)> callback) {

    QNetworkRequest request(QUrl(m_ollamaHost + QStringLiteral("/api/show")));
    request.setHeader(QNetworkRequest::ContentTypeHeader, QStringLiteral("application/json"));

    QJsonObject body{{QStringLiteral("model"), model}};
    auto* reply = m_network.post(request, QJsonDocument(body).toJson(QJsonDocument::Compact));

    QObject::connect(reply, &QNetworkReply::finished, this, [reply, callback, model]() {
        reply->deleteLater();

        // 保守默认值：Ollama 没运行 / 模型不存在 / 网络异常时一律退化为 Prompt 注入 +
        // 4096 token 的保守上下文预算，Agent 依然可以工作，只是效率略低
        ToolCallingMode mode  = ToolCallingMode::PromptInjection;
        int             ctxWindow = 4096;

        if (reply->error() == QNetworkReply::NoError) {
            const auto doc = QJsonDocument::fromJson(reply->readAll());
            const auto root = doc.object();

            const auto capabilities = root[QStringLiteral("capabilities")].toArray();
            for (const auto& c : capabilities) {
                if (c.toString() == QStringLiteral("tools")) {
                    mode = ToolCallingMode::Native;
                    break;
                }
            }

            // 上下文窗口的字段名随模型架构而异（如 "llama.context_length"、
            // "qwen2.context_length"），需要在 model_info 里按前缀模糊匹配，
            // 匹配不到时保留上面的保守默认值
            const auto modelInfo = root[QStringLiteral("model_info")].toObject();
            for (auto it = modelInfo.constBegin(); it != modelInfo.constEnd(); ++it) {
                if (it.key().endsWith(QStringLiteral(".context_length"))) {
                    ctxWindow = it.value().toInt(ctxWindow);
                    break;
                }
            }

            TB_LOG_INFO(LogModule::AI,
                "Ollama capability probe | model={} tools={} ctxWindow={}",
                model.toStdString(),
                mode == ToolCallingMode::Native, ctxWindow);
        } else {
            TB_LOG_WARN(LogModule::AI,
                "Ollama capability probe failed for '{}', falling back to prompt-injection mode",
                model.toStdString());
        }

        callback(mode, ctxWindow);
    });
}
```

### 12.6 Agent 上下文预算与会话记忆管理

原文档完全没有处理这个问题，但对**本地模型**而言这是决定 Agent 能不能跑完一个多步任务
的关键：云端 GPT-4o 有 128K 上下文，而本地跑的 8B/14B 量化模型常见上下文窗口只有
4K～32K。一次 `read_file` 就可能占掉大半个窗口，Agent 循环两三轮就会因为超出上下文
而报错或产生质量急剧下降的回复。

```cpp
// src/core/ai/ContextBudgetManager.h
#pragma once
#include <QJsonArray>
#include <QString>

/// 上下文预算管理：token 估算、工具输出截断、历史裁剪/摘要
///
/// C++/Qt 技术栈里没有现成的 tiktoken 绑定，用字符数做近似估算即可满足
/// "防止超限"这个目的——不需要精确计费场景下的字节级精确度。
class ContextBudgetManager {
public:
    static ContextBudgetManager& instance();

    /// 粗略估算一段文本的 token 数
    /// 经验系数：英文/代码约 4 字符≈1 token，中文约 1.5～2 字符≈1 token，
    /// 这里统一按混合文本的保守系数估算（宁可高估，不可低估，避免真正超限）
    [[nodiscard]] int estimateTokens(const QString& text) const;

    /// 单条工具输出的最大保留长度（字符数），超出则截断并标注
    /// 默认按 contextWindow 的 1/4 动态计算，避免一次工具调用吃满整个预算
    [[nodiscard]] QString truncateToolOutput(const QString& output,
                                             int contextWindowTokens = 4096) const;

    /// 确保 messages 总 token 数不超过 contextWindowTokens 的 80%
    /// （预留 20% 给模型的回复），超出时按以下顺序裁剪：
    ///   1. 丢弃最旧的 tool 消息（保留其配对的 assistant 消息，标注"[已省略]"）
    ///   2. 仍超出则将中间一段历史压缩为一条摘要消息（见下）
    ///   3. system 消息和最近 2 轮对话始终保留，不参与裁剪
    [[nodiscard]] QJsonArray enforceBudget(const QJsonArray& messages,
                                           int contextWindowTokens) const;

private:
    [[nodiscard]] QJsonArray summarizeMiddleHistory(const QJsonArray& messages) const;
};
```

```cpp
// src/core/ai/ContextBudgetManager.cpp（关键逻辑节选）
int ContextBudgetManager::estimateTokens(const QString& text) const {
    int asciiChars = 0, wideChars = 0;
    for (const QChar& c : text) {
        if (c.unicode() < 128) ++asciiChars; else ++wideChars;
    }
    // ASCII 部分按 4 字符/token，中文等宽字符按 1.7 字符/token，
    // 再加 15% 安全余量
    const double raw = asciiChars / 4.0 + wideChars / 1.7;
    return static_cast<int>(raw * 1.15) + 1;
}

QString ContextBudgetManager::truncateToolOutput(const QString& output,
                                                   int contextWindowTokens) const {
    const int budgetTokens = std::max(contextWindowTokens / 4, 256);
    const int budgetChars  = budgetTokens * 3;  // 保守换算

    if (output.length() <= budgetChars) return output;

    return output.left(budgetChars) +
        QStringLiteral("\n\n[...内容过长，已截断，共 %1 字符，仅显示前 %2 字符...]")
            .arg(output.length()).arg(budgetChars);
}

QJsonArray ContextBudgetManager::enforceBudget(const QJsonArray& messages,
                                                int contextWindowTokens) const {
    const int budget = static_cast<int>(contextWindowTokens * 0.8);

    int total = 0;
    for (const auto& m : messages) {
        total += estimateTokens(m.toObject()[QStringLiteral("content")].toString());
    }
    if (total <= budget) return messages;  // 未超预算，直接返回

    TB_LOG_INFO(LogModule::AI,
        "ContextBudget | estimated {} tokens > budget {}, compressing history",
        total, budget);

    // system 消息 + 最近 4 条消息始终保留；中间部分压缩为一条摘要
    // （摘要本身通过一次轻量 LLM 调用生成，见下方 summarizeMiddleHistory）
    return summarizeMiddleHistory(messages);
}
```

**关于摘要压缩的实现取舍：** `summarizeMiddleHistory()` 需要额外发起一次 LLM
调用来生成摘要文本，这本身也要消耗 token/算力，在本地模型上会带来明显的额外延迟。
更轻量的替代方案是**规则式压缩**（不调用 LLM，直接把中间的 `tool` 消息内容替换为
`"[工具 X 的结果，已省略，详见执行记录]"`，只保留 `assistant` 的文字性小结）。
实战中建议优先实现规则式压缩，只有在 Agent 单次任务的迭代次数经常超过 6～8 轮时，
才值得引入基于 LLM 的语义摘要。

### 12.7 Agent 会话持久化（SQLite）

Agent 的"思考轨迹"（工具调用、确认、结果）如果只存在内存里，应用一重启就全部丢失，
用户也没法在 UI 上回看"AI 上次到底做了什么"。复用 §11.3 已经引入的 SQLite，新增一张
`agent_trace` 表即可，不需要额外依赖：

```sql
CREATE TABLE IF NOT EXISTS agent_trace (
    id           INTEGER PRIMARY KEY AUTOINCREMENT,
    session_id   TEXT    NOT NULL,       -- 关联到某次对话
    iteration    INTEGER NOT NULL,       -- Agent 循环的第几轮
    entry_type   TEXT    NOT NULL,       -- thinking | tool_call | tool_result | confirmation | final
    tool_id      TEXT,                   -- entry_type 为 tool_call/tool_result 时有值
    payload      TEXT    NOT NULL,       -- JSON 序列化的内容
    created_at   INTEGER NOT NULL        -- Unix 时间戳
);
CREATE INDEX IF NOT EXISTS idx_agent_trace_session ON agent_trace(session_id);
```

### 12.9 沙箱与安全考虑

工具系统赋予 AI 强大的能力，也带来了安全风险。必须实施以下安全措施：

```
⚠️ 工具安全分级

绿色（自动执行）：
  - read_file、search_files、list_directory、file_info
  - read_clipboard、parse_json
  → AI 可自主调用，无需用户确认

黄色（用户确认）：
  - write_file、execute_command
  - http_request、registry_read
  → 调用前弹出确认对话框，显示工具名和参数

红色（全局禁用）：
  - 删除文件、格式化磁盘、修改系统配置
  → 不在可用工具列表中，AI 不可调用
```

**敏感操作的保护机制：**

```cpp
// WriteFileTool 写入路径白名单检查
ToolResult WriteFileTool::execute(const QJsonObject& args) {
    const QString filePath = args[QStringLiteral("filePath")].toString();

    // 只允许写入用户文档目录下的文件
    const QString allowedDir = QStandardPaths::writableLocation(
        QStandardPaths::DocumentsLocation);
    if (!filePath.startsWith(allowedDir)) {
        return ToolResult{
            .success = false,
            .output  = QStringLiteral("错误：只允许写入 %1 目录下的文件。").arg(allowedDir),
        };
    }

    // ... 写入文件 ...
}

// ExecuteCommandTool 命令白名单
ToolResult ExecuteCommandTool::execute(const QJsonObject& args) {
    const QString command = args[QStringLiteral("command")].toString().trimmed();

    static const QStringList ALLOWED_PREFIXES = {
        QStringLiteral("ls"), QStringLiteral("cat"), QStringLiteral("pwd"),
        QStringLiteral("head"), QStringLiteral("tail"), QStringLiteral("wc"),
        QStringLiteral("echo"), QStringLiteral("find"), QStringLiteral("grep"),
        QStringLiteral("which"), QStringLiteral("dir"), QStringLiteral("type"),
        QStringLiteral("git status"), QStringLiteral("git log"),
    };

    bool allowed = false;
    for (const auto& prefix : ALLOWED_PREFIXES) {
        if (command.startsWith(prefix)) { allowed = true; break; }
    }

    if (!allowed) {
        return ToolResult{
            .success = false,
            .output = QStringLiteral("错误：命令 '%1' 不在允许的白名单中。").arg(command),
        };
    }

    // 执行命令用 QProcess，并设置超时 + 输出体积上限：
    // - setTimeout(30s)：本地命令一般应该秒回，超时大概率是命令本身有问题
    // - 输出截断到 §12.6 的 truncateToolOutput 预算内，防止一条 `find /` 
    //   直接把上下文窗口打满
}
```

> **本地优先架构下的额外收益，也有额外义务**：当整条链路（推理走 Ollama、检索走
> §11.3 的本地 FTS5、工具全部操作本机文件系统）都在本地闭环时，用户数据确实不会
> 离开这台机器，这是"本地智能 Agent"相对纯云端方案最大的隐私优势。但**这不等于
> 可以放松工具白名单/确认机制**——文件系统被误删、命令被误执行的风险和模型跑在
> 哪里毫无关系，安全分级必须对云端和本地模型一视同仁。

### 12.11 Agent 单元测试策略

Agent 循环涉及多轮异步回调、确认弹窗、取消、死循环检测，纯手工测试很难覆盖全部分支。
关键是要有一个**可脚本化的假 LLM**，能够按预设脚本依次返回"工具调用"或"最终回复"，
这样才能用 `QSignalSpy` 对 Agent 的每一种分支做确定性断言：

```cpp
// tests/unit/MockScriptedAIService.h
#pragma once
#include "services/ai/IAIService.h"
#include <QQueue>

/// 按预设脚本依次返回 ChatResponse 的假 Service，专供 AIAgent 单元测试使用
class MockScriptedAIService final : public QObject, public IAIService {
    Q_OBJECT
public:
    void enqueueResponse(ChatResponse response) { m_script.enqueue(std::move(response)); }

    void chatComplete(const QJsonArray&, const std::vector<ToolDefinition>&,
                       std::function<void(Result<ChatResponse>)> callback) override {
        if (m_script.isEmpty()) {
            callback(Result<ChatResponse>::err(
                TB_MAKE_ERROR(ErrorCode::InvalidArgument, "script exhausted")));
            return;
        }
        // 用 QTimer::singleShot(0, ...) 模拟异步，同时保持测试的确定性执行顺序
        auto response = m_script.dequeue();
        QTimer::singleShot(0, this, [callback, response]() {
            callback(Result<ChatResponse>::ok(response));
        });
```
