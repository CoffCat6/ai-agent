# 40 - S5+ 技能可用性收口方案

> **已废弃（2026-11-05）**：技能不承担工具权限，S1 门控与工具候选已回滚，见 `docs/41-Skill工具限制回滚方案.md`。



> 目标：让 `allowed-tools` 可被正确填写、保存错误可被程序区分、Windows 非法 id 被拒绝、未知 `$skill` 不再静默失败。
> 基线：HEAD `9944152`，全量 59/59 + panel 1/1。
> 范围：SkillEditorService / AgentViewModel / SkillEditorDialog / InputConsole；不改 AIAgent 白名单语义。

## 1. 现状与缺口

| 项 | 事实 | 影响 |
|---|---|---|
| `allowed-tools` 是自由文本 | `SkillEditorDialog.qml:337-344` 单个 TextField | 拼错工具名 → S1 白名单漏项 → 模型失去能力 |
| 保存错误是中文文案 | `SkillEditorService.cpp:436-440` “技能已存在” | 覆盖确认靠文案匹配，多语言/改文案会失效 |
| id 校验允许尾点 | `validateId` 正则 `...{0,63}$` | Windows 会归一为同名目录（`review.` → `review`） |
| 未拒绝 Windows 保留名 | 无 CON/PRN/NUL/COM1… 检查 | 创建目录可能失败或产生别名 |
| 保存可能穿过 symlink | `QSaveFile` 写 `SKILL.md` 链接路径 | 可能覆盖链接目标（另一个技能） |
| 未知 `$skill` 静默 | `resolveSkills` 静默跳过未知项 | 用户以为技能生效，实际未注入 |

## 2. 方案

### 2.1 结构化错误码

`SkillEditorService::save/remove/load` 增加可选 `QString* code`（C++ 默认 `nullptr`，不破坏既有调用），并设置：

| 场景 | code |
|---|---|
| 成功 | `ok` |
| id 非法 | `invalid_id` |
| 正文/文件名超限 | `too_large` / `invalid_body` |
| 元数据非法 | `invalid_metadata` |
| 工具名含非法字符 | `invalid_tools` |
| 根目录不可用 | `root_unavailable` / `invalid_root` |
| 目标已存在且未覆盖 | `exists` |
| 目标为空/非普通文件 | `not_file` |
| symlink/junction 越界或文件链接 | `symlink` / `outside_root` |
| 创建/备份/写入/提交失败 | `io_error` |
| 删除目标不存在 | `not_found` |

VM `saveSkill/removeSkillById` 返回 `code`；`SkillEditorDialog` 用 `code === "exists"` 判断覆盖确认，不再匹配中文文案。

### 2.2 Windows id 校验

在 `validateId` 增加：
- 拒绝以 `.` 或空格结尾（`review.`、`review `）；
- 拒绝 Windows 保留设备名（大小写不敏感，取第一个 `.` 前）：`CON/PRN/AUX/NUL/COM1..COM9/LPT1..LPT9`；
- 保留现有 1-64 字符、字母数字开头、`.` `_` `-`、拒绝 `..` 段。

### 2.3 保存时的链接防护

`save` 若 `SKILL.md` 是 symlink（即使 canonical 目标在根内），返回 `code="symlink"`，不写；与 `remove` 的既有拒绝一致，避免覆盖另一个技能。

### 2.4 工具名候选与未知工具二次确认

`SkillEditorDialog`：
- 从 `AgentVM.toolRegistryModel` 生成候选：`enabled && !blockedByPolicy && level !== "dangerous"`；`ComboBox`（objectName `skillToolPicker`）选中即追加到 `skillToolsField`（去重，逗号分隔）。
- 全量名称（含 disabled/dangerous）用于“未知”判定；`parseTools` 后按 `(` 前名称、大小写不敏感比较。
- 有未知工具时第一次保存只显示警告（`skillUnknownToolsHint`），不写盘；用户再次点击保存才写入（`unknownToolsConfirmed`），避免拼写错误静默生效，同时允许为暂时离线的 MCP 预留工具名。
- 工具目录为空（如初始化未完成）时跳过未知校验，避免误报。

### 2.5 未知 `$skill` 提示

- `AgentViewModel::unknownSkillTokens(text)`：复用 `$name` token 提取；返回无法按 id/显示名解析的 token（不占用 maxPerMessage 名额，不做“超出上限”判定）。
- `InputConsole`：`updateSkillChips()` 同时更新 `unknownSkillTokens`；输入框上方显示 `skillUnknownHint`：“未找到技能：$a, $b。请检查名称，或在 设置 → 技能 中刷新。”
- 只提示不阻止发送（正文中的 `$HOME` 等可能是有意文本）；解析成功的 skill 仍正常注入。

### 补修：目录级 symlink/junction（2026-11-05）

- 终验发现根内目录级链接（如 `alias -> victim`）的 canonical 目标仍在技能根内，save/remove 会顺着链接覆盖/删除被指向技能，绕过“仅拒绝 SKILL.md 文件链接”的防护。
- 修复：canonicalDir 通过根内检查后，再与「根路径 + id」的词法期望路径比较（Windows 大小写不敏感），不一致即视为经过链接/重解析点，`code="symlink"`，不写入/不删除。
- 回归：新增 `saveAndRemoveRejectDirectoryLinkInsideRoot`（目录 junction；save 不覆盖 victim、remove 不删除 victim 文件/目录）；`test_skills_editor` 24 用例。
- 复核：全量 59/59（126.88s，`-j2`）+ panel 1/1（18.55s）；qmllint Error 0；工作区干净。
- 仍遗留 P3：`load` 对根内 SKILL.md symlink 会读取目标（save/remove 拒绝，读语义未统一）；code 全表测试缺口（invalid_root/root_unavailable/not_file/outside_root/io_error 无新增断言）；“发送不被阻断/发送后清理”仅代码可证；工具候选测试走 appendTool 测试缝；新建向导不能直接创建 `allowed-tools: []`。
