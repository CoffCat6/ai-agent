## 1. 背景与现状

应用现有两套相互独立的"日志"设施,定位不同:

### 1.1 运行日志(Logger)——本计划的对象

`Logger`(src/core/utils/Logger.h)在启动时安装 Qt 消息处理器(`install()`,Logger.cpp:115-127),把全部 `qDebug/qInfo/qWarning/qCritical` 镜像到按天轮转的日志文件 `<AppLocalData>/logs/nexus-YYYYMMDD.log`(Logger.h:7-12),保留最近 7 天(Logger.cpp:47-52),并同步镜像到 stderr(Logger.cpp:91-93)。

关键现状细节:

- **线程安全已就位**:处理器全程持有全局互斥锁 `g_mutex`(Logger.cpp:19、`:58`),日志可来自任意线程(QtConcurrent 工具线程、嵌入批量、网络回调)。
- **级别过滤已就位**:`g_minLevel` 默认 `QtInfoMsg`(Logger.cpp:22),`setMinLevel` 可运行中调整(Logger.cpp:110-113);`install()` 启动时读取 QSettings 键 `logging/level`(debug|info|warning|critical)与环境变量 `NEXUSAI_LOG_LEVEL`(优先级更高,Logger.cpp:116-124)。
- **信息已结构化**:每行含时间戳、级别、可选分类(`context.category`,Logger.cpp:63-64);Warning/Critical 附带源文件与行号(Logger.cpp:66-67)。
- **痛点**:窗口化构建没有控制台,这些诊断信息**只能手工打开日志文件查看**;没有级别过滤视图,没有实时性,问题排查体验差。

### 1.2 工具审计(audit_log)——边界之外,不要混淆

SQLite `audit_log` 表(SqliteMemory.cpp:143)记录**工具活动**(tool_execute/tool_approved/tool_declined/tool_blocked/unknown_tool,IMemory.h:40-52),已有应用内查看入口:侧边栏底部"审计日志"按钮(Sidebar.qml:337-342)与快捷键 `Ctrl+L`(main.qml:282-285)。

**本计划做的是"运行日志可视化",不是审计功能重构**——两者数据源、受众、保留策略都不同;只在新入口的文案与定位上做区分("日志"=应用诊断,"审计日志"=工具活动)。

## 2. 目标与非目标

**目标**:

1. 应用内**实时**查看运行日志(无需开文件);
2. 按级别(Debug/Info/Warning/Critical)与关键词过滤;
3. 入口按钮位于**界面左下方**(方案见 §3.3);
4. 日志最低级别可在设置中调整,**即时生效**(打通既有 `logging/level` 键);
5. 从日志面板一键打开日志文件目录(定位到当天的文件);
6. 新界面文案全部走 i18n 通道。

**非目标**:

- 不改造日志文件格式、不引入外部日志库(spdlog 等);
- 不做日志的数据库持久化(维持"文件 7 天轮转 + 进程内环形缓冲"两层);
- 不重构 AuditDialog/审计表;
- 不做跨进程/多实例日志聚合。

## 3. 方案设计

### 3.1 数据源:Logger 内环形缓冲(主推)

在 `messageHandler`(Logger.cpp:54-97)格式化出一行后,除写文件与 stderr 外,同时追加进进程内**环形缓冲**:

- `struct LogEntry { quint64 seq; qint64 timestamp; int level; QString category; QString message; }`,`seq` 为进程级单调递增号;
- 容量定值(建议 **1000 条**,内存上限约 200 KB),满则淘汰最旧;
- 复用既有 `g_mutex`(Logger.cpp:19)保护,不新增锁;
- 对外暴露线程安全快照接口:`Logger::revision()`(当前最大 seq)与 `Logger::entriesSince(quint64 seq)`(增量拉取);
- Fatal 级别在 `abort()`(Logger.cpp:95-96)之前已入缓冲,尽力而为即可,不承诺落盘。

**为什么不做"读取日志文件"方案**:文件尾读要处理日切轮转(Logger.cpp:69-83)、prune 删档、编码与半行缓冲,实时性和简单性都差;环形缓冲与文件互不干扰,格式化只做一次。

**为什么用"拉取"而不是"信号推送"**:Logger 是 nexus_core 的纯工具类(非 QObject,`Sandbox() = delete` 式的静态门面,Logger.h:13-28),handler 又可能来自任意线程;推送需要把 Logger QObject 化再做 QueuedConnection。改为 viewmodels 侧 **QTimer 100ms 节流拉取增量**(按 revision 对账),与既有节流惯例一致(kStreamFlushMs,AIAgent.cpp:21;节流逻辑 :658-676),10 Hz 的快照拷贝成本可忽略。若后续确需推送,再引入 QObject 化的 LogBroadcaster(备选,不在首期)。

### 3.2 数据模型:LogModel(新增,viewmodels 层)

`src/viewmodels/LogModel.h/.cpp`:继承 `QAbstractListModel`(模式参照 TraceModel,TraceModel.h:17-50),角色:`TimestampRole / LevelRole / CategoryRole / MessageRole / SeqRole`。

- 内部持有一个 QTimer(100ms)按 revision 拉增量;有新行才 `beginInsertRows/endInsertRows`,淘汰最旧时发 `dataChanged`/`reset`(结构变化走 modelReset,同 TraceModel.h:39-46 的语义);
- 过滤在模型内实现:`filterLevel`(高于该级别的行隐藏)与 `filterText`(大小写不敏感子串)两个可写属性;变更时重查询并 reset——日志行数有上限(≤1000),全量刷新成本可接受,不需要 SortFilterProxy 类的精细增量;
- 面板打开时才启动拉取定时器,关闭即停(零空闲开销)。

### 3.3 界面与入口:左下方按钮(主推侧边栏底部,备选悬浮把手)

**面板**:新增 `src/ui/components/LogPanel.qml`,复用既有对话框体系(注册方式同四个全局对话框,main.qml:213-234;底座组件 DialogBackground/IconButton/Theme 单例取色)。布局自上而下:过滤栏(级别下拉 + 关键词输入)→ 日志 ListView(等宽字体;`pinnedToBottom` 自动滚动模式,参照 AgentChatPage.qml:40-46,向上滚动即暂停、右下角"回到底部")→ 工具行(复制可见行、打开日志目录[`Logger::logDir()`,Logger.cpp:101-103]、清除视图)。

**入口(用户要求的"界面左下方")**:

- **主推:侧边栏底部按钮行**。现有按钮行(RowLayout,Sidebar.qml:330-350)自左向右依次是"审计日志"(shield 图标,:337-342)与"设置"(:345-350),位于侧边栏左下区域——在此行**最左侧**新增一个"日志"IconButton(建议图标 `list`/`terminal`,沿 AppIcon 体系),配 `signal logsRequested()`(与既有 `settingsRequested()/auditRequested()` 同模式,Sidebar.qml:14-15),main.qml 中接新对话框。优点:与现有信息入口聚合、零新增布局层次、天然处于"左下方"。
- **备选:主窗口左下角悬浮把手**。若"左下方"指脱离侧边栏的独立入口,可复用侧边栏把手的悬浮模式(main.qml:116-161 的 `sidebarHandle`:半悬浮胶囊 + hover 效果 + ToolTip),固定停靠窗口左下角。缺点:多一个常驻悬浮元素,遮挡内容;建议仅在侧边栏被折叠时作为补充入口考虑。

两者不互斥:首期实现主推方案,备选留作折叠态增强(见 §5 M4,可选)。

### 3.4 过滤与检索

- **级别过滤**:四档下拉(Debug/Info/Warning/Critical),语义为"显示该级别及以上";实现为 LogModel.filterLevel;
- **关键词过滤**:单行输入,大小写不敏感子串匹配 message+category,防抖 200ms 输入生效;
- **默认视图**:Info 及以上(与运行日志默认级别一致,Logger.cpp:22);
- 可选增强(不做承诺):Warning/Critical 的未读计数徽章显示在入口按钮上。

### 3.5 设置联动:打通 `logging/level`

现状:`logging/level` 键**已存在**但只在 `install()` 启动时读取一次(Logger.cpp:116-124),运行中改注册表不生效。方案:

1. `SettingsService` 新增 `logLevel` 属性(QString,默认 "info"),**复用同一 QSettings 键** `logging/level`(属性读写模式照抄 `allowFullDiskRead`:SettingsService.h:32、`:54-57`,SettingsService.cpp:437-442);
2. `setLogLevel` 内调用 `Logger::setMinLevel`(Logger.cpp:110-113)实现即时生效;启动时 `install()` 的读取逻辑保持不变,`NEXUSAI_LOG_LEVEL` 环境变量优先级高于设置(维持 Logger.cpp:121-123 语义,需在设置界面注明);
3. 设置对话框(SettingsDialog)加一行"日志级别"下拉,并在日志面板顶部提供同样的快捷下拉(两处绑定同一属性)。

### 3.6 国际化(FEAT-804 通道)

所有新增用户可见字符串包 `qsTr()`,经 `qt_add_translations` 汇入 `translations/nexus_ai_zh_CN.ts`(CMakeLists.txt:159-167),实现时跑一次 `lupdate`。预计新增词条(中/英):日志/Logs、日志级别/Log level、调试/Debug、信息/Info、警告/Warning、严重/Critical、关键词过滤/Filter keywords、暂停滚动/Scroll paused、回到底部/Jump to bottom、复制可见日志/Copy visible lines、打开日志目录/Open log folder、清除视图/Clear view。

### 3.7 性能护栏

| 项 | 值/策略 | 依据 |
|---|---|---|

## 6. 测试计划

新建 `tests/test_logger.cpp`(以 `nexus_add_test` 注册,tests/CMakeLists.txt:6-10 的既有模式):

1. **环形淘汰**:写入 容量+200 条,`entriesSince(0)` 恰返回容量条且 seq 连续、最旧被淘汰;
2. **级别过滤**:设 `setMinLevel(Warning)` 后写入 debug/info,缓冲中不出现;
3. **增量拉取**:两次 `entriesSince(seq)` 拼接 = 全量快照(无重无漏);
4. **多线程写入 smoke**:4 线程各写 500 条,总数与 seq 唯一性校验(复用 g_mutex 的回归保护);
5. **快照一致性**:拉取期间并发写入不崩溃、返回条目均为完整行。

另在 `test_settings.cpp` 增补 `logLevel` 用例:默认值、持久化往返、变更信号(沿用该套件既有的 QSettings 现场守卫模式)。

## 7. 风险与开放问题

| 风险/问题 | 缓解/说明 |
|---|---|
| 日志来自任意线程(工具 worker、嵌入批量、网络回调) | 入缓冲复用 `g_mutex`(Logger.cpp:19、:58);UI 只经 LogModel 在 GUI 线程消费,无跨线程信号 |
| Fatal 后进程即退出(Logger.cpp:95-96),面板看不到临终日志 | 接受:文件日志仍是最终手段;可选在 Critical 面板行内高亮,临终前尽力可见 |
| 大量 DEBUG 日志拖慢 UI | 级别过滤在入缓冲前生效;环形淘汰有界;100ms 节流 |
| 与"审计日志"入口混淆 | 文案区分("日志"=应用诊断,"审计日志"=工具活动);两对话框互不引用 |
| 内存占用 | 1000 条 × 平均 ~200 B ≈ 200 KB,常量上限 |
| 开放问题:是否需要 qLoggingCategory 分类过滤 | 首期不做;category 已随行记录(Logger.cpp:63-64),后续加一列过滤即可 |
| 开放问题:未读 WARN/CRIT 徽章 | 列为 M4 可选项 |
