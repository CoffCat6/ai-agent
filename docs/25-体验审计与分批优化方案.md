## 2. 批次 A：P0 正确性（5 项，均为小改动大收益）

### A1 [高] MCP 工具一次取消后被永久「毒化」

- **位置**：`src/core/mcp/McpToolAdapter.cpp:63-142`（`execute()` 入口未重置）、`:144-146`（`cancel()` 置位）
- **根因**：`cancel()` 把 `m_cancelled` 原子标志置 `true` 后永不复位；`execute()` 开头不像 `ShellExecTool.cpp:463`、`NetworkFetchTool.h:79`（Batch 21 B3 修复）那样 `store(false)`。同一适配器在第一次取消后，后续所有调用都会在 `invokeMethod` lambda 里（第 90 行）立即触发 `cancelRequest(id)`，秒返回 `"cancelled"`，直到重连才恢复。
- **修复**：`execute()` 入口加 `m_cancelled.store(false);`，与另两个工具一致；在 `tests/test_mcp.cpp` 补「取消后再次执行可正常完成」的回归用例。
- **验收**：新用例通过；既有 `test_mcp` 全绿。

### A2 [高] embedding 被 parent 到 app，退出期 use-after-free

- **位置**：`src/main.cpp:288`（`auto* embedding = new OllamaEmbedding(&app);`）对照 `:289-295` 注释
- **根因**：注释明言该对象应「process-lifetime and NEVER deleted …… parenting it to the app would destroy the object under them (use-after-free at exit)」，但实参就是 `&app`。`rag`（`new RagService(nullptr)`，永不删除）的 embedder/batchEmbedder 闭包捕获 raw `embedding` 指针；三个 discard-future 的 `QtConcurrent::run` worker（`startKnowledgeRestore` main.cpp:178、re-embed-all :719、AgentViewModel 导入）经 `rag` 间接调用 `embedding->embed()/embedBatch()`。app 析构删除 embedding 后 worker 若仍在跑即 UAF。
- **修复**：改为 `new OllamaEmbedding(nullptr)`，与 rag/memory 同纪律；同步修正注释主语（明确 rag 与 embedding 同为 process-lifetime）。
- **验收**：全量 ctest 回归无新增失败；代码走查确认退出链路无其它 parent 引用。

### A3 [中] LLM 流式中断后的「透明重试」未排除已流式输出的请求

- **位置**：`src/infrastructure/llm/LLMServiceBase.cpp:137-150`
- **根因**：137-139 行注释声明「anything that streamed output are not retried」，但 142-143 行重试条件只判 `attempt == 0 && !cancelled && (transient error/5xx/429)`。请求已流式吐字后遭遇 RemoteHostClosed 等瞬态错误时，`resetStreamState()` 清空累积内容并整条重发 → UI 内容闪回/重复流式，且多浪费一次请求。
- **修复**：重试条件追加 `ctx->content.isEmpty() && ctx->reasoning.isEmpty()`（仅对尚未产出任何文本的请求重试）。
- **验收**：`test_provider_lifecycle`/`test_llm_parsers` 回归；人工冒烟一次流式中断场景不再闪回（可选）。

### A4 [中] 托盘「退出」只停 active tab，与注释「先停全部 busy tab」不符

- **位置**：`src/main.cpp:846/850`（`agentVM->stop(); QCoreApplication::quit();`）与 `src/viewmodels/AgentViewModel.cpp:1654-1656`（`stop() { active()->stop(); }`）
- **根因**：`AgentViewModel::stop()` 只停 active tab；其余 busy tab 依赖「app 析构 → agentVM → controller 析构 → `~ChatSessionController` 里 `m_agent->stop()`」被动兜底，隐式依赖 QObject 析构顺序。
- **修复**：`AgentViewModel` 新增 `stopAllTabs()`（遍历全部 controller 逐个 stop），托盘退出路径改调 `stopAllTabs()`。
- **验收**：`test_viewmodel` 回归；多标签 busy 状态下托盘退出无崩溃。

### A5 [中] `projects/activeId` 读/写两端分家 + 内存镜像陈旧

- **位置**：`src/viewmodels/SettingsService.cpp:1049-1054`（`setActiveProjectId` 无任何调用者）对照 `src/viewmodels/AgentViewModel.cpp:629-644`（直写 `persistSettingsValue("projects/activeId")`）与 `src/ui/components/Sidebar.qml:74`（读 `Settings.activeProjectId`）
- **根因**：运行时真值由 AgentViewModel 直写 QSettings，SettingsService 的 `m_activeProjectId` 内存镜像在 `load()` 之后不再同步，Sidebar 恢复「上次浏览位置」读到陈旧值。
- **修复**：确立唯一属主——AgentViewModel 写路径改走 `SettingsService::setActiveProjectId`（保持内存/QSettings 一致，最小改动）。
- **验收**：切换项目后重启应用，Sidebar 恢复到正确的上次浏览位置；`test_settings` 回归。

## 3. 批次 B：P1 性能与数据层（6 项主修复 + 2 项顺带）

### B1 [中] `episodic` 表缺 `session_id`/`timestamp` 索引

- **位置**：`src/core/memory/SqliteMemory.cpp:284-293`（createTables 无索引）；受影响查询 `listEpisodic`(:1384)、`clear`(:1507)、`hardDeleteSessionRows`(:1713)、`searchEpisodicSemantic`(:1316)
- **修复**：补 `CREATE INDEX IF NOT EXISTS idx_episodic_ts ON episodic(timestamp)` 与 `idx_episodic_session ON episodic(session_id)`（仿照 messages 索引策略，`IF NOT EXISTS` 保证旧库平滑升级）。

### B2 [中] `searchEpisodicSemantic` 全表扫描 + LIMIT 500 硬上限

- **位置**：`src/core/memory/SqliteMemory.cpp:1316-1317`
- **根因**：`WHERE length(embedding) > 0 ORDER BY timestamp DESC LIMIT 500`——逐行函数无法走索引；500 是静默截断，更早的 episode 永远检索不到，与「长期记忆」定位矛盾。另：语义结果丢弃余弦分数，`retrieveRaw`（EpisodicService.cpp:202-211）FTS 结果在前、语义结果追加在后，注入排序非相关性；`<3` 字符关键词的 LIKE 回退（:1278-1292）无行数护栏。
- **修复**（保守组合）：① 依赖 B1 索引消除排序全扫；② `LIMIT 500` 提为具名常量并在结果满额时 `qCWarning` 提示（暂不移除上限，避免无界内存余弦）；③ 语义结果带出 score，与 FTS 结果按统一分数合并后再取 topK；④ LIKE 回退仿照 `searchMessages` 的 `kLikeScanMaxMessages` 加行数护栏。

### B3 [中] 情景记忆语义检索在 GUI 线程同步执行

- **位置**：`src/core/agent/EpisodicService.cpp:191-214`（`retrieveRaw`、:197-198 `m_embedder(query)`），调用源头 `src/core/agent/AIAgent.cpp:475`
- **根因**：`startTask`（GUI 线程）→ `retrieveRelevantSummaries` → `retrieveRaw`，同步执行网络 embed（Ollama 往返）+ DB 扫描 + 最多 500 条 BLOB 内存余弦。开启 episodic 后每次新会话开始都卡 UI，与 RAG 侧「embedding 网络 IO 移出 GUI 线程」的既定设计相悖。
- **修复**：把 embedding 与语义检索下发 QtConcurrent 工作线程，结果以信号回灌（与 `EpisodicService` summary 生成已有的异步模式统一）；`AIAgent::startTask` 处改为异步注入或超时兜底（如 200ms 内未返回则本轮跳过注入，避免拖慢首响）。
- **验收**：`test_episodic` 回归 + 新增异步路径用例；开启 episodic 后新会话首条消息期间 UI 不卡顿。

### B4 [中] `purgeDeletedSessions` 逐会话硬删、无事务（顺带 `clear()` 三连删除）

- **位置**：`src/core/memory/SqliteMemory.cpp:1694-1698`（循环）+ `:1702-1725`（4 条 DELETE）；顺带 `:1500-1518`（`clear` 三条 DELETE）
- **修复**：整轮 purge 包进一个 `m_db.transaction()`，失败 rollback；`clear()` 同样包事务（对比 `truncateLastTurn` 已有事务）。

### B5 [中] `RagService::finishSearch` 持锁执行全量余弦

- **位置**：`src/core/rag/RagService.cpp:356-379`（361-369 在 `QMutexLocker` 内）
- **根因**：持锁期间对所有文档 `retriever->search()`（每 chunk 余弦 + `std::sort`），复杂度 O(总 chunk × 维度) 且随 `MaxTotalChunks`(4096) 线性增长；同期 `documents()`/`documentChunks()`/`isEmpty()` 等 GUI 读会阻塞在纯 CPU 计算上。
- **修复**：持锁只做 `m_docs` 只读快照（`std::shared_ptr` 拷贝或指针向量），解锁后再计算相似度。

### B6 [中] `VectorStore::search` 全量排序无剪枝

- **位置**：`src/core/rag/VectorStore.h:25-50`
- **修复**：`std::sort` 改 `std::partial_sort`（只维护 top-k），避免全量 O(n log n)；余弦本身受 4096 chunk 上限兜底，暂不引入 ANN 索引（记录为后续可选项）。

### B7 [低，顺带] PDF 导入路径双重切块且先于体积门限

- **位置**：`src/core/rag/RagService.cpp:171-175`（先 `chunkDocument`）vs `:100-105`（`buildRetriever` 门限在后）
- **修复**：先做 `MaxChunksPerDocument`/体积预检再切块，并复用 chunk 结果到 `addDocument`，消除第二次切块。

## 7. 统一验证与回归策略

```powershell
# 增量构建（先加编译器/构建工具入 PATH，Qt 6.9.0 MinGW 位于 D:/Qt/6.9.0/mingw_64）
cmake --build build
# 回归（分批策略：先核心三件套，再全量）
ctest --test-dir build --output-on-failure -R "qmllint_gate|test_mcp|test_settings"
```

## 9. 批次六遗留技术债（Token/成本统计面板可视化）

批次六（T1 数据层范围/分页接口 + T2 图表组件 + T3 页面集成）双路审查（builtin-rules + security，0 Blocker / 2 Major / 4 Minor + 安全 1 Minor）中 Major/Minor 已随批次修复收口，以下 Suggestion 级遗留与已知边界登记于此，均不阻塞提交；行号以批次六交付快照为准。

- **[Suggestion] s1 Canvas 重绘对非色板 Theme 色的间接依赖**：DonutChart / LineTrendChart / BarCompareChart 的 Canvas 重绘监听 paletteColors（色板色）等变化，但 onPaint 内还直接引用 borderSubtle（网格线）/ textSecondary（刻度文字）/ bgSecondary（描边底色）/ textPrimary（高亮描边）等非色板色——当前明暗主题切换会同时改变色板色（paletteColors 重新求值触发重绘）故无残留；未来主题若仅微调非品牌色（如只调网格线色），画布将残留旧色。建议：组件监听 Theme 暗色标志/主题版本号统一触发 requestPaint，或在注释中声明该前提假设。
- **[Suggestion] s2 请求明细 Repeater 无虚拟化 + refresh() 主线程同步 SQL**：UsageStatsPage 请求明细用 Repeater + detailRows.concat，「加载更多」每次全量重建全部已加载行的 delegate（无虚拟化、无增量），累积数百行后交互开销线性增长；refresh() 在主线程同步执行 6 组 SQL（4 聚合 + COUNT + 明细页），「全部」模式含全表聚合，token_usage 达数万行时 UI 可感知卡顿。建议：明细区改 ListView（复用 + 增量 append），同步 SQL 后续批次评估移 WorkerScript/QtConcurrent + 属性通知。
- **[Suggestion] s3 「今日」预设跨午夜不自动重估**：rangeParams 用 `new Date().setHours(0,0,0,0)` 计算，QML 属性绑定不依赖时钟流逝——页面停留跨午夜后今日卡片会继续显示昨天的「今日」数据；重复点击同一预设（强制刷新）或刷新按钮可缓解。现状可接受（页面注释已声明），长期可加每日 0 点 Timer 或页面可见性变化时自动 refresh。
- **[Suggestion] s4 聚合与明细接口 (0,0) 口径分裂**：聚合三接口（tokenStatsDetailed / tokenStatsBySource / costStats）(fromTs=0, toTs=0) 回退 recentDays 30 天窗口，而 tokenUsageRecords (0,0) 表示全部记录——同签名同参数不同义，调用方漏读注释会拿 30 天数据当全量（UI 侧已用 from=1 规避，IMemory.h 两处注释已分别声明，约 IMemory.h:230 附近）。长期演进：显式「无回退」开关（如 recentDays < 0 表示不回退）或语义命名的范围版本接口（tokenStatsDetailedRange）。
- **[Suggestion] s5 LineTrendChart 末点标签阈值与抽样间距不一致**：x 轴日期标签按 ~56px 间距抽样（maxLabels = plotW/56），末点补充阈值却是 30px——末点与最后一个已显示标签间距落在 30~56px 区间时两者同显，视觉拥挤与抽样设计不一致（LineTrendChart.qml:198 附近）。建议：末点补充阈值对齐抽样间距（≥56px 才补），或改「末点未显示则强制显示并隐藏与其最近的已显示标签」的互斥策略。
- **[Suggestion][安全] 请求明细列表无 UI 层硬上限**：明细「加载更多」累积上限为 DB total（服务端 limit 钳制 [1,500]、单页 50，增长有终点无失控循环），本地单用户数据源无跨用户 DoS 面；但长期使用 token_usage 累积数万行并全量加载时有内存与布局压力。建议：detailRows 达阈值（如 1000 行）后隐藏「加载更多」并引导缩小时间范围，或与 s2 合并整体换 ListView 复用。
- **[Major M1 修复边界] byDay 范围模式 366 行上限**：M1 修复后范围模式 byDay 上限放宽至 366 行（recentDays 回退保持 31），数据跨多年（>366 天）时仍按 day DESC 截断最近 366 天——「全部」预设下极长周期数据的按天明细不完整且无提示（契约已在 IMemory.h/SqliteMemory.h 声明）。长期可做按周/月聚合降采样或前段抽样。
- **[流程] qmllint_gate ctest 通道空转（既有缺陷，非批次六引入）**：tests/CMakeLists.txt 中 gate 测试以 `-DQMLLINT=${QT6_INSTALL_FULL_BINS}/qmllint.exe` 传路径，本机 CMake 配置中 `QT6_INSTALL_FULL_BINS` 解析为空 → 实际执行 `/qmllint.exe`（不存在）→ execute_process 失败但 `out` 为空 → `string(FIND "" "Error: ")` 恒 -1 → 误判 clean（输出特征：`warnings only: no such file or directory`）。即本机 ctest 的 qmllint_gate 从未真实执行 qmllint，此前各批次的 Error=0 结论实为手动验证补足。建议：改用 `$<TARGET_FILE:Qt6::qmllint>` 生成器表达式或 find_program 解析真实路径，修复后以 rsp 全量跑一次确认 Error 级 0（批次六验证时已手动确认全量 Error=0，修复 gate 后应可延续）。

## 10. 用量统计页：去冗余 + 一图一行 + 请求明细表格化

| U1 | 「按模型」「按天」两个列表与图表完全同源（前者 = 环形图 / 模型对比图 / 费用明细，后者 = 按天走势折线图），只重复图的结论 | `UsageStatsPage.qml` | 删除两段列表；`modelSeries` / `dayTrendSeries` 仍供图表使用 |

实现要点（后续改动勿踩）：

- 表格横向滚动**不能**把表体宽度设为列宽总和：那样纵向滚动条会被横向滚动推出视口。现结构是「外层横向 Flickable 只负责 contentX，表头与表体保持视口宽，内部内容整体左移 `-contentX`」。
- 列宽存于 `columnWidths` 数组，改宽必须**整体重新赋值**（QML 的 var 数组元素赋值不发通知）。
- 筛选/排序是本地视图层行为，只作用于已加载的行；「加载更多」由页面注入回调，组件不自己翻页。
- §9 s2 的「Repeater 无虚拟化」与「明细列表无 UI 层硬上限」两条建议随 U4 收口（ListView 复用 + 固定表体高度，页面不再被明细撑长）；`refresh()` 主线程同步 SQL 一项仍在，未变。
