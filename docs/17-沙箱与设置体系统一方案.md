# 17 - 沙箱与设置体系统一方案

状态：工作流 B 已实施（B1 双层禁用/拦截徽标、B2 底栏语义与恢复默认、B3 账本收编、B4 配额编辑、B5 分组、B7 部分项；B6 设置搜索与无障碍补齐为可裁剪项未做）。工作流 A（沙箱）待实施。
前置：本文档基于 2026-09-29 的代码排查结论；所有行号以当前 master 为准。

## 0. 现状小结

沙箱（Sandbox.h）是纯静态路径策略校验器：读策略两档（UserDirectories 白名单 =
文档/下载/桌面/AppData，默认；FullDisk opt-in），写策略固定（白名单 + 整个 Home），
系统目录恒封锁，canonicalize + 边界前缀匹配防逃逸。受约束工具仅 read_file/list_dir
（读）与 write_file/edit_file（写）；shell_exec 与 MCP 工具不在路径沙箱内。
`Sandbox::validateToolCall` 只有测试调用，运行时真实校验点在各工具 execute() 内部。

设置体系五套机制并存：M1 SettingsService 直连（即时保存，GeneralPage/ToolsPage/
MemoryPage）、M2 PreferenceRegistry+EditBuffer（仅 InterfacePage，可保存/取消/恢复
默认）、M3 ToolRegistry 直写 tools/disabled、M4 AgentViewModel 直写运行时布局键、
M5 mcp_servers.json。SettingsSchema 自称唯一事实源但漏收 M3/M4 部分与全部 prefs/v1
键。已排出的 P0-P3 问题清单（P0-1 localOnlyMode 静默重置用户工具开关、P0-2 通用页
"取消"不回滚等）见对话记录，本文档按清单分期消化。

## 1. 工作流 A（定稿 v2）：项目级会话 + 双层沙箱

> v2 依用户决策重写：原 A1 的 extraReadDirs 方案作废——用户构想升级为
> "项目级会话（导入文件夹作为项目）+ 项目沙箱 + 全局黑名单"三层。
> 默认黑名单取保守清单（用户已确认）。实施分两批：批 1 项目会话闭环，
> 批 2 沙箱+黑名单+安全页。

### A0. 项目级会话（批 1）

- **数据模型**：新表 `projects(id TEXT PK, name, root_path, created_at)`；
  `sessions` 表加 `project_id TEXT`（NULL = 普通本地会话），受控 ALTER 迁移
  （沿用 migrateKnowledgeSchema 先例）。删除项目时会话保留（project_id
  置 NULL），不级联删除。
- **当前项目作用域**：全局单活动项目（所有 tab 共享），id 存设置键
  `projects/activeId`，重启恢复。
- **UI**：左侧栏分"项目 / 对话"两区，各自可新建——新建项目 =
  FolderDialog 选目录（项目名默认取目录名）；新建对话与现状一致。
  会话列表按活动项目过滤：项目激活时只显示该项目会话，退出项目显示
  本地（NULL）会话。
- **打点**：活动项目激活期间新建的会话在 beginSession 后标记 project_id；
  token_usage.workspace_id 仅在设计层面关联说明，本轮不打通。

### A1. 项目级沙箱 + 全局黑名单（批 2）

- **判定语义（优先级从高到低）**：
  1. 系统目录硬封锁（现状不变）；
  2. **黑名单 = 绝对拒绝层**：命中即拒，优先于一切允许规则（含 FullDisk
     与项目目录）——防止"导入整个盘当项目"把 ~/.ssh 暴露给模型；
  3. 允许层 = 白名单目录 ∪ 当前项目 root_path（∪ FullDisk 全盘若开启）。
- **默认黑名单（保守清单，用户已确认）**：`~/.ssh`、`~/.gnupg`、`~/.aws`
  凭据目录；`*.pem`、`*.key`、`*.ppk`、`*.kdbx` 密钥/加密文件 glob。
  候选未纳入默认（列此备查）：浏览器 `User Data/**/Login Data`、`*.keystore`、
  `.env`、`id_rsa*`（已被 .ssh 覆盖）。
- **项目目录只读**：写策略范围不变（白名单 + Home），项目目录写入仍走
  原策略——模型对项目外目录的写授权不在本轮范围。
- **拒绝提示（A5）**：区分被哪一层拒绝（系统目录 / 黑名单 / 读取白名单）
  并指引"设置 → 安全"。
- **黑名单条目**：目录前缀与 glob 两种；匹配前先 canonicalize（防 .. 与
  symlink 绕过）；大小写与分隔符在 Windows 下归一。

### A2/A3/A4（不变）

- A2 写策略维持现状（论证见 v1）。
- A3 shell_exec/MCP 不在路径沙箱内：明示 + 缓解 = 确认门 + 会话权限模式，
  本轮不动。
- A4 删除 `Sandbox::validateToolCall` 死代码，test_sandbox 用例改写为直驱
  validatePath。

### A6. 设置页"安全"分类（批 2）

- 新增独立分类 security（SecurityPage.qml + PreferenceRegistry 注册）：
  迁入 allowFullDiskRead / localOnlyMode / allowLocalNetworkFetch 三个开关
  （GeneralPage 安全分组移除，其"恢复本页默认"键集合同步缩减）、黑名单
  编辑器（逐条增删，目录或 glob）。项目管理主体在侧栏，不入设置页。

## 2. 工作流 B：设置体系统一

### B1. 双层禁用状态（修 P0-1，量级 M）—— 最高优先

**问题**：main.cpp:218-238 的 `applyLocalOnlyGate` 用 `setToolEnabled` 表达策略
拦截，把"用户禁用"（tools/disabled 持久层）与"隐私策略拦截"（运行时策略）混在
一层。关闭 localOnly 或切 profile 时无条件 `setToolEnabled(true)`，用户手动禁用
的工具被静默重开并持久化。

**设计**：ToolRegistry 增加独立策略层（内存态，不持久化）：

```
setPolicyBlocked(const QStringList& names, bool blocked)   // 策略层写入口
bool isPolicyBlocked(const QString& name) const
bool isToolUsable(const QString& name) const               // = isToolEnabled && !isPolicyBlocked
```

- `toolNamesForModel()` 改用 `isToolUsable`（模型看不到被策略拦截的工具）。
- AIAgent 的 disabled 分支（processNextToolCall）改查 `isToolUsable`，错误文案
  区分两种原因："disabled by the user" / "blocked by the local-only privacy mode"。
- main.cpp 的 gate 改调 `setPolicyBlocked`，不再触碰 tools/disabled。启动时
  `applyLocalOnlyGate()` 已有调用，策略层重启后自然重建。
- `AgentViewModel.toolRegistryModel` 每项增加 `blockedByPolicy` 字段（B4 的
  ToolsPage 徽标数据源）。
- 迁移：无数据迁移。曾被污染写为 enabled 的工具需用户手动重开一次（可接受，
  release note 注明）。

### B2. 对话框底栏语义 + 通用页恢复默认（修 P0-2 / P1-4，量级 S/M）

**问题**：SettingsCenterDialog 底栏"保存/取消"对 M1 即时保存页无意义且误导
（取消不回滚 GeneralPage 的安全开关改动）；"恢复默认"仅 interface 类可用。

**设计**：
- 底栏 context-aware：当前分类有 M2 注册键时才显示"保存/取消"（复用现有
  `preferencesInCategory(...).length > 0` 判定）；否则显示"此页修改即时保存"
  静态文本。"恢复默认"按钮同步按分类隐藏（替换现在的禁用置灰）。
- GeneralPage 顶部新增"恢复本页默认"：SettingsService 新增
  `Q_INVOKABLE void resetGeneralToDefaults()`，把该页 9 个键回写 schema 默认值
  并逐一 emit notify。安全开关回滚前弹二次确认（沿用 Dialog 模式）。

**最终决策（实施后由用户拍板升级）**：设置中心全面即时保存——EditBuffer::stage
改为"校验通过立即写穿"，界面设置页同样不再有保存/取消；底栏统一为
"恢复默认（仅声明式偏好分类）+ 关闭"。安全开关等 M1 键与 M2 键行为完全一致，
不存在"忘了点保存"的窗口期；确认放弃弹窗移除，onClosed 回滚仅兜底丢弃
校验失败的 staged 残值。原"全面推广成本高"的顾虑通过改造 EditBuffer 本体
（13 处 QML 调用点零改动）化解。

### B3. 设置账本统一（修 P2-7，量级 S）

SettingsSchema 收编为真正的总账：
- 登记 `tools/disabled`、`schemaVersion`、全部 `prefs/v1/*` 键与
  `settings.lastCategory`（encrypted=false）。
- test_settings 新增"账本完整性"用例：断言 PreferenceRegistry 全部键 + M3/M4

- schema 头注释明确范围：QSettings 键账本；M5（mcp_servers.json）不属于本账本
  并注明理由（非 QSettings 存储，独立格式有独立校验）。
- M4 布局键维持直写（拖拽高频写，不走 notify 体系），仅纳入账本登记。

### B4. 配额编辑 UI（修 P1-3）+ 策略拦截可见性（修 P1-5）（量级 S/M）

### B5. 页面归属整合（修部分 P2-6，量级 S）

## 4. 风险与取舍

1. **期 1 触碰工具执行链**，回归点最多：localOnly 切换 × profile 切换 × 用户
   手动开关 × MCP 动态上下线 × 会话权限模式的组合。策略层必须内存态（重启由
   启动 gate 重放），`tools/disabled` 内容不再被 gate 触碰——这是修复本身，
   但意味着历史被污染的 enabled 状态不会自动恢复。
2. **恢复默认会重置安全开关**：必须二次确认，且 reset 列表与 GeneralPage 实际
   键集合要保持同步（测试断言）。
3. **extraReadDirs 的信任边界**：用户添加的目录等同白名单，模型可读其中一切
   并可能发送给云模型——UI 文案需明示；不校验路径存在性（canonicalize 容错），
   但规范化必须去重/统一分隔符，避免绕过。
4. **A4 删死代码**是行为无损变更，但 test_sandbox 断言需同步重写，注意保留
   "系统目录封锁"断言。
5. **B3 纯登记零行为变化**，唯一风险是 schema 测试基线同步。
6. **裁剪项**：期 6（搜索/无障碍）不阻塞主目标，可最后评估。
