**Batch 13 执行注记（2026-09-09，随本批提交）**：
- **实现偏差**（经线程时序说明论证，与 §1.1 契约一致）：`QProcess` 保持 `execute()` 局部变量、**不**升为工具成员——成员方案需 GUI 线程跨线程触碰 QProcess，而 QueuedConnection 投递 kill 会落到正阻塞在 waitForFinished 上的池线程（事件循环不处理）。实际形态：`cancel()` 只置 `std::atomic` 标志；`execute()` 以 200ms 分片等待，片间自查标志并在池线程自身完成 `taskkill /T /F`（Windows 树杀）+ `kill()` + `waitForFinished(2000)` 收尾。入口不复位标志（保证 stop 先于 execute 入口的取消仍被首个片间观察到）。
- **测试偏差**：`AnomalyTool` 的 sleep 模式用 100ms 可中断分片替代 `sleep_for(30s)`（硬睡会使 trace 翻转迟到 30s，"cancelled"断言不可达且长期占用池线程）；`shellProcessKilledOnStop` 按 Windows 适配用 `ping -n 31 127.0.0.1 > nul`（cmd 下无 `sleep`）。
- **验证揪出的缺陷**：Qt 6 的 `QProcess::execute(单字符串)` **不拆分参数**（仅 `(program, arguments)` 签名），taskkill 曾静默失败 → cmd 被杀而 ping 孤儿化 → ctest 因等待孤儿持有的继承管道 EOF 而假慢 31.9s。已改双参形式并校验退出码后，test_agent 回落 4.16s（基线 3.7s）。
- 已知有界残留（时序说明窗口 B）：cancel 落在 execute 已返回、watcher 回调未运行的微秒级窗口时，取消标志会残留并被下一个 shell_exec 的首个片间消费为一次快速失败 "Command cancelled"——自愈、无副作用悬挂，接受。

## 11. 验收与回归纪律（沿用 7 号文档第 7 节）

1. 修改前先读代码；不确定不猜测，用日志/测试取证。
2. 不为过测而改测试；不删功能绕问题；不做无理由重构；最小修改、不碰无关代码。
3. 每个 Batch 结束跑全量 `ctest`；发现新 P0/P1 立即记入 7 号文档第 2 节并重排 Batch。
4. 临时 workaround 必须标注"由 Batch X 收敛"，禁止无主 workaround。
5. 不伪造结果：未验证不得声称完成；验证命令与输出随 Batch 报告提交。
6. **跨线程工具改造（Batch 13）必须先写线程时序说明再动代码**；cancel 路径禁止阻塞与跨线程对象直触。
7. **凡新增 QSettings 键，同批补 SettingsGuard 测试键清单**（教训：Batch 12 曾因遗漏导致测试关闭后真实注册表泄漏）。本计划涉及新键：`security/localOnlyMode`（Batch 14）、`security/allowLocalNetworkFetch`（Batch 20）。
8. **凡涉及 SQLite 迁移，沿用 PRAGMA 检测 + ALTER/CREATE 自愈模式并补旧库升级用例**（教训：Batch 6/11 双表迁移自愈是既定模式）。本计划涉及：`messages_fts`（Batch 17）。
