## 1. 背景与目标

### 1.1 问题陈述

NexusAI 当前的上下文长度处理存在**全局统一值与模型实际窗口不匹配**的核心矛盾：

- Agent 侧上下文预算为全局单值 `Settings.contextTokens`（默认 300000，范围 2048–1048576），最初在**通用设置页**暴露、对所有 Profile/模型共享；该入口已随后续调整移除，统一由「模型配置」页按配置管理，此值只作能力表未覆盖模型的兜底。
- 不同模型的实际上下文窗口差异巨大（4K–200K），全局统一值导致：大模型窗口被浪费（过早压缩）、小模型窗口被溢出（请求被拒绝）。
- 不存在按模型名映射上下文窗口的能力表。

### 1.2 设计目标

1. **按模型自动配置上下文长度**：依据每个 Provider 的模型能力表，自动设定当前会话的上下文预算。
2. **模型切换时即时适配**：切换模型导致上下文预算变化时，即时检测并处理历史不适配。
3. **用户可见、历史可恢复**：压缩操作对用户可见（trace 节点 + UI 提示），被丢弃的历史保留在 SQLite 中可追溯。
4. **向后兼容**：旧版本配置不受影响；未知模型回退到全局默认值。
5. **用户可覆盖**：能力表提供默认值，用户可在 Profile 级手动覆盖（高级选项）。

### 1.3 非目标

- 不修改 Provider 请求体结构（OpenAI/Anthropic 无上下文窗口请求参数，仅 Ollama 有 `num_ctx`）。
- 不改变 `compressToFit` 的压缩算法（保留 system prompt + omission marker + 最大连续后缀）。
- 不实现模型能力表的自动发现（通过 API 获取模型窗口）——留作后续增强。

## 2. 现状分析（带代码证据）

### 2.1 上下文长度双轨链路

项目中存在两条独立的上下文长度链路：

**链路 A：Agent 侧上下文预算（全局统一）**

```
Settings.contextTokens（默认 300000，clamp 2048–1048576）
  → main.cpp:373/511/515 → AIAgent::setContextLimit()
  → AIAgent.cpp:143-148 clamp 到 [MinContextTokens, MaxContextTokens]
  → AIAgent.cpp:520 applyContextBudget() 在每次 LLM 请求前调用
  → AIAgent.cpp:558-572 实际压缩逻辑
  → TokenEstimator.h:98-145 compressToFit() 执行历史压缩
```

- 边界常量：`AIAgent.h:52-53` → `MinContextTokens = 2048`、`MaxContextTokens = 1048576`。
- UI 暴露点：`GeneralPage.qml:97-109` → "上下文窗口 (Tokens)"输入框。
- **问题**：全局统一值，所有 Profile、所有模型共享。

**链路 B：Provider 侧上下文窗口（仅 Ollama）**

```
Profile.numCtx（per-profile，留空=不发送）
  → main.cpp:332-333 SamplingParams::optionalPositiveInt() 规范化
  → main.cpp:348 OllamaService::setSamplingParams()
  → OllamaService.cpp:43-44 options.num_ctx 加入请求体
```

- OpenAI/Anthropic 请求体无任何上下文窗口参数（`OpenAIService.cpp:56-61`、`AnthropicService.cpp:226-236`）。
- **问题**：`numCtx` 仅对 Ollama 有效，且是 per-profile 而非 per-model。

### 2.2 压缩时机：惰性压缩

`setContextLimit()`（`AIAgent.cpp:143-148`）只更新 `m_contextLimit` 并 emit 信号，**不立即压缩**。压缩延迟到下一次 LLM 请求时（`AIAgent.cpp:520` `applyContextBudget`）才发生。

### 2.3 压缩行为：单向丢弃

`compressToFit()`（`TokenEstimator.h:98-145`）：
- 保留：system prompt（第一条）+ omission marker + 最大的连续后缀（从最近的 user 消息开始）。
- 丢弃：中间的历史消息（从 `m_messages` 内存数组中移除）。
- **被丢弃的消息仍在 SQLite 中**（`compressToFit` 只修改内存 `m_messages`，不删除持久化数据）。

### 2.4 会话恢复：不检查窗口适配

`resumeSession()`（`AIAgent.cpp:366-394`）从 SQLite 加载最多 200 条历史消息到 `m_messages`，不检查是否超出当前 `contextLimit`。

### 2.5 Profile 结构与扩展性

- Profile 存于 QSettings 键 `modelProfiles`（`SettingsService.cpp:48`），为 `QVariantList<QVariantMap>`。
- `updateProfile()` 对未知键**无白名单透传合并**（`SettingsService.cpp:313-318`），仅跳过 `id` 和非法 `provider`。
- `SettingsSchema` 明确不登记 profile 内部键（`SettingsSchema.h:27-29`）。
- **结论**：新增 per-profile 字段无需修改 SettingsService 或 SettingsSchema。

### 2.6 模型选择器

- `ModelSelector.qml`（挂载 `AgentChatPage.qml:254`），切换的是 Profile 内的 `model` 字符串。
- 切换后触发 `activeProfileChanged` → `main.cpp:543 applySettings()` → 重新注入 `contextLimit`（值为全局 `contextTokens`）。

### 2.7 不存在按模型能力表

全局搜索 `128000`、`200000`、`contextWindow`、`modelCapabilities`、`contextLength`、`pricing` 等关键词，零匹配。仅有全局 Min/Max 常量。

### 3.3 上下文预算决策函数

新增 `SettingsService` 方法，按优先级解析当前模型的有效上下文预算：

```cpp
// SettingsService.h 新增
public:
    /// 解析当前活跃 Profile 的有效上下文预算。
    /// 优先级：Profile 级 contextLength 覆盖 > 能力表 contextWindow > 全局 contextTokens
    int resolveContextLimit() const;

    /// 查询指定 provider+model 的能力表上下文窗口。
    /// 返回 0 表示未知（调用方应 fallback 到全局默认）。
    int modelContextWindow(const QString& provider, const QString& model) const;

// SettingsService.cpp 实现
int SettingsService::modelContextWindow(const QString& provider,
                                        const QString& model) const {
    const auto it = providerDefaults().constFind(provider);
    if (it == providerDefaults().constEnd()) return 0;
    const auto wit = it.value().contextWindows.constFind(model);
    if (wit == it.value().contextWindows.constEnd()) return 0;
    return wit.value();
}

int SettingsService::resolveContextLimit() const {
    const QVariantMap profile = activeProfile();
    const QString provider = profile.value("provider").toString();
    const QString model = profile.value("model").toString();

    // 优先级 1：Profile 级 contextLength 覆盖
    const QVariant profileOverride = profile.value("contextLength");
    if (profileOverride.isValid() && !profileOverride.toString().isEmpty()) {
        bool ok = false;
        const int v = profileOverride.toInt(&ok);
        if (ok && v > 0) return v;
    }

    // 优先级 2：能力表 contextWindow
    const int tableValue = modelContextWindow(provider, model);
    if (tableValue > 0) return tableValue;

    // 优先级 3：全局 contextTokens（fallback）
    return m_contextTokens;
}
```

## 4. 模型切换适配策略

### 4.1 三种场景与处理策略

| 场景 | 描述 | 策略 |
|------|------|------|
| A. 大窗口 → 小窗口 | 如 GPT-4o (128K) → Ollama 7B (4K)，历史 50K 超出 | 即时压缩 + trace 节点 + UI Toast |
| B. 小窗口 → 大窗口 | 如 Ollama 7B (4K) → GPT-4o (128K)，历史曾被压缩 | 从 SQLite 恢复完整历史 |
| C. 会话恢复时不适配 | 恢复 50K 历史但当前模型仅 4K | 加载后即时压缩 |

### 4.2 AIAgent 改造

#### 4.2.1 setContextLimit 改造

```cpp

    void onContextLimitChanged(int oldLimit, int newLimit);
    void restoreFullHistoryIfAvailable();

// AIAgent.cpp 改造
void AIAgent::setContextLimit(int tokens) {
    const int clamped = qBound(MinContextTokens, tokens, MaxContextTokens);
    if (m_contextLimit == clamped) return;
    const int oldLimit = m_contextLimit;  // 新增：记录旧值
    m_contextLimit = clamped;
    emit contextLimitChanged();
    onContextLimitChanged(oldLimit, clamped);  // 新增：即时适配
}
```

#### 4.2.2 onContextLimitChanged 实现

```cpp
void AIAgent::onContextLimitChanged(int oldLimit, int newLimit) {
    if (m_messages.isEmpty() || oldLimit == newLimit) return;
    if (m_active) return;  // 任务进行中不干扰（下次请求时自然适配）

    const int currentTokens = TokenEstimator::estimateTokens(m_messages);
    const int reserved = estimateReservedTokensForNextRequest();
    const int effective = qMax(0, newLimit - reserved);

    if (newLimit > oldLimit && currentTokens <= effective) {
        // 场景 B：切换到大窗口，当前历史未超新预算
        // 尝试从 SQLite 恢复被压缩的历史
        restoreFullHistoryIfAvailable();
    } else if (currentTokens > effective) {
        // 场景 A 或 C：历史超出新预算，即时压缩
        const int before = m_messages.size();
        applyContextBudget(reserved);
        // applyContextBudget 内部已插入 trace 节点（AIAgent.cpp:568-571）
        // 若实际发生了压缩（m_messages.size() < before），UI 会通过 traceChanged 感知
    }
    // else：历史未超新预算，无需操作
}

int AIAgent::estimateReservedTokensForNextRequest() const {
    // 估算下一次请求的 reserved tokens（tools schema）
    // 保守估计：取最近一次的 tools schema 大小，或固定值
    if (!m_toolRegistry) return 0;
    QJsonArray toolsArray;
    for (const auto& def : m_toolRegistry->listAll()) {
        if (def.level == ToolLevel::Dangerous) continue;
        if (!m_toolRegistry->isToolEnabled(def.name)) continue;
        QJsonObject toolObj;
        toolObj["type"] = "function";
        QJsonObject fn;
        fn["name"] = def.name;
        fn["description"] = def.description;
        fn["parameters"] = def.parameters;
        toolObj["function"] = fn;
        toolsArray.append(toolObj);
    }
    return TokenEstimator::estimateToolsSchema(toolsArray);
}
```

#### 4.2.3 restoreFullHistoryIfAvailable 实现

```cpp
void AIAgent::restoreFullHistoryIfAvailable() {
    if (!m_memory || m_sessionId.isEmpty()) return;

    // 从 SQLite 加载完整历史（提高上限以覆盖长会话）
    const QJsonArray fullHistory = m_memory->loadMessages(m_sessionId, 2000);
    if (fullHistory.size() <= m_messages.size() - 1) return;  // -1 for system prompt

    // 重建 m_messages：保留当前 system prompt + 完整 user/assistant 历史
    QJsonArray restored;
    if (!m_messages.isEmpty()
            && m_messages.first().toObject().value("role") == "system") {
        restored.append(m_messages.first());
    }

    for (const auto& entry : fullHistory) {
        const QJsonObject msg = entry.toObject();
        const QString role = msg.value("role").toString();
        if (role != "user" && role != "assistant") continue;
        if (role == "assistant" && msg.value("content").toString().isEmpty())
            continue;
        restored.append(msg);
    }

    const int restoredTokens = TokenEstimator::estimateTokens(restored);
    const int reserved = estimateReservedTokensForNextRequest();
    const int effective = qMax(0, m_contextLimit - reserved);

    if (restoredTokens > effective) {
        // 恢复后仍超出新窗口，压缩（但至少恢复了更多历史）
        m_messages = restored;
        applyContextBudget(reserved);
    } else {
        const int added = restored.size() - m_messages.size();
        if (added > 0) {
            m_messages = restored;
            appendTraceNode("context",
                QStringLiteral("History restored: %1 messages reloaded "
                               "after switching to a larger context window")
                    .arg(added),
                "completed");
            notifyTokens();
        }
    }
}
```

#### 4.2.4 resumeSession 改造

```cpp
void AIAgent::resumeSession(const QString& sessionId) {
    // ... 现有加载逻辑保持不变 ...

    // 新增：加载后检查是否超出当前 contextLimit
    const int reserved = estimateReservedTokensForNextRequest();
    const int effective = qMax(0, m_contextLimit - reserved);
    if (TokenEstimator::estimateTokens(m_messages) > effective) {
        applyContextBudget(reserved);  // 即时压缩
    }
}
```

## 8. 风险评估与缓解

| # | 风险 | 严重度 | 概率 | 缓解措施 |
|---|------|--------|------|---------|
| 1 | 能力表数据过时（模型更新） | 中 | 中 | 内置主流模型 + 允许用户覆盖 + 未知模型 fallback；后续可加自动发现 |
| 2 | Ollama 模型窗口不固定 | 中 | 高 | 能力表标注为估计值；用户可通过 `numCtx` 覆盖服务端窗口、`contextLength` 覆盖 Agent 侧预算 |
| 3 | `contextLength` 与 `numCtx` 语义混淆 | 中 | 中 | UI 中明确区分：`contextLength` = Agent 侧压缩预算；`numCtx` = Ollama 服务端窗口参数。添加 tooltip 说明 |
| 4 | 历史恢复时 SQLite 查询性能 | 低 | 低 | `loadMessages` 上限 2000 条，SQLite 索引查询通常 < 10ms；可加防抖 |
| 5 | 切换时即时压缩的延迟 | 低 | 低 | `compressToFit` 是纯内存操作（遍历 `m_messages`），通常 < 1ms |
| 6 | 任务进行中切换模型 | 中 | 低 | `onContextLimitChanged` 检查 `m_active`，任务中不干扰，下次请求时自然适配 |
| 7 | `contextLength` 与 `maxOutputTokens` 混淆 | 中 | 中 | UI 标注：上下文预算 = 输入 + 输出总预算；最大输出 = 仅输出部分。分属不同区域 |
| 8 | 向后兼容（旧 Profile 无 `contextLength`） | 低 | 低 | `resolveContextLimit` 优先级 1 检查 `isValid` + 非空，旧 Profile 自动 fallback 到能力表或全局 |
| 9 | 能力表与 `numCtx` 不一致 | 中 | 中 | Ollama 模型：`contextLength`（Agent 预算）应 ≤ `numCtx`（服务端窗口）；UI 可加一致性校验提示 |

## 9. 接口变更摘要

### 9.1 SettingsService 新增公共方法

```cpp
/// 查询指定 provider+model 的能力表上下文窗口。
/// @return 上下文窗口大小（tokens）；0 表示未知
int modelContextWindow(const QString& provider, const QString& model) const;

/// 解析当前活跃 Profile 的有效上下文预算。
/// 优先级：Profile 级 contextLength > 能力表 contextWindow > 全局 contextTokens
/// @return 有效的上下文预算（tokens）
int resolveContextLimit() const;
```

### 9.2 AIAgent 新增私有方法

```cpp
/// 上下文预算变化时的即时适配。
/// 大窗口 → 恢复历史；小窗口 → 即时压缩。
void onContextLimitChanged(int oldLimit, int newLimit);

/// 从 SQLite 恢复被压缩的完整历史。
void restoreFullHistoryIfAvailable();

/// 估算下一次请求的 reserved tokens（tools schema）。
int estimateReservedTokensForNextRequest() const;
```

### 9.3 Profile 新增字段

| 字段 | 类型 | 默认 | 说明 |
|------|------|------|------|
| `contextLength` | int（可选） | 无 | Profile 级上下文预算覆盖；留空 = 按能力表自动 |

> **注意**：Profile 为 QVariantMap，`updateProfile` 透传未知键，无需修改 SettingsService 结构。`SettingsSchema` 不登记 profile 内部键。
