## 5. 验证基线（后续工作的回归口径）

**`ctest` 现在不需要手工设 PATH** —— `tests/CMakeLists.txt` 顶部的 `add_test` 包装给全部 39 个用例注入了 Qt bin 目录（见 §5.2）。在任意 shell 直接跑：

```powershell

```

### 5.1 从零配置（新工作区 / CI）

`build/` 里的 `CMakeCache.txt` 已缓存 Qt 与编译器路径，所以增量构建不需要任何环境变量。**全新配置**则必须显式给齐工具链，否则 `find_package(Qt6)` 直接失败：

```powershell
# Ninja 与 g++ 需在 PATH（来自 D:/Qt/Tools/），Qt 用 CMAKE_PREFIX_PATH 定位
$env:PATH = "D:/Qt/Tools/mingw1310_64/bin;D:/Qt/Tools/Ninja;" + $env:PATH
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release -DBUILD_TESTS=ON `
      -DCMAKE_PREFIX_PATH=D:/Qt/6.9.0/mingw_64
```

三者缺一不可：缺 Ninja/g++ → `CMAKE_MAKE_PROGRAM is not set`；缺 `CMAKE_PREFIX_PATH` → `Could not find Qt6Config.cmake`。

### 5.2 Qt PATH 是怎么接上的（2026-10-21 修复）

**问题**：测试可执行文件动态链接 Qt，Windows 加载时找不到 `Qt6Core.dll` 等，进程以 `0xc0000135`（STATUS_DLL_NOT_FOUND）退出——**一个用例都没跑起来**，看起来像大面积失败，实际只是缺工具链。

**修复**：`tests/CMakeLists.txt` 顶部包装了 `add_test`，每次注册都顺手给该用例设 `ENVIRONMENT_MODIFICATION "PATH=path_list_prepend:<Qt bin>"`。

两个关键设计点：

- **用 `path_list_prepend` 而非 `ENVIRONMENT`**：前者是**追加**到继承来的 PATH，编译器目录和用户 PATH 都保留；后者会整体替换 PATH，把 `git`、`powershell` 等依赖搞坏（`test_git_service`、`qmllint_gate` 需要它们）。
- **包装 `add_test` 而非在文件末尾统一设**：本文件有两种注册方式——直接 `add_test(...)` 和经 `nexus_add_test()` 辅助函数。末尾统一设的方案里，`PARENT_SCOPE` 只能把名字传回函数作用域而非目录作用域，经 `nexus_add_test` 注册的 13 个用例会漏掉。在包装函数内立即设属性则两条路径都覆盖。

**为什么只需要 Qt bin 一个目录**：Qt 的 bin 目录自带 MinGW C++ 运行时（`libstdc++-6.dll`、`libgcc_s_seh-1.dll`、`libwinpthread-1.dll`），所以 `D:/Qt/Tools/mingw1310_64/bin` 不必进 PATH。

**验证**：清空 PATH 中的 Qt 后 `ctest` 仍 39/39 通过；全新配置树同样 39/39 命中该属性。
