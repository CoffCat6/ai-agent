## 0. 修复原则

1. **先复现后修复**：P0/P1 中标注“潜在/理论”的条目，先写失败用例或最小复现脚本，确认触发条件再改代码。
2. **安全默认**：涉及凭据、外部配置、路径边界时，默认拒绝而不是静默降级。
3. **单一职责**：一个 PR/批次只改一类问题，避免“顺手重构”扩大回归面。
4. **可观测**：新增失败路径必须有日志/错误码，不允许 `qWarning` 后继续。
5. **文档同步**：每批完成后回填本文件状态，并修正相关 codemap 的失真描述。
6. **不做无证据的“防御性大改”**：例如不因理论风险重写整个调度器；优先用局部锁/幂等封口/校验。

## 2. B1 — 安全与崩溃止血（当前执行）

### B1-1 停止 profiles/activeProfile 向 QML 泄露明文 API Key

**根因**
- `SettingsService::profiles()` 直接返回 `m_profiles`，`activeProfile()` 直接返回其中一项；`m_profiles` 在 load 时已用 DPAPI 解密为明文（`SettingsService.cpp:299`）。
- 两个 getter 都是 `Q_PROPERTY`，任意 QML 可读 `Settings.profiles[i].apiKey`。
- QML `ModelConfigPage` 还依赖 `editing.apiKey` 判断“已配置”、传给 `ConnectionTester.test/fetchModels`。

**设计**
1. `profiles()` / `activeProfile()` 返回**公共副本**：移除 `apiKey`，新增 `hasApiKey: bool`；其余字段不变。
2. 新增 C++ 专用 `profilesWithSecrets()` / `activeProfileWithSecrets()`：不注册为 Q_PROPERTY/Q_INVOKABLE，返回真实值。
3. 内部调用点改用 `*WithSecrets()`：`main.cpp:778/841/843`、`CommitMessageDrafter.cpp:177`、`SettingsService.cpp:330`。
4. 连接测试改为按 profileId 取密钥：新增 `ConnectionTester::testProfile(profileId, model)` 与 `fetchModelsForProfile(profileId)`（或在 SettingsService 内部完成），QML 不再传 `apiKey`。
5. `ModelConfigPage`：密钥输入框始终为空；状态/提示改用 `hasApiKey`；`submitField("apiKey", ...)` 仅在用户实际输入时调用，避免空值覆盖。
6. `updateProfile` 保持“缺省字段不覆盖密钥”的语义，并用测试锁定。
7. 测试：新增“QML 可见 profile 不含 apiKey / hasApiKey 正确 / 按 id 测试连接使用真实密钥 / 未输入密钥不覆盖”。

**验收**
- `test_settings` 全绿且新增 4 条断言；QML 侧 grep 不到 `apiKey` 读取。

### B1-2 数据库恢复失败后标签页为空并可能空指针

**根因**
`AgentViewModel::restoreDatabaseFrom` 在 `closeAllTabs()` 后，`restoreFromBackup` 失败直接 `return`，跳过 `openTab()`；`AgentViewModel.h:243+` 的 getter 直接 `active()->...`。

**设计**
- 失败分支先 `openTab()` 恢复单标签稳态，再返回错误；补 `active()` 空守卫的通用降级（至少状态/轨迹类 getter）。
- 测试：构造 restore 失败（目标路径被占用/只读/非数据库），断言 `tabCount() == 1`、`state() == Idle`、无崩溃。

**验收**
- `test_viewmodel` 新增失败路径用例并通过。

### B1-3 `importFromUrl` 工作线程捕获 `this`

**根因**
`AgentViewModel.cpp:1915` 的 Lambda 捕获 `this`，在线程池中读取 `m_urlFetchCancel`；VM 析构后 UAF。

**设计**
- 把取消旗标改为 `std::shared_ptr<std::atomic<bool>>`（或 `QSharedPointer`），worker 捕获副本；`WebContent::fetchUrl` 接受引用即可解引用。
- 停止/析构路径置位，worker 安全退出。
- 测试：启动导入后立即销毁/取消，ASAN 或至少无崩溃；`urlImportRunning` 复位。

**验收**
- `test_viewmodel` 新增“导入中取消/销毁不崩溃”。

### B1-4 MCP `.cmd/.bat` 参数中的 cmd 元字符注入

**根因**
`StdioTransport.cpp` 对 batch 包装器用 `cmd.exe /d /s /c`，`quoteForCmd` 只处理空格/制表/双引号；args 中 `& | < > ^ %` 未转义，导入的配置可串联执行额外命令。

**设计**
- 方案 A（首选，安全默认）：对 `.cmd/.bat` 的 args 做严格校验，出现 `& | < > ^ ( ) % !` 等 cmd 元字符时拒绝启动，并给出“请改用 .exe 或移除元字符”的可读错误。
- 方案 B（兼容）：逐字符 `^` 转义 + `%` 双写；复杂度高，暂不采用。
- `McpConfigTransfer::validate` 在导入阶段同步拒绝元字符参数，导入预览明确提示。
- 保留现有 `.cmd` 路径解析；非 batch 仍走参数数组，不经过 shell。
- 测试：`test_mcp` 新增恶意 args 导入/启动被拒；正常含空格路径仍可启动。

**验收**
- `test_mcp` 全绿；新增 2 条安全用例。
