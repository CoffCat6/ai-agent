## 1. 背景与目标

功能增强波次 0–3（T1–T14）已全部交付（2026-09-25，18/18 ctest 全绿），归档于 `docs/12` §18。§19 登记了 6 项遗留事项 L1–L6。本方案对 L1–L6 逐项做**现状与根因定位**，给出**修复方案**、**任务拆分**与**验收标准**。

目标：

1. 消除"有 C++ 能力、无用户入口"的功能孤岛（L1）；
2. 消除"配置键无统一登记/迁移"的结构性隐患（L2）；
3. 提升中文情景记忆检索召回率（L3）；
4. 修复搜索 provider 配置失效并打通多后端扩展点（L4）；
5. 明确 GUI 真机冒烟清单（L5）；
6. 统一日志/数据目录的文档口径（L6）。

## 2. 现状与根因定位

> 以下结论均以 master 源码为准（spec.md / design.md 交付基线不可信，参见既有约定）。

### L1 web_search 与 episodic 缺设置中心 UI 入口

| 项 | 结论 |
|----|------|
| 现状 | `SettingsService` 暴露 `webSearchProvider` / `webSearchApiKey` / `episodicMemoryEnabled` 三个 Q_PROPERTY（`src/viewmodels/SettingsService.h:45-49`），均有 QSettings 持久化与信号（`SettingsService.cpp:226-229`、`540-568`）；QML 侧**无任何引用**（`src/ui/` 全量检索无命中） |
| 设置中心结构 | 分类由 `PreferenceRegistry.categories()` 驱动，`CategoryNav.qml:30` 动态渲染；`SettingsCenterDialog.qml:103-136` 用**静态 Loader** 按 category 加载 5 个页面（model / interface / general / mcp / tools） |
| 可复用落点 | `GeneralPage.qml:112-115`「应用行为」区已有直接绑定 `Settings.*` 的 CheckBox（`simulationMode` / `allowFullDiskRead` / `localOnlyMode` / `allowLocalNetworkFetch`），**实时保存**且不受底部「保存/取消」影响（页面自带说明 `:43`）；`ToolsPage.qml:43` 是工具开关列表 |
| 根因 | T6/T8 只完成了 C++ 能力层与持久化，**未做 QML 接入**；非代码缺陷，属交付缺口 |
| 掩码语义 | `webSearchApiKey()` getter 返回空串掩码（`SettingsService.h:101`），UI 不能回显明文，须设计"留空=不修改"输入语义 |

### L2 SettingsGuard 键备份未落地

| 项 | 结论 |
|----|------|
| 现状 | 存在**两套**设置存储：① `PreferenceRegistry`（QML 偏好元数据注册表，`PreferenceRegistry.h:44-77`）+ `PreferenceStore`（QSettings 存储 + legacy 兼容 + ChangeBus，`PreferenceStore.h:15-42`）；② `SettingsService`（直接 QSettings，键清单硬编码在 `load()`） |
| 键清单 | `SettingsService::load()` 硬编码约 12 个键（`SettingsService.cpp:212-229`）：`contextTokens`、`simulationMode`、`security/*`、`embedding/*`、`agent/systemPromptOverride`、`logging/level`、`webSearch/*`、`memory/episodicMemoryEnabled`；profile 走独立 JSON 键 |
| 机制存在性 | `SettingsGuard` / `kGuardedKeys` / `guardKeys` 全仓**无匹配**——纯规划设想，代码不存在 |
| 根因 | 规划（`docs/12` §16.2、tasks.md）要求"SettingsGuard 覆盖新键"，但该机制从未实现；键分散两套存储，无统一备份/迁移入口 |
| 影响 | 新增键无统一登记；无导出/导入/版本迁移路径；`ui.themeMode` 仅靠 `PreferenceStore` 的 legacy 兼容兜底 |

### L3 FTS5 中文分词限制

| 项 | 结论 |
|----|------|
| 现状 | `episodic_fts` 建表**未指定 tokenizer**（`src/core/memory/SqliteMemory.cpp:161-163`）→ 使用默认 `unicode61`；对照 `messages_fts` 已用 `tokenize='trigram'`（`SqliteMemory.cpp:105-108`，Batch 17 决策） |
| 根因 | T8 新建 `episodic_fts` 时未沿用 Batch 17 的 trigram 决策（`SqliteMemory.cpp:94-101` 记录了"unicode61 无法子串匹配 CJK"的探针结论） |
| 影响 | CJK 子串查询失败（如查询"信号"无法匹配摘要中的"信号槽"）；现有测试用整词规避（`tests/test_episodic.cpp:79` 用 `"Qt 信号槽"`、`:139` 用英文 `"Qt"`） |
| 附带隐患 | `searchEpisodic()`（`SqliteMemory.cpp:682-703`）把原始 query **直接拼入 MATCH**，未转义引号/特殊字符；非法 FTS 语法会使 `exec()` 失败并**静默返回空**（无告警日志） |

### L4 搜索后端仅 Tavily

| 项 | 结论 |
|----|------|
| 现状 | `WebSearchBackend` 抽象清晰（`providerKey()` + `search()`，`src/core/tools/WebSearchBackend.h:20-35`），仅 `TavilyBackend` 一个实现（`:40-48`） |

| 影响 | 无法接入第二个搜索服务；provider 配置项对用户是误导 |

## 3. 修复方案

### 3.1 L1 设置中心补入口（决策 D3：新增独立分类）

**方案（已定：新增「工具与记忆」独立分类）**

1. **注册分类**：`PreferenceRegistry::registerCategory("tools_memory", QT_TRANSLATE_NOOP("NexusAI", "工具与记忆"), <order>)`；`CategoryNav.qml:30` 动态取 `categories()` 自动渲染，导航无需改动。
2. **新建页面** `src/ui/pages/ToolsMemoryPage.qml`：
   - **长期记忆**区：CheckBox `Settings.episodicMemoryEnabled` + 说明（开启后完成任务生成摘要、新会话注入相关摘要）；
   - **联网搜索**区：provider `ComboBox`（选项来自后端注册表，当前仅 `tavily`）+ apiKey `TextField`（`echoMode: Password`，参照 `ModelConfigPage.qml:209-217`）+「清除密钥」按钮 + 隐私提示"查询将发送至所配置的搜索服务商"（呼应 `WebSearchTool.h:36-38`）；
   - **掩码语义**：apiKey placeholder 提示"已配置/未配置"，留空 = 不修改（`webSearchApiKey()` getter 返回空串掩码，`SettingsService.h:101`）。
3. **挂载 Loader**：`SettingsCenterDialog.qml:103-136` 增加一个 Loader（`active: dialog.currentCategory === "tools_memory"`）。
4. 全部文案走 `qsTr()` 并更新双语 `.ts`；补齐 `Accessible.name` / `Accessible.description`（延续 T7 规范）。

**注意**：新页面采用**实时保存**语义（与 `GeneralPage` / `ToolsPage` 一致），不受底部「保存/取消」影响；该分类不注册 `PreferenceRegistry` 偏好项，故「恢复默认」按钮对此分类 disabled（可接受）。

### 3.2 L2 设置键集中登记与备份/迁移（决策 D1：B 档）

三档范围（已定 **B 档**）：

| 档 | 内容 | 工作量 | 收益 |
|----|------|--------|------|
| **A（完整）** | 新建 `SettingsSchema`：集中登记全部键（key / default / type / scope / encrypted / backupable / schemaVersion）；`SettingsService::load()` 改为按 schema 遍历；提供 `exportAll()` / `importAll()`（JSON）实现**设置导出/导入备份**；`schemaVersion` + 迁移钩子 | 大 | 一劳永逸，支撑备份与未来迁移 |
| **B（推荐）** | 新建 `SettingsSchema`：仅**集中登记键清单 + schemaVersion + 迁移钩子**，不实现导入/导出 | 中 | 消除键分散隐患，为未来迁移留路径 |
| **C（最小）** | 仅产出**文档版键清单**（`docs` 新增「设置键总表」），代码不动 | 小 | 零风险，但不解决结构性隐患 |

**已定 B**：新建 `SettingsSchema` 集中登记键清单 + `schemaVersion` + 迁移钩子，**不实现导入/导出**。与 L1 协同（L1 新增的 UI 入口键同时登记进 schema）。若后续需要"配置备份"功能再升级到 A。

### 3.3 L3 episodic 中文分词修复（决策 D4：trigram）

**方案（推荐：对齐 messages_fts 的 trigram 路线）**

1. **迁移 `episodic_fts` 为 trigram**：
   - 检测现有表 tokenizer（`sqlite_master.sql` 是否含 `tokenize='trigram'`）；未命中则 `DROP TABLE episodic_fts` → 按 `tokenize='trigram'` 重建（保持 `content='episodic'` external-content 模式）→ **从 `episodic` 全量 rebuild**（幂等，覆盖存量数据）。
   - 迁移逻辑放入 `SqliteMemory` 的初始化路径（与 `migrateMessagesFts()` 同构，命名 `migrateEpisodicFts()`）。
2. **`searchEpisodic()` 增加兜底与加固**：
   - 关键词 < 3 字符时退回 `LIKE '%kw%'` 扫描（参照 `searchMessages()` 的 `kLikeScanMaxMessages` 行数上限保护，`SqliteMemory.cpp:569-593`）；
   - MATCH 前**转义引号**并加引号包裹（参照 `searchMessages()` `:609-620`），避免非法 FTS 语法静默失败；
   - `exec()` 失败时补 `qWarning` 日志（当前静默）。
3. **测试**：`tests/test_episodic.cpp` 新增 CJK **子串**用例（如摘要含"信号槽"，查询"信号"应命中），并保留既有整词用例回归。

**备选**：保持 unicode61，仅在检索侧做 n-gram 查询扩展。**不推荐**（复杂度高、与 messages 方案不一致）。

**风险**：trigram 索引体积增大；external-content 表迁移需重建索引（一次性，本地 DB 规模可控）。

### 3.4 L4 搜索后端接线与扩展（决策 D2：仅修接线，不新增后端）

**方案（已定：工厂 + 接线 + 校验；不新增第二后端）**

1. **后端工厂**：新增 `createWebSearchBackend(const QString& providerKey)`（返回 `std::unique_ptr<WebSearchBackend>`），未知 provider 回退 `tavily` 并告警。
2. **接线（核心修复）**：`main.cpp` 按 `settings->webSearchProvider()` 创建 backend 并构造 `WebSearchTool`；监听 `webSearchProviderChanged` 时重建工具（或让 `WebSearchTool` 支持 `setBackend()` 热切换，避免重注册）。
3. **枚举校验**：`setWebSearchProvider()` 增加合法值校验（合法集合来自后端注册表），非法值拒绝并告警。
4. **不新增第二后端（决策 D2 = 否）**：本次 provider 合法集合仍仅 `tavily`；工厂已预留扩展点，后续按需新增子类（候选：Brave Search / SearXNG / DuckDuckGo），届时仅需加实现 + 注册枚举。

**测试**：新增工厂单测（未知 key 回退 `tavily`、合法 key 映射）；`test_web_search.cpp` 补 provider 选择用例。

## 4. 任务拆分与优先级

| 波次 | 任务 | 对应遗留 | 风险 | 依赖 |

## 5. 验收标准（Done Definition）

- **L1**：设置中心「工具与记忆」独立分类可切换 episodic 开关、选择搜索 provider、录入/清除搜索密钥；重启后保持；密钥不回显明文；`qmllint_gate` 通过；双语翻译 0 unfinished。
