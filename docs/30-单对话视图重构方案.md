## 0. 问题陈述

现状是"标签栏 + 每标签一个 `ChatSessionController`"。目标是主流形态：
**主区永远只显示一条会话**，其他正在进行的会话在左侧会话栏里以动画图标提示，
点击切换。

### 0.1 排查结论：这不是重构引擎，是重构呈现

| 层 | 现状 | 结论 |
|---|---|---|
| 引擎 | `QVector<ChatSessionController*> m_tabs`，每 controller 一个独立 `AIAgent` + 独立 SQLite 连接（`main.cpp:565` 的工厂） | **已经是目标形态**，保留 |
| 主区 | `traceModel` 本来就只转发**活动** controller 的 trace（`AgentViewModel.cpp:302-305`） | **已经是"单窗口"** |
| 标签栏 | `SessionTabs.qml` 是这套引擎的一个横向视图 | 待移除 |

因此"迁移"的实际内容是：**删掉标签栏，把它的三项能力（并行会话 / 运行指示 / 切换）下沉到侧栏**。

### 0.2 现有结构暴露的四个真问题

| # | 问题 | 代码位置 |
|---|---|---|
| 1 | 同一条会话在侧栏与标签栏两处出现，互不联动；后台运行的会话在侧栏完全看不出来 | `Sidebar.qml:842`、`SessionTabs.qml:35` |
| 2 | 空白新标签不可辨识（两个空标签都叫"新会话"） | `AgentViewModel.cpp` `tabModel()` |
| 3 | 关标签 = 杀任务，与"关掉一个视图"的直觉冲突 | `AgentViewModel.cpp:496-503` |
| 4 | 忙时点会话会静默多开一个标签 | `AgentViewModel.cpp` `loadSession()` |

第 4 条不是缺陷而是**引擎约束**：`AIAgent::resumeSession` 在 `m_active` 时直接返回
（`AIAgent.cpp:1104`），`ChatSessionController::loadSession` 也有 `isBusy()` 守卫
（`ChatSessionController.cpp:360`）。忙的 controller 不可能换会话，所以"后台有任务
时打开另一条会话"必然需要第二个 controller。单窗口模型的正确表达是：多出的是
**后台 controller**，而不是多出一个**可见窗口**。

## 1. 目标模型

| 概念 | 定义 |
|---|---|
| **打开集合** | 持有 controller 的会话，可以有多个；后台可并行运行 |
| **活动会话** | 唯一，= `m_activeTab` 那个 controller，主区渲染它 |
| **切换** | 点侧栏行 → 已打开则激活（不碰 DB、不打断任务）；未打开则加载 |
| **运行指示** | 侧栏行内的动画图标，任意 controller busy 都显示（含后台） |
| **关闭** | 显式动作：停任务 + 释放 controller，**不删数据** |

## 2. P0 · 数据面（已实施）

### 2.1 新增 API

```cpp
Q_INVOKABLE void openConversation(const QString& sessionId);
Q_INVOKABLE void closeConversation(const QString& sessionId);
Q_INVOKABLE void clearConversationUnread(const QString& sessionId);
static constexpr int kMaxOpenConversations = 12;
```

`openTab/closeTab/activateTab/tabModel` **全部保留**：它们验证的是引擎的会话隔离性
（每标签独立 agent / 独立连接 / 归属隔离），语义不随 UI 迁移改变，现有 8 个用例
（`test_viewmodel.cpp`、`test_chat_workflows.cpp`、`test_session_template_qml.cpp`）
继续有效。改名会牵动 `main.cpp:565` 的工厂链、`closeAllTabs` 的"无信号"契约
（`AgentViewModel.cpp:415-424`）与数据库恢复编排（`:1826`），收益为零。

### 2.2 `openConversation` 的三步

1. **已被承载** → `activateTab` 到它，清未读，推进 LRU。后台 busy 的会话由此切
   回来，任务不中断（`activateTab` 不碰 agent）。
2. **没有承载者** → 就地复用或新建：
   - 活动 controller 空闲**且无草稿** → 就地换内容（复用）
   - 否则找空闲的空壳 controller → 复用
   - 都没有 → 守上限后 `addTab`；上限已满且无可淘汰对象 → `noticeOccurred` 明确拒绝
3. **归属同步** → 按目标会话的 `projectId` 调 `applyProjectTo` 再 `loadSession`，
   避免打开瞬间徽标/沙箱指向旧值。

**为什么"空闲时点一条会话"必须就地复用**：每个 controller 背一条独立 SQLite 连接
（`main.cpp:572` 的 `setOwnedMemory`）+ 最多 800 条 trace 节点恢复
（`AIAgent.cpp:55`）。若浏览历史也新建，翻九条旧会话就会撞上上限，然后开始淘汰——
不可接受。

**为什么有草稿时不能就地复用**：草稿属于它所在的那条会话，就地换内容会把草稿带到
另一条会话上。此时保留原 controller（`conversationPinned` 已钉住它，不会被淘汰），
另起一个承载目标会话。

### 2.3 `sessionList` 富化（读取时叠加，不写进数据库快照）

```jsonc
{ id, title, projectId, pinned, archived, updatedAt, timeText,  // 已有
  open: true, active: true, busy: true, hasDraft: true, unread: false }
```

叠在读取端而非 `refreshSessions` 的写入端：`busy/unread` 随任务变化而数据库快照不变，
写进快照会反复失效重拉。通知面新增 `sessionListChanged`，在以下时机发出：
controller 状态变化（busy/hasDraft）、会话 id 变化、切换活动、关闭、打开、新建。

### 2.4 上限与淘汰

- `kMaxOpenConversations = 12`。依据：每 controller 一条 SQLite 连接（WAL +
  `busy_timeout=5000`），12 远低于 SQLite 实际压力，也在桌面内存预算内。
- 淘汰顺序：LRU 队列里最久未用的**空闲无草稿**会话 → 其次是最久未用的空白对话。
- **永不淘汰**：活动会话、`busy` 会话、有草稿/带附件的会话。
- 达上限且全部钉住 → `noticeOccurred("打开的对话过多…")`，不静默失败。

### 2.5 关闭语义（`closeConversation`）

| 情形 | 行为 |
|---|---|
| 非最后一个 | `closeTab(index)`（先 `stop()` 再 `deleteLater`），会话仍在历史里 |
| 最后一个 | **就地重置成空白对话**，而不是拒绝操作 |

"关掉最后一个 → 立刻开一个空白对话"是对 `closeTab` 的 `m_tabs.size() <= 1` 守卫的
语义替换：用户点「结束对话」时必须真的结束，否则它看起来像坏了。

### 2.6 `loadSession` 的收敛

原先"忙 → 开新标签"的分支移进 `openConversation`，并补上清未读与 LRU 推进。保留
`loadSession` 作为内部入口（搜索定位 `revealMessage` 走它），两个入口不再各写一份
判断，避免语义分叉。

### 4.2 两个实测发现

   加载到上一版 QML。改动组件后若行为与源码不符，先 `--target clean` 重建。

## 5. P1 处理的四个坑（结论）

1. **会话模板入口变少一条。** → 已在 TopBar 补 `templateEntry`（图标
   `preset`，无模板时隐藏），`onManageRequested` 经 `TopBar.templatesRequested` →
   `AgentChatPage` → `main` 打开设置中心 prompts 分类。
2. **`active()` 无保护**（`m_tabs.at(m_activeTab)`）：`closeAllTabs`/数据库恢复期间
   不能发任何信号。新 API 已遵守同一栈内约定。
3. **`detailState` 跨会话串味（已修）**：改为 `detailStateBySession`（外层键
   sessionId），`detailState` 变成按当前会话取值的绑定。回归用例
   `transcriptDetailStateIsPerConversation` 锁住"A 折叠 'k' 不影响 B"。
4. **托盘「新建会话」语义不一致**：`main.cpp:948` 调 `newChat()`（reset 当前），而侧栏
   按钮调 `newLocalChat()`（开新 controller）。**未统一**——刻意保留：托盘菜单项叫
   「新建会话」，在单窗口下 reset 当前是最小惊讶的行为，改为开新 controller 会让
   "一个窗口"的直觉反而被破坏。留作后续观察项。
