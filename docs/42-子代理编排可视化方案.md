## 1. 结论摘要

| 结论 | 说明 |
|---|---|
| **可行** | 现有 `BackgroundTaskHub`、`SubAgentRunner`、`LLMResponse`、`PricingCalculator`、`token_usage` 已提供大部分原料 |
| **不能直接画“完整 DAG”** | 当前架构禁止子代理递归派生子代理（`spawn_agent` 只在主代理暴露），图是“主代理 + N 个子代理”的星型；用 `parentTaskId` 预留未来嵌套 |
| **同步子代理不在 Hub** | 同步 `spawn_agent` 的内联执行只出现在对话流 ProcessCard；若只扩展 Hub，编排图会漏掉同步子代理 |
| **成本归因缺字段** | `SubAgentReport.tokensUsed` 只有总数；需补 input/output/cache/model，才能用 `PricingCalculator` 算准 |
| **推荐架构** | 新增 core 层 `OrchestrationRecorder`（会话级事件/节点/边/成本），由主代理任务、同步子代理、后台 Hub 共同写入；UI 读统一快照 |
| **推荐 UI** | 在现有 `BackgroundTasksDialog` 顶部增加“任务 / 编排 / 时间线 / 成本”四个 Tab；列表保持默认，避免回归 |

## 3. 目标 / 非目标

### 目标

1. **编排图**：主代理根节点 + 子代理节点；状态/角色/步骤/Token/耗时/成本徽标；点击节点联动详情。
2. **时间线**：每个节点的排队、等槽、思考、工具、等待、完成区间；支持缩放与横向滚动。
3. **成本**：每个子代理 input/output/cache/tokens/费用；子代理合计；主代理会话区间参考值。
4. **同步 + 后台子代理统一**：同步 `spawn_agent` 与后台任务都进入同一编排快照。
5. **当前会话实时刷新**：250–500ms 节流；会话切换清空；可导出 JSON。
6. **零回归**：现有任务列表/详情、取消/停止、ProcessCard 行为不变。

### 非目标（本期）

- 跨会话历史持久化（DB 表）、跨 run 对比。
- 子代理递归派生（当前架构不支持）。
- 工具级火焰图/每次 LLM 调用的独立条（时间线先到 phase/step）。
- 供应商账单核对；成本是估算值。
- 独立新窗口（优先集成现有对话框）。

## 4. 推荐架构：OrchestrationRecorder

### 4.1 为什么不直接扩展 Hub

| 方案 | 问题 |
|---|---|
| 只扩展 `BackgroundTaskHub` | 同步子代理不在 Hub；Hub 职责变成“执行 + 观测 + 成本”，膨胀 |
| 只读 trace 节点 | trace 无 start/end/token/cost；同步/后台结构不同 |
| 新 `OrchestrationRecorder` | 统一事件源，Hub/主代理/同步 Runner 都只上报；UI 只读快照 ✅ |

### 4.2 数据流

```text
AIAgent.startTask ──► recorder.runStarted(main)
SubAgentTool(sync) ─► recorder.nodeCreated/running/progress/finished
BackgroundTaskHub ──► recorder.nodeCreated/running/progress/wait/finished
SubAgentRunner ─────► usage (input/output/cache/model) 随 report 返回
recorder ──► AgentViewModel.orchestrationSnapshot() ──► QML
```

- `OrchestrationRecorder` 归 GUI 线程或线程安全（Hub worker 会写入）；建议内部 `QMutex` + 事件 ring。
- 通过 Router（类似 `BackgroundTaskHubRouter`）让 `SubAgentTool`/Hub 获取当前会话 recorder；无 recorder 时 no-op（测试/宿主兼容）。
- UI 仍从 Hub 读任务列表；编排 Tab 从 recorder 读统一快照。

### 4.3 线程与生命周期

| 项 | 规则 |
|---|---|
| 线程 | Hub worker / 同步工具池线程可写 recorder；写入加锁，快照拷贝 |
| 会话 | recorder 按 sessionId 隔离；`resetSession`/切换清理 |
| 上限 | 每会话 64 节点、2000 事件；超出丢弃最旧事件并标记 `trimmed` |
| 刷新 | recorder 发 `changed`；VM 250ms 合并发 `orchestrationChanged` |
| 销毁 | 归 GUI 线程；worker 只持 weak/shared 安全句柄 |

## 5. 数据模型

```cpp
struct OrchestrationUsage {
    int promptTokens{0};        // 与主代理口径一致：prompt + cacheCreation
    int completionTokens{0};
    int cacheHitTokens{0};      // cached + cacheRead
    qint64 costCents{0};
    bool pricingKnown{false};
    bool estimated{false};      // 只有 tokensUsed 回退
};

struct OrchestrationEvent {
    qint64 ts{0};
    QString taskId;             // "main" 或 "sa-N"
    QString type;               // created/queued/running/slot_wait/progress/wait_begin/wait_end/finished/cancelled/expired
    QString phase;              // thinking/tools/...
    QString detail;
    int step{0};
    int maxSteps{0};
};

struct OrchestrationNode {
    QString id;                 // main | sa-N
    QString parentId;           // main；未来嵌套时为父 sa-N
    QString sessionId;
    QString role;               // primary / explore / coder / ...
    QString goal;
    QString model;
    QString source;             // sync | background
    QString state;              // queued/running/waiting/done/failed/cancelled
    qint64 createdAtMs, runningAtMs, finishedAtMs;
    int steps, maxSteps, proposalCount;
    OrchestrationUsage usage;
    QString error;
};

struct OrchestrationEdge {
    QString from;               // main / parent
    QString to;
    QString type;               // spawn | wait | parent
};
```

- 节点 `main` 为合成根：`id="main"`，`role=primary`，`parentId=""`。
- 边：
  - `spawn`：主代理 → 子代理（同步/后台都有）。
  - `wait`：主代理 `subagent_wait` 期间的等待依赖（虚线）。
  - `parent`：预留嵌套子代理。
- 当前图是星型；UI 标题写“编排图”，不写“多层 DAG”。

## 7. 成本模型

### 7.1 子代理精确成本

```text
input      = promptTokens + cacheCreationTokens
cacheHit   = cachedTokens + cacheReadTokens
output     = completionTokens
costCents  = PricingCalculator::calculateCost(
                 model, input, output, cacheHit,
                 inputPrice, outputPrice, cacheHitPrice)
```

- 定价来自 `model_pricing`（`PricingCalculator::getPricing`）。
- 未知模型/本地模型：`pricingKnown=false, costCents=0`，UI 显示“未定价”，不伪造价格。
- 只有 `tokensUsed` 的旧服务/假服务：`estimated=true`，input=0、output=tokensUsed，UI 标“估算”。

### 7.2 主代理参考成本

- 用 `sessionTokenBreakdown(sessionId)` 或 `tokenUsageRecords(from,to)` 在本次编排时间窗口内求和 `costCents`。
- 并行阶段主代理也在产生调用，这部分属于主任务，不是子代理；UI 单列“主代理（会话区间参考）”，不与子代理相加成“精确总额”。
- 页面明确文案：“子代理成本为精确归因；主代理为会话区间参考”。

## 9. API / VM

```cpp
// core/agent/OrchestrationRecorder.h
class OrchestrationRecorder : public QObject {
    Q_OBJECT
public:
    void runStarted(const QString& sessionId, const QString& model, qint64 ts);
    QString nodeCreated(const NodeInit& init);   // returns id
    void nodeRunning(const QString& id, qint64 ts);
    void nodeProgress(const QString& id, const QString& phase,
                      const QString& detail, int step, int maxSteps, qint64 ts);
    void waitBegin(const QString& taskId, qint64 ts);
    void waitEnd(const QString& taskId, qint64 ts);
    void nodeFinished(const QString& id, const OrchestrationUsage& usage,
                      const QString& state, const QString& error, qint64 ts);
    QVariantMap snapshot(const QString& sessionId) const;
signals:
    void changed();
};

// AgentViewModel
Q_INVOKABLE QVariantMap orchestrationSnapshot() const;
Q_INVOKABLE bool exportOrchestrationJson(const QString& path);
signals: void orchestrationChanged();
```

- 快照 map：`{runStart, now, nodes[], edges[], events[], cost{subagentsCents, mainReferenceCents, totalTokens, pricingKnown}, trimmed}`。
- QML 不直接持有 recorder；只读 VM 快照，保证线程边界。

## 11. 测试与验收

### 单测

- recorder：节点/边/事件、会话隔离、ring 上限、cancel/expire、嵌套预留。
- usage：input/output/cache 累加、只有 tokensUsed 的估算回退、未知定价。
- cost：正常/缓存/未知模型/零 token。
- VM：快照键、主参考成本窗口、导出。

### QML

- 四个 Tab 可见、默认“任务”、切换不丢选中。
- 编排：1 root + N 节点、spawn/wait 边数量、状态色、点击联动。
- 时间线：泳道数、区间起止、缩放、空态。
- 成本：行数、合计、未定价文案、占比重。
- 既有任务列表/详情/取消/停止回归。

### 端到端验收

1. 主代理发起 1 个同步 + 2 个后台子代理（含一个等待槽位）。
2. 编排图显示 root + 3 节点，spawn 边 3 条，wait 边正确。
3. 时间线显示 queued/slot_wait/thinking/tools/finished。
4. 成本表显示每个子代理 tokens/¥；主代理参考值单独标注。
5. 取消一个 → 节点变 cancelled，时间线截断；全部结束 → 汇总更新。
6. 切换会话 → 编排视图清空，不串台。
7. 全量 `ctest -j2` 59/59 + panel 1/1。

## 12. 风险

| 风险 | 缓解 |
|---|---|
| Hub worker 线程写事件 | recorder 加锁 + 快照拷贝；不改 Hub 现有锁顺序 |
| 同步子代理生命周期短 | 完成即写入，UI 通过 recorder 历史仍可见 |
| 无嵌套子代理，DAG 名不副实 | 标注“编排图”；`parentId` 预留，未来支持嵌套后再称 DAG |
| 成本不准 | 明确“子代理精确/主代理参考”；未知定价显示未定价；估算标记 |
| 主代理与子代理 token 口径混用 | 复用主代理 `prompt+cacheCreation` / `cached+cacheRead` 口径 |
| 事件 ring 丢历史 | 2000 上限 + `trimmed` 标记；历史持久化后续 |
| 高频刷新卡 UI | 250–500ms 节流；Canvas 局部重绘；节点对象复用 |
| 现有面板回归 | 新功能放新 Tab；“任务”Tab 原样保留；QML 夹具覆盖 |
