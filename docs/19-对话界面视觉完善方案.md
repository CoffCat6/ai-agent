## 0. 问题陈述

### 0.1 现象

使用者反馈："对话区毫无美感，只有单一的文字输出显示。"

### 0.2 根因

对话区**没有「消息」这个概念**。所有节点（用户消息 / 思考 / 工具调用 / 工具结果 / 助手回复 / 错误 / 指标）共用同一个 delegate（`src/ui/components/AgentTraceNode.qml`），只有节点的**类型标签文字**和**状态点颜色**不同，其余排版完全一致：

- 全部节点跑在同一条 2px 时间轴上（`AgentTraceNode.qml:70-77`，`x: 11`），视觉上是一条单调的竖直灰线贯穿整屏。
- 正文除用户消息外一律用等宽字体（`AgentTraceNode.qml:215`），助手回复与工具输出无法一眼区分。
- 节点占满整个列表宽度（`AgentChatPage.qml:177`），无气泡、无对齐差异、无最大宽度约束，长回复在宽屏上横跨整个窗口。

### 0.3 结论

不是"调色不够好看"，而是缺一整个**消息呈现层**。因此本方案不做事后贴图式微调，而是引入气泡对话流：把 delegate 从"单体时间轴节点"拆成"按节点类型分派的消息组件"，并配套扩展设计令牌层、富文本/代码块样式与过程卡片。

## 1. 目标与原则

1. **用户 / 助手二元区分**：用户消息右对齐气泡，助手回复左对齐全宽正文，一眼可辨。
2. **过程信息降级**：思考 / 工具调用 / 结果以可折叠卡片附着在助手回复之上，默认折叠，不干扰正文阅读。
3. **令牌先行**：所有颜色 / 间距 / 圆角 / 动效先从 `ThemeProvider` 出（暗亮各一值），QML 不出现魔法数字。
4. **数据契约不动**：`TraceModel` 的 role（`TraceModel.cpp:29-40`）与 `AIAgent` 的节点结构（`AIAgent.cpp:229-249`）保持不变；呈现层只读 `modelData.type` 分派。
5. **性能不退化**：流式期间不整表重绘；`MultiEffect` 不挂在高频变更的 delegate 根节点上。
6. **可访问**：正文对比度 ≥ WCAG AA（4.5:1）；自定义控件补 `Accessible.*`。

## 3. 设计令牌层扩展

### 3.1 放置位置与理由

| 令牌类别 | 放置位置 | 理由 |
|---|---|---|
| 颜色（气泡 / 卡片 / 代码 / 文本三级色 / 边框 / 阴影色） | **C++ `ThemeProvider.h`** | 暗/亮两套值、随 `ThemeManager` 的 `themeChanged` 全局通知；QML 侧引用 `Theme.*`，与现有 11 个颜色令牌一致 |
| 间距刻度（space.xs…xl） | **C++ `ThemeProvider.h`** | 纯数值、主题无关，但集中一处便于走查；放 C++ 可被 `CodeHighlighter.cpp` 等非 QML 侧复用（若将来需要） |
| 圆角刻度（radius.sm/md/lg/bubble） | **C++ `ThemeProvider.h`** | 同上；避免再出现 `radius: 4/6/8` 混用 |
| 动效时长与缓动 | **C++ `ThemeProvider.h`（时长）+ QML 内联（缓动）** | 时长是纯数值，与颜色令牌同处一处利于走查；缓动曲线（`Easing.*`）是 QML 枚举，直接在 QML 内联 |
| 最大内容宽度、气泡最大宽度比例 | **C++ `ThemeProvider.h`** | 与颜色同源，避免再引入 QML 单例与登记成本 |

> 决策（实施修订）：**全部令牌统一由 `ThemeProvider.h` 暴露为 `Theme.*`**，不新增 `Motion.qml` / `Metrics.qml` 单例。理由：令牌集中一处、单一事实源，且免去 QML 单例的 `pragma Singleton` + `CMakeLists` 登记成本；缓动曲线仍在 QML 内联（C++ 传枚举字符串不划算）。

### 3.2 颜色令牌（新增，暗亮各一值）

所有值已用 WCAG 2.1 相对亮度公式实测，标注对比度。

| `bubbleAssistant` | `#13131A` | `#FFFFFF` | 助手气泡背景（复用 `bgSecondary` 值，单列名以表达语义） | 同上 |

**文本三级色（修正 D12）**

| 令牌 | 暗色 | 亮色 | 用途 | 实测对比度 |
|---|---|---|---|---|
| `textPrimary`（保持不变） | `#E4E4ED` | `#1F2329` | 正文 | 对 `bgPrimary`：14.63 / 14.70（AAA） |
| `textSecondary`（**亮色值下调**） | `#8A8A9F`（不变） | **`#5C6673`**（原 `#8F959E`） | 辅助说明、时间戳 | 对白底：5.47 / **5.83**（AA）；原亮色值 3.02 **不达标** |
| `textTertiary`（新增） | `#6E6E85` | `#8A9099` | 极弱提示（如"已折叠 · N 字符"） | 对 `bgPrimary`：3.98 / 3.22（仅用于大号或非必要信息，见注②） |

**注①**：气泡背景与 `bgPrimary` 的对比度天然很低（1.0~1.5），这是所有气泡式 UI 的共性——它们靠**位置（对齐）+ 形状（圆角）+ 头像/标识**三重冗余区分，不依赖颜色对比。WCAG 1.4.11 针对"识别组件所必需的视觉信息"，本方案通过对齐与标识满足，故不强制气泡底色达 3:1。若审计要求严格，可将 `cardBorder` 提到 `#606080`（暗，对卡片底 3.12）与 `#9BA5B1`（亮，对白底 2.5，仍不足）——亮色侧无论如何都难以在"柔和"与"3:1"间两全，建议保留柔和值并在验收记录中说明取舍。

**注②**：`textTertiary` 仅用于"已折叠提示""耗时"等**冗余信息**（正文已含同等信息），故允许 3:1~4.5:1；若文案承载唯一信息则必须改用 `textSecondary`。

## 5. 富文本、代码块与过程信息规范

### 5.1 Markdown 渲染增强

现状：`AgentTraceNode.qml:292-307` 用 `TextEdit` + `MarkdownText`，仅吃 Qt 内置 Markdown 子集，样式由 `TextEdit` 的默认派生（`color: textPrimary`）。问题：

- 标题、列表、引用、表格全部同字号、同颜色，层级塌陷。
- 行内代码与代码块无背景区分。
- 无链接色。

方案：
1. **保持 `TextEdit.MarkdownText`**（不引入第三方 Markdown 库，避免重依赖）。
2. 通过 `TextEdit` 的 `textDocument` + `QSyntaxHighlighter`（**复用现有 `CodeHighlighter` 机制**，`src/viewmodels/CodeHighlighter.cpp`）对 Markdown 结构着色：标题→`textPrimary` + 加粗、引用→`textSecondary` + 左侧竖线、行内代码→`cardHeaderBackground` 底 + `brandPrimary` 前景、链接→`brandPrimary` + 下划线。
3. 表格与任务列表：Qt 内置支持有限，**标注为待确认**（见 §10）；若内置渲染不佳，接受"可读但朴素"，不做自研 Markdown 引擎。
4. `onLinkActivated` 已存在（`AgentTraceNode.qml:307`），保留。

### 5.2 代码块增强（修 D13）

现状 `CodeBlock.qml`：`radius: 4`、单色 `bgColor`（默认 `surfaceHover`）、左侧 3px `brandPrimary` accent 条、`fontSizeCaption`。

目标：
1. 外层：`codeBackground` + `radius.md`（升级自 4）。
2. 标题栏：`cardHeaderBackground`，左侧显示**语言标签**（由 `CodeHighlighter::detectLanguage` 结果反查——需给 `CodeHighlighter` 暴露一个 Q_PROPERTY `languageName`，属小改），右侧 `CopyButton`。
3. 正文区：`TextEdit` 保持 `PlainText` + `CodeHighlighter`（`CodeBlock.qml:54`），新增**行号槽**（可选，`Metrics` 开关默认关）。
4. 流式期间：代码块随内容增长，语言标签在检测稳定前显示 `…`，避免抖动。
5. 行数阈值：超长块（现状 `CodeHighlighter.cpp` 的 `MaxChars`/`MaxLines` 已降级为纯文本）保留折叠 + "查看全部"。
6. `MultiEffect`：代码块不加阴影（避免大量 delegate 上的 GPU 成本）。

### 5.3 过程信息层级

- **默认折叠**思考与工具卡片，只露标题行；用户点击展开。
- 页面级"思考过程"开关（`AgentChatPage.qml:188-240`）保留为**总开关**，作为组件默认展开态的上游：关闭时不渲染过程卡片（现状行为），开启时按卡片逐条折叠。
- 过程卡片与助手正文之间用 `space.md` 分隔，形成"折叠区 / 正文区"的视觉断点。
- 错误与 `waiting_confirm` **不受折叠开关影响**（保持现状 `AgentTraceNode.qml:32-33` 的逻辑）。

### 5.4 性能取舍（MultiEffect）

| 位置 | 是否用 MultiEffect | 理由 |
|---|---|---|
| 气泡 / 卡片 | ✅ 仅亮色启用轻阴影（blur 半径小） | 静态，悬停才重绘，成本可接受 |
| 代码块 | ❌ | 流式高频变高，避免每帧重算 |
| 状态点呼吸 | ❌ 用 `Rectangle` 透明度动画（现状 `AgentTraceNode.qml:96-101`） | 零 GPU 特效成本 |
| 流式正文光标 | ❌ 用 2px `Rectangle` + `OpacityAnimator` | 同上 |

**原则**：`MultiEffect` 只用于**不随流式变化的静态容器**。若实测帧率下降，退路是改用"边框 + 底色分层"（零特效）。

## 9. 反目标与风险

### 9.1 明确不做

1. **不改数据契约**：不动 `TraceModel` role、`AIAgent` 节点字段（除 D16 的白名单补丁）、`ChatSessionController`。
2. **不引入第三方依赖**：不引 Markdown 库、不引动画库、不引 UI 框架；特效只用 Qt 6 自带 `MultiEffect`。
3. **不换配色体系**：保留品牌青 / 蓝主色与暗亮双主题，只做分层与令牌化。
4. **不做全产品换肤**：设置页 / 侧栏 / 日志面板不在本次范围（仅同步令牌引用）。
5. **不做虚拟滚动重构**：现有 `ListView` + `TraceModel` 增量更新保留，不引入 `TableView` 或自定义回收。
6. **不为美化牺牲性能**：任何导致流式帧率下降的特效一律退回零特效方案。
7. **不改 Agent 行为**：纯呈现层，不因视觉需要去改 ReAct 循环、工具确认或 token 逻辑。

### 9.2 风险清单

| 风险 | 等级 | 缓解 |
|---|---|---|
| 亮色 `textSecondary` 下调影响面广，观感突变 | 中 | 挪到 V7 单独 commit；先全局走查引用点 |
