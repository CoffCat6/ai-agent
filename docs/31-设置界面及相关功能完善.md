## 1. 一句话结论

设置中心已经跨过"能用"的门槛：目录化搜索、跳转高亮、即时保存回执、整页复位、设置导入导出、数据库备份恢复、诊断包、用量导出都已具备。剩余问题集中在两类：

1. **看不见**——看不到哪些设置改过、搜不到当前值、看不到已有备份、看不到日志；
2. **进不去**——没有全局复位、没有首次启动向导、快捷键仍是硬编码。

因此本轮优先级应是"先让已有能力可见、可达"，再补新入口。

## 3. 优化项（O1–O11）

> 优先级：高 = 直接影响日常使用；中 = 体验提升；低 = 锦上添花。
> 成本：小（≤0.5 天）/ 中（1–2 天）/ 大（3 天+）。

### O1 [高/中] 恢复默认只到"整页"，且看不到"改过什么" ✅ S1

- **现状**：底栏「恢复本页默认值」按分类整体复位（`SettingsCenterDialog.qml:99-132`）；`EditBuffer::resetAllToDefault()` 已实现但**全库无调用方**（`EditBuffer.h:53`）；页面上没有任何"此项已修改"的标识。
- **缺口**：
  - 只想改回一个字段，却要把整页都复位；
  - 不知道当前页哪些值与默认不同；
  - 没有"恢复全部设置"的入口。
- **方案**：
  1. **统一默认值来源**：偏好键取 `PreferenceRegistry.preferenceMeta(key).defaultValue`（与 `SettingsSchema` 同源）；M1 键复用页面已有的 `reset*Defaults` 默认表（`test_settings.cpp:712-846` 已断言它们与 schema 一致），**不要在 UI 里另写一份默认值**。
  2. **行级复位**：在 `SettingRow` / `PreferenceControl` 右侧增加"已修改"小圆点 + 悬浮「复原」按钮；仅当值 ≠ 默认时出现。点击即 `EditBuffer.stage(key, default)` 或调用页面单键复位函数，沿用即时保存回执。
  3. **导航徽标**：`CategoryNav` 每个分类右侧显示"已修改 N 项"（数据来自新增的 `SettingsCatalog.modifiedCount(category)` 或 QML 侧逐键比较）。
  4. **全局复位**：底栏在"恢复本页默认值"旁增加「恢复全部设置」，调用 `EditBuffer.resetAllToDefault()`；确认弹窗列出将受影响的分类数，并明示"已加密的密钥不会被清除"。
- **约束**：密钥字段**不提供**行级/全局复原；清除密钥只能走页面上的「清除密钥」按钮（见 §6 红线 1）。
- **验收**：
  - 改动任一偏好 → 所在分类出现"已修改 1"，行级复原按钮出现；
  - 点击行级复原 → 控件回默认、徽标消失、底栏一条「已保存」；
  - 恢复全部 → 所有偏好回默认，`test_settings` 断言 API Key 字段值保持不变；
  - 批量复位期间只显示一条回执（复用现有 `suppressSaveStatus`）。

### O2 [高/中] 搜索只匹配元数据，不显示当前值、无高亮、无相关度 ✅ S1

- **现状**：`SettingsCatalog::search()` 的 haystack 是 `title + keywords + id + categoryName`（`SettingsCatalog.cpp:378-405`），结果按分类顺序排序；结果行只渲染 `title` + `categoryName`（`SettingsCenterDialog.qml:511-537`）。
- **缺口**：
  - 用户搜到条目后仍不知道当前值是什么，还要点进去确认；
  - 命中词没有任何视觉提示；
  - 标题命中与关键词命中权重相同，结果顺序不直观。
- **方案**：
  1. `search()` 返回结果补充三个字段：
     - `currentDisplay`：当前值摘要（Bool → 开/关；Enum → 本地化标签；Int → 数字；String → 截断 24 字；**`def.encrypted` 的键固定显示"已配置/未配置"**，取值前先查 `SettingsSchema::definition(key)->encrypted`）；
     - `highlightStart` / `highlightLength`：标题内命中区间（没命中返回 -1）；
     - 结果按权重排序：title 100 > keywords 60 > id 40 > categoryName 20，同分再按分类顺序。
  2. 结果行渲染：标题高亮 + 值摘要 + "已修改"小标记（与 O1 共用比较函数）。
  3. 可选：为高频中文词补拼音别名（如 `moxing`、`daili`），只在静态表里手工维护，不引入通用拼音库。
- **验收**：
  - 搜"智谱"时密钥类结果显示"已配置/未配置"而非明文；
  - 标题命中高亮；同一查询两次结果顺序稳定；
  - 扩展 `test_settings.cpp:2678` 覆盖权重排序与敏感值掩码。

### O3 [高/中] 备份页看不到已有备份 ✅ S1

- **现状**：恢复必须先点「预览备份文件…」手动选文件（`SettingsBackupPage.qml:96-120`）；后端只有 `lastDatabaseBackupPath()` 返回最新一份路径（`AgentViewModel.h:531`），另有 `previewDatabaseBackup` / `restoreDatabaseFrom`（`:525`、`:529`）。
- **缺口**：`<app-data>/backups` 下明明有启动自动生成的 N 份 `auto_*.db`（`SqliteMemory.h:207-217`），用户却看不见、选不对、也删不掉旧备份。
- **方案**：
  1. 新增只读接口 `AgentViewModel::databaseBackups()`（或 `SqliteMemory::listBackups()`）→ `[{path, fileName, sizeBytes, mtimeMs, isAuto}]`，按 mtime 倒序。
  2. 备份页改为列表：时间 / 大小 / 自动或手动 / 「预览」「恢复」「删除」「打开目录」。
  3. 「恢复」复用现有确认弹窗（`SettingsBackupPage.qml:205-256`），先把 `previewDatabaseBackup` 结果填进摘要；损坏文件只允许预览不允许恢复（沿用现状）。
  4. 「删除」二次确认，并**校验路径位于备份目录内**，防止路径穿越删除任意文件。
- **验收**：
  - 启动自动备份 3 份后列表显示 3 条且倒序；
  - 恢复/删除后列表即时刷新；
  - 新增单测覆盖排序、`isAuto` 识别与路径校验。

### O4 [中/中] 导入预览太粗，没有逐键差异 ✅ S2

- **现状**：`parseImport()` 只返回 `sections`（"应用设置（N 项）"等）、`skippedSecrets`、`warnings`（`SettingsBackup.cpp:423-433`）；页面原样展示（`SettingsBackupPage.qml:288-325`）。
- **缺口**：用户点「确认恢复」前不知道哪些键会被覆盖、覆盖成什么。
- **方案**：
  1. `parseImport()` 增加 `changes`：`[{key, categoryId, title, currentDisplay, importedDisplay, secret}]`；与当前值逐键比较，**只列发生变化或新增的键**，最多返回 200 条并附 `changesTruncated` 计数。
  2. 敏感键（`encrypted`）只显示"当前：已配置 / 备份：未包含"，不显示任何值。
  3. 确认弹窗改为"变更列表 + 「仅显示变化」开关 + 分类折叠"，原有 warnings 保留在底部。
- **验收**：
  - 构造一个改了 3 个键的备份，diff 恰列 3 条；
  - 密钥不泄露；
  - `test_settings_backup` 增加 diff 用例（完全一致 → 0 条）。

### O5 [中/小] 不能按分类导出 ✅ S2

- **现状**：`buildExportPayload()` 无参数、固定导出全部可移植键 + 模型配置 + MCP（`SettingsBackup.cpp:164-243`）；页面只有全量导出（`SettingsBackupPage.qml:72-93`）。
- **缺口**：只想迁移"模型配置"或"工具禁用清单"时，必须导出全量再人工删减，容易误带其他配置。
- **方案**：
  1. `buildExportPayload(const QStringList& categories = {})`：按 `SettingsCatalog.entry(key).category` 过滤 `settings` 键；`profiles` 归 `model`，`mcpServers` 归 `mcp`；空列表 = 全量。
  2. `exportSettings(path, categories)`；页面导出卡片加分类多选（默认"全部设置"）。
  3. 导入侧不改：分类子集仍是合法的全量格式，`parseImport` 已按数组/键解析。
- **验收**：导出"模型配置"文件只含 `modelProfiles` / `activeProfileId` 等模型键 + `profiles`，不含其他键；该文件可被现有导入流程恢复。

### O6 [高/中] 日志页只能"打开目录" ✅ S2

- **现状**：`LogsPage.qml` 只有日志级别、目录、轮转参数与「打开目录」（`:88`）；查看内容必须用外部编辑器。
- **缺口**：用户反馈问题时无法在应用内确认"刚才那步到底报了什么"。
- **方案**：
  1. 新增只读接口（建议独立于 AgentViewModel）：`readLogTail(maxLines, minLevel, keyword)`，只读文件尾部若干 KB，避免整文件进内存；超长行截断（如 2,000 字符）。
  2. UI：最近日志面板（默认 200 行，最大 2,000）+ 级别下拉 + 关键字过滤 + 「跟随最新」开关（`QFileSystemWatcher` 或 2 秒定时）。
  3. 复用 `Logger::logDir()`，与诊断包走同一路径解析。
- **验收**：切换级别/关键字后列表过滤正确；日志追加后 2 秒内出现在底部；1 GB 日志文件不卡 UI（用尾部读取验证）。

### O7 [中/小] 切页即销毁，滚动位置与输入状态全丢 ✅ S1

- **现状**：16 个 `Loader` 的 `active` 全部绑定 `currentCategory === id`，切走即销毁重建（`SettingsCenterDialog.qml:597-721`）。usage / activity 两页是**刻意**绑定 `dialog.opened` 关闭即销毁，以刷新统计（`:680-696`）。
- **方案**：
  1. 增加 `visited` 记录：首次访问后保持 `active`，仅切换 `visible`；usage / activity 维持现状。
  2. 若担心内存，用最近 4 页的 LRU 上限（`ModelConfigPage` / `PromptAssetsPage` 较重）。
- **验收**：在"界面与外观"改字号 → 切到"模型配置" → 切回，滚动位置与未提交控件状态保留；usage 页仍每次打开重新拉取。

### O8 [低/中] 对话框尺寸固定 900×680 ✅ S4.1

- **现状**：`width: Math.min(900, parent.width - 24)`、`height: Math.min(680, parent.height - 24)`（`SettingsCenterDialog.qml:16-17`）。
- **方案**：记住上次尺寸（新增 `ui.settingsDialogWidth/Height` 两个偏好键并登记 schema + catalog + 双语），加拖拽边框或角标；窄屏 clamp 逻辑保留。不愿加键时可先只做"最大化/还原"按钮，不持久化。
- **验收**：调整后关闭再打开尺寸保持；窗口缩小后仍能 clamp 回可视区。
- **落地**：两个键按**隐藏偏好**（空分类）登记，尺寸由右下角 `settingsResizeHandle` 拖动修改，只在关闭时落盘；详见 §16.2 S4.1。

### O9 [低/小] 字体下拉不可搜索，等宽列表混入非等宽字体 ✅ S3

- **现状**：正文字体/等宽字体两个 `ComboBox` 直接吃 `FontProbe.availableFamilies()` 全量排序列表（`InterfacePage.qml:29-33`、`:84-105`）。
- **方案**：
  1. 可搜索下拉（editable + 过滤），或上方加搜索框过滤 model；
  2. `FontProbe` 增加 `fixedPitchFamilies()`（`QFontDatabase::isFixedPitch`），等宽下拉只列等宽字体；正文下拉对等宽项加标记。
- **验收**：输入 `Ya` 能筛到雅黑类字体；等宽下拉不含非等宽字体；切换后预览区（`InterfacePage.qml:140-178`）即时生效。

### O10 [中/中] 缺动效/密度等可访问性开关

- **现状**：主题仅 `auto/dark/light` 三档（`SettingsSchema.cpp:131-136`）；动效时长是 `ThemeProvider` 的**常量**（`ThemeProvider.h:240-247`：100 / 180 / 260 ms），全 UI 直接使用。
- **方案**：
  1. 新增 `ui.reduceMotion`（Bool，默认 false）：`ThemeProvider` 的 motion 系列改为可读写属性，`reduceMotion=true` 时返回 0；需排查所有 `Behavior`/`NumberAnimation` 的 duration 绑定，工作量集中在这里。
  2. 可选 `ui.density`（comfortable/compact）：先只作用于设置页行高与列表行高，不扩大到聊天区。
  3. 可选强调色（accent）留作后续，先不做，避免主题体系震荡。
- **验收**：开关后过渡动画消失且布局不抖；密度切换行高改变、文本不截断；新键三件套齐全。

### O11 [中/中] 设置页缺交互级回归测试 ✅ S2（部分：剩余夹具见 §14）

- **现状**：只有实例化无警告、搜索、导航折叠、主题令牌四类用例（`test_chat_workflows.cpp:495/535/567/601`），点击链路无覆盖。
- **方案**：仿 `tests/qml/ToolsPageHarness.qml` 建 `SettingsHarness.qml`：
  - 直接加载 `SettingsCenterDialog`，用 `QStandardPaths::setTestModeEnabled(true)` 隔离写盘（`test_chat_workflows.cpp:97` 已有先例）；

## 6. 红线与设计约束

以下约束来自既有约定与历史事故，任何本文件中的方案都不得违反：

1. **加密密钥**：getter 保持掩码；「恢复默认」（整页 / 行级 / 全局）**不清除**已加密密钥；设置导出不包含；清除密钥只能由页面上的「清除密钥」按钮完成。O1、N1、N4、N8 均适用。
2. **密码/密文字段**：只读控件的 `text`，绝不读 `displayText`（`displayText` 带掩码字符，回写会污染密钥）。
3. **即时保存语义**：`EditBuffer.stage` 直写 + 防抖 + `Component.onDestruction` 提交；不引入"保存"按钮，不改变关闭时 `rollback()` 的兜底（`SettingsCenterDialog.qml:270`）。
4. **secret 字段写法**：`secret + ignoreEmptySubmit + clearOnSubmit`；**空白输入 = 不修改**。
5. **新键三件套**：任何新增设置键必须同时登记 `SettingsSchema`、`SettingsCatalog`（`test_settings.cpp:2644` 会逐个断言）、双语 `.ts`；缺一即视为未完成。
6. **破坏性操作**：全局复位、删除备份、清空数据必须二次确认；删除备份前校验目标路径位于 `<app-data>/backups` 内；能先备份的必须先提示备份。
7. **测试隔离**：设置写盘测试一律用 `QStandardPaths::setTestModeEnabled(true)` 指向临时目录，禁止写真实用户配置。

- 注意：撤销只回写一次、不链式；跨分类切换后仍可撤销（记录的是键而非页面）。

**实施结果与偏差**
- **撤销点登记时机**：`stage()` 在调用 `saveBatch` **之前**记录 `{undoKey, undoHadPrevious, undoPrevious}`，失败时恢复旧记录。原因：`PreferenceStore::saved(keys)` 在 `saveBatch` 内同步发出，设置中心的回执槽必须当场看到"这次改动可撤销"，否则回执永远慢一拍。`hadPrevious` 用 `hasStoredValue()`（物理键是否存在），撤销时无旧值走 `reset()` 删键，而不是把默认值写成"已修改"。
- **只在成功写盘后保留**：校验失败分支不触碰撤销记录；`commit()`（批量）成功与两个复位入口都清空记录——批量提交无法用一次回写表达，复位后再撤销只会回到半复位中间态。
- **C++ 侧防御**：`undoLast()` 只接受 `PreferenceRegistry::hasPreference()` 的键，并用 `SettingsValue::inspect(key).secret` 拒绝密钥类；未登记键/密钥一律 clear 记录并返回 false。偏好键本身没有 secret 元数据，这条是防止未来把撤销机制扩展到 M1 键时绕过红线 1。
- **控件同步**：撤销没有改动 `staged` 映射，而控件是按 `EditBuffer.staged` 的 NOTIFY 重新求值的，所以 `undoLast()` 在成功写回后主动 `emit staged(key, load(key))` + `stagedChanged()`；InterfacePage 的 `pref()` 与 `PreferenceControl::stagedValue()` 都会重算。
- **回执寿命**：可撤销时回执 **5 秒**（N3 验收"5 秒内可点撤销"），普通「已保存」仍是 1.8 秒；错误回执 8 秒且不提供撤销。原文写的"与文案同寿命（现 1800ms）"按验收口径取 5 秒，这是本批唯一的主动偏差。
- **UI 条件**：撤销按钮同时要求 `dialog.undoAvailable`、`undoKey` 与 `EditBuffer.undoKey` 相等且 `canUndo`——后台或其它分类的写入即使恰好同键也不会借用旧撤销点；`SettingsCatalog.entry(key).secret` 再挡一次。
- **测试**：`test_settings_values` 四例（有旧值回 15、无旧值删键回默认、复位清记录、密钥/未登记键拒绝且不落盘）；`test_settings_page_qml::undoButtonRestoresPreferenceAndDisappears` 真实打开对话框 → stage → 回执出现「撤销」→ 点击 → 值回原值、按钮消失、`canUndo` 为假、回执文案含「撤销」。

**4c 按项目覆盖：方案（已关账，2026-10-31 评估后决定不做）**
> **关账理由**：核对代码发现 per-tab 模型选择（`AgentViewModel::selectChatModel`，写 `active()->modelProfile`）与 per-tab 权限模式（`setPermissionMode` 只作用于活动标签）已存在，会话模板还能按预置配置一键开会话——4c 的真实增量只剩"按项目记忆偏好并在开新标签时自动套用"。该前提（用户经常多项目并行且各项目固定用不同模型）当前不成立，而覆盖与手动选择的冲突状态机（`overrideApplied` 回退判定）是全套方案里最容易出 bug 的部分，收益低于风险。方案原文保留如下，未来使用形态变化时可重启。
