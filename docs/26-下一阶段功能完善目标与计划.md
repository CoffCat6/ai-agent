## 2. 批次 F：接通已有能力（性价比最高）

### F1 [高] `todo_write` 的任务清单在 UI 完全不可见

- **现状**：工具已实现（`src/core/tools/ToolRegistry.cpp:926` 起，schema 含 `content` / `status` / `priority`）；ViewModel 已暴露 `Q_PROPERTY(QVariantList todoList ...)`（`src/viewmodels/AgentViewModel.h:125-126`），切标签/新建标签时都会从 `active()->todoList()` 重载并通知（`src/viewmodels/AgentViewModel.cpp:432`、`:465`）；但 `src/ui` 全目录**没有任何 QML 消费 `todoList`**（grep `todo` 只命中注释）。
- **缺口**：模型按提示写了多步清单，用户只能在工具结果气泡里看到一段 JSON，无法获得"当前进度"的持续视图。
- **建议**：在 `ContextPanel` 或对话区右侧新增可折叠「任务清单」区，读 `AgentVM.todoList`；`pending / in_progress / completed` 三态配图标与删除线，`priority` 用左侧色条区分。数据链路已完整，**不改 core、不改 VM**。
- **验收**：模型调用 `todo_write` 后清单实时出现；切标签显示各自清单；任务结束后清单保留可回看；空态不占位。

### F2 [高] 未发送草稿不跨重启

- **现状**：草稿仅进程内按标签保存（docs/21「多标签草稿」：*当前为进程内保存*；后续批次第 5 条明确「未发送草稿的跨重启恢复仍未做」）。
- **缺口**：长提示词敲到一半关窗即丢失。
- **建议**：草稿按 `sessionId` 落 `PreferenceStore`（或新增 `drafts` 表），输入变化做 500ms 防抖写入；启动恢复仅对"仍存在的会话"生效，发送/切换会话后清除；附件不持久化（体积与安全），恢复时提示"附件未保留"。
- **验收**：写入后强杀进程重启，草稿正文回来；发送成功后草稿清空；删除会话时草稿一并清理。

### F3 [中] 设置项未做基础/高级分层

- **现状**：docs/21 后续批次第 6 条「分层未做」；当前 `SettingsSchema::categories()` 注册的 10 个分类在 `CategoryNav` 里平铺（模型配置 / 界面设置 / 通用设置 / 安全 / MCP 服务器 / 工具管理 / 记忆管理 / 用量统计 / 活动记录 / 设置与备份）。
- **缺口**：新用户被安全策略、MCP、工具开关等高级项淹没。
- **建议**：在 `CategoryNav` 上分「基础（模型配置、界面设置、通用设置）」与「高级（安全、MCP 服务器、工具管理、记忆管理、用量统计、活动记录、设置与备份）」两组，分组标题可折叠；不改变任何页面内部结构，纯导航层调整（`SettingsSchema` 的 order 不动，分组映射放 UI 层）；搜索命中时仍直接跳到目标页（`SettingsCatalog` 无需改动）。
- **验收**：两组默认折叠状态正确；搜索跳转不受分组影响；`test_settings` 中 `SettingsCatalog` 搜索/目录用例全绿。

### F4 [低] 会话导出只有 md / json

- **现状**：`AgentViewModel::exportSession` 仅接受 `md` / `json`，其它格式报错（`src/viewmodels/AgentViewModel.cpp:802-804`）。
- **缺口**：无法直接产出可分享的富文本归档。
- **建议**：新增 `html`（自带内联样式，图片走 data URL 或相对路径）与 `pdf`（复用已引入的 Qt6Pdf 写侧能力，若写侧 API 不足则先只做 html）。复用现有 Markdown 渲染路径，不新起一套。
- **验收**：导出 html 在浏览器打开样式完整、引用徽标可读；导出失败路径仍给出可读错误。

## 3. 批次 G：编码场景关键缺口

### G1 [高] 缺「计划/只读」权限档

- **现状**：`src/core/agent/PermissionMode.h` 三档为 `ConfirmChanges` / `AutoEdit` / `FullAccess`，最低档也允许确认后写文件、执行命令。
- **缺口**：用户想"先让它看代码、给出方案，但一个字都别改"时，只能靠提示词约束，模型仍可能直接动手。
- **建议**：新增 `PlanOnly` 档：写类工具（`file_write` / `edit_file` / `shell_exec` / `git_commit`）在 `processNextToolCall` 层直接拒绝并回灌"当前为只读模式"；`git_status` / `git_diff` / 读类工具照常。UI 在权限选择器加一档，文案说明"只读：仅分析与检索"。设置键沿用 `agent/defaultPermissionMode`，取值加 `plan_only`。
- **验收**：只读模式下写工具被拒绝且模型能收到可读原因并继续分析；切回其它档位立即恢复；新增 `test_agent` 用例覆盖四档矩阵。

### G2 [高] 输入框无 `@` 文件引用与路径补全

- **现状**：`InputConsole.qml` 只有拖拽附件与手写路径（全库无 mention 实现）。
- **缺口**：编码场景最高频交互缺失——想说"改一下 `src/core/agent/AIAgent.cpp` 的 `applyContextBudget`"只能整段粘贴路径。
- **建议**：输入 `@` 触发项目文件补全浮层（数据源复用 `glob` 的目录遍历，限定当前项目根、忽略 `.git` / `build` / `node_modules`）；选中后插入相对路径并在提交时作为"文件引用"上下文（可只给路径 + 片段，不整文件入 prompt，控制 token）。无项目归属的会话给出提示而非静默失效。
- **验收**：`@` 弹出补全、键盘可选、Esc 关闭；引用文件内容进入请求且不重复占用整份上下文；无项目时会话有明确提示。

### G3 [中] 无项目规则文件自动加载

- **现状**：全库无 `AGENTS.md` / `NEXUS.md` 读取逻辑。
- **缺口**：每个项目都要重复交代技术栈、构建命令、代码规范、禁区。
- **建议**：项目会话启动时按 `项目根/AGENTS.md` → `项目根/.nexus/rules.md` 顺序读取首个存在的文件，注入系统提示词（置于用户自定义 override 之后、工具说明之前），并计入上下文预算；文件大小设上限（如 8KB）并截断提示；UI 在项目行右键提供"编辑规则文件"。
- **验收**：存在规则文件时模型能复述其中约定；文件缺失不报错；超限截断有日志；规则内容不写进消息表。

### G4 [中] 文件改动无检查点与回滚

- **现状**：diff 只在工具确认弹窗展示（`src/ui/components/ToolConfirmDialog.qml:140` 附近）；DB 备份只覆盖 SQLite，不含工作区文件。
- **缺口**：模型改错文件，用户只能自己 `git checkout`，且无法区分"哪些是模型改的"。
- **建议**：`file_write` / `edit_file` 落盘前把原内容存入新增的 `file_checkpoints` 表（`session_id` / `path` / `before_content` / `timestamp` / `request_id`）；会话内提供「查看本次会话的文件改动」与「撤销某次改动」；非 git 目录同样可用；单文件与单会话都设体积上限，超出降级为"仅记录路径 + 提示用 git"。
- **验收**：撤销后文件字节级还原；同一文件多次修改按时间倒序逐次可撤；清理策略（会话删除 / 30 天）生效。

### G5 [中] RAG 不覆盖代码库

- **现状**：RAG 只面向手动导入的文档（`importDocument(s)` / PDF）；项目会话内无向量索引，模型只能靠 `grep` / `glob` 逐文件翻。
- **缺口**：中大型仓库里定位实现成本高。
- **建议**：项目级可选「建立代码索引」：按文件类型白名单（`.cpp/.h/.qml/.py/.md` 等）切块入库，复用现有 `VectorStore` 与嵌入链路，索引与知识库物理隔离（独立表或独立 collection）；增量按 mtime + 内容哈希；索引构建与重建走后台线程并显示进度；提供"排除规则"（沿用 `.gitignore` 语义）。
- **验收**：索引后可语义检索到实现位置并给出 `path:line`；增量重建只处理变更文件；删除项目时索引一并清理。

## 4. 批次 H：平台与集成

### H1 [高] 无 HTTP 代理设置

- **现状**：`SettingsDefinition.h` / `SettingsService.h` 无 proxy 相关键（联网搜索仅能配后端与实例地址）。
- **缺口**：企业网或受限网络下 OpenAI / Anthropic 直连不可用，整个应用不可用。
- **建议**：新增 `network/proxyMode`（`system` / `manual` / `off`）、`network/proxyHost`、`network/proxyPort`、`network/proxyAuth`（用户名/密码走 DPAPI）；在 `QNetworkAccessManager` 统一装配 `QNetworkProxy`，覆盖 LLM、嵌入、搜索、MCP HTTP 四条链路；提供"测试代理"按钮。SSE 流式请求必须同样生效。
- **验收**：三种模式行为正确；代理不可用时给出可读错误而非静默超时；密钥不落明文配置。

### H2 [中] MCP 只接了 tools

- **现状**：`src/core/mcp/McpClient.cpp:126` 只发 `tools/list`，另有 `notifications/tools/list_changed`。
- **缺口**：支持 `resources` / `prompts` 的服务器能力用不上。
- **建议**：分两步——先接 `resources/list` + `resources/read`，把资源以只读工具或上下文注入方式暴露（沿用现有确认与审计链路，`localOnlyMode` 同样门控）；`prompts` 与 `sampling` 单独评估（sampling 涉及反向请求，需先定安全边界）。
- **验收**：资源列表可见、读取成功且进审计；不可信数据声明对资源内容同样生效。
- **进展**（2026-11-09，docs/46）：`prompts/list` + `prompts/get` 已接入（fetch-and-insert，`/` 补全动态混入，`localOnlyMode` 门控，per-server ≤32）；`resources/*` 与 sampling 仍未做，维持本条剩余范围。

### H3 [低] 全局唤起热键

- **现状**：docs/20 §9 候选池登记，未做。
- **建议**：Windows `RegisterHotKey`（默认 `Ctrl+Alt+Space`，设置可改，冲突时提示）；触发行为：窗口不在前台则唤起并聚焦输入框。
- **验收**：热键冲突有提示；托盘与主窗状态一致；不注册时功能不报错。

### H4 [低] 无定时任务/自动化

- **现状**：全库无调度器（`schedule` 仅出现在 MCP 崩溃重启）。
- **缺口**：无法定时跑 prompt、定时抓取、定时生成报告。
- **建议**：最小可用形态——「定时任务」列表（cron 简化为"每天 HH:mm / 每周 X / 每 N 小时"），到点以指定模型与提示词新建会话执行，结果落会话并可选托盘通知；执行历史可查、可停用。不做任意表达式与依赖编排。
- **验收**：到点触发且只触发一次；应用未运行时的补偿策略明确（默认不补跑）；任务可停用与删除。

### H5 [低] 无斜杠命令与提示词库

- **建议**：`/` 前缀触发命令面板；内置少量（`/new`、`/clear`、`/model`、`/export`），用户可自定义"名称 + 提示词模板 + 默认附件策略"，存 PreferenceStore；模板支持 `{{selection}}`、`{{file}}` 占位。
- **验收**：命令与普通输入不冲突（首字符 `/` 且无空格时触发）；自定义命令可增删改；模板占位缺失时给出提示。

### H6 [低] 知识库不能从 URL 入库

- **现状**：只有本地文件导入。
- **建议**：复用 `network_fetch` 抓取 → 正文提取（HTML 去标签）→ 走既有分块/嵌入链路；记录来源 URL 与抓取时间，重新抓取时按内容哈希去重。
- **验收**：常见文档页可入库并检索命中；抓取失败分类提示；重抓不产生重复文档。

### H7 [远期] 子代理与并行编排

- **现状**：单 `AIAgent` 单循环，长任务无法拆分并行。
- **建议**：先只做"只读子代理"——主代理可派生 1~N 个只读子代理并行检索/分析，汇总后回到主循环；写操作仍由主代理串行执行。这是成本最低、风险最小的切入形态。
- **验收**：并行度可配且有上限；子代理失败不拖垮主任务；全程审计可追溯到父 request_id。

## 5. 批次 I：安全与长尾

### I1 [中] 数据库明文落盘

- **现状**：仅 API Key 走 DPAPI（readme 已声明），会话正文、知识库内容、审计日志均为明文 SQLite。
- **建议**：评估 SQLCipher 或对高敏字段（消息正文、知识库 chunk）做字段级加密；迁移需幂等且可回滚。此项涉及全表读写与性能，须先出独立方案再动手。
- **验收**：加密开启后功能不回归；密钥丢失有明确处置路径；备份/恢复链路同样适配。

### I2 [低] 无语音输入

- **建议**：优先接系统级方案（Windows 语音识别）或用户自带 API Key 的 Whisper 端点；录音只在本地，上传前显式确认。
- **验收**：转写文本进入输入框可编辑；无麦克风/无权限有提示。

### I3 [低] 快捷键不可自定义 ✅ 已落地（docs/31 N2，2026-10-30）

- **现状**：~~`ShortcutsDialog.qml` 是速查表，不是配置界面。~~ 已改为可由用户录制：`viewmodels/ShortcutMap` 集中默认表，设置中心新增「快捷键」分类，速查表按当前绑定动态生成。
- **建议**：改为可编辑列表 + 冲突检测 + 恢复默认；仅覆盖应用内快捷键，全局热键见 H3。
- **验收**：改键立即生效并持久化；冲突时不允许保存。

### I4 [低] 会话标题为截断首句 ✅（2026-11-01 实施）

- **现状**：~~`AIAgent.cpp:471` 用 `userMessage.left(60)` 作标题~~ 已实现自动生成：首轮回答落地后（与 episodic 摘要共用主服务、单请求语义，串行在其 `summaryStored` 之后）发一次廉价请求生成 3–8 词短标题，写库并 `sessionsChanged` 刷新侧栏。
- **实现**：`AIAgent::generateSessionTitle()`——`requestStarted/requestId` 身份关联防串音、15s 兜底解挂（被顶掉时无信号可回）、剥引号取首行限长 60 字符；失败静默保留截断标题，每会话至多一次；用户手动重命名永久跳过；新任务 `startTask` 时断连 + `cancel` 在飞请求。`setAutoSessionTitleEnabled` 供测试/嵌入关闭。
- **验收**：✅ 标题生成失败不影响会话；✅ 重命名优先于自动标题（test_agent 三用例）。

## 附记：I4 会话标题生成在 episodic 关闭时不触发 + 15s 兜底过紧（2026-11-02 修复）

用户反馈标题始终是截断的首条消息。根因有两个，都在静默路径上：

1. **标题生成串行在 episodic 摘要之后，以 `summaryStored` 为触发信号；而
`EpisodicService::generateAndStoreSummary` 的早退路径（`m_enabled=false` /
无 LLM 服务 / 无有效对话轮）直接 return、不发信号**。episodic 记忆默认关闭
（`memory/episodicMemoryEnabled` 默认 false），于是标题链的触发者永远不来
——首任务正常完成后 `m_titleAfterSummary=true` 挂起，无人生偿。修复：早退
路径也发 `summaryStored(sessionId, false)`，信号语义收敛为「摘要流程结束
（成败皆可）」。回归 `test_episodic::disabledServiceStillSignalsCompletion`。

2. **标题请求 15s 兜底过紧**：标题请求打到推理档模型（reasoningEffort=high
时 3–8 词的小请求也可能思考数十秒），超时即静默放弃（设计上失败不重试），
截断标题保留。放宽到 60s。
