NexusAI 是一个**本地优先的桌面 AI 智能体**:ReAct(Reason + Act)循环驱动的大模型对话 + 工具调用 + 知识库 RAG,基于 Qt 6.5+ / C++20 / QML,Windows 优先。本文按"先骨架、后心脏"的顺序带你读完代码,并以一条用户消息的完整旅程串起所有模块。

## 1. 目录地图

```
src/
├── core/                  # 纯 C++ 核心库,零 UI 依赖
│   ├── agent/             #   ReAct 主循环:AIAgent、AgentState、LLMTypes、EpisodicService(T8 情景记忆)
│   ├── memory/            #   会话持久化:IMemory 接口 + SqliteMemory 实现
│   ├── tools/             #   工具体系:ITool、ToolRegistry、Sandbox、WebSearchTool(T6 联网搜索)
│   ├── mcp/               #   MCP 客户端:McpClient、HttpTransport、McpToolAdapter
│   ├── rag/               #   知识库:RagService、DocumentRetriever、VectorStore、KnowledgeSearchTool
│   └── utils/             #   TokenEstimator(上下文预算)、Logger(轮转日志 + 历史回填)
├── infrastructure/        # 外部服务适配层
│   ├── llm/               #   IAIService 抽象 + LLMServiceBase 基类 + OpenAI/Anthropic/Ollama 三家实现
│   └── embed/             #   OllamaEmbedding(向量嵌入客户端)
├── viewmodels/            # MVVM 层:AgentViewModel、SettingsService、ThemeManager、McpManager、LogModel、TraceModel 等
├── ui/                    # QML 视图:main.qml + components/ + pages/ + panels/
└── main.cpp               # 依赖注入组装点
tests/                     # 18 个 QtTest 套件
docs/                      # 设计文档与技术路线(1-5 为历史文档,read_files/ 为本文档体系)
```

## 2. 分层与依赖方向

依赖严格单向,由 `CMakeLists.txt:34-150` 的四个目标声明:

```
nexus_ai (QML UI + main.cpp)
   → nexus_viewmodels (QML 单例, 依赖 core+infra)   CMakeLists.txt:81
      → nexus_infra (三家 LLM 服务 + 嵌入, 依赖 core)  CMakeLists.txt:59
         → nexus_core (agent/memory/tools/rag/utils)   CMakeLists.txt:34
```

读代码时记住两条铁律:

- **core 不知道 UI 和具体厂商存在**——它只认识 `IAIService`(抽象接口)和 `ITool`(抽象工具)。这也是为什么测试可以脱离网络跑。
- **所有 Provider 在接口层统一收敛为 OpenAI wire format**——`IAIService::chatComplete` 的入参消息和 `LLMResponse` 出参都是 OpenAI 格式(`src/infrastructure/llm/IAIService.h:20-24`、`src/core/agent/LLMTypes.h:11-20`),各家协议差异被封装在 infra 层内部转换。

## 3. 建议阅读顺序(8 步)

1. **`CMakeLists.txt:34-150`** —— 三个静态库 + 可执行文件的拆分就是架构图;`nexus_viewmodels` 是个 C++ QML 模块(`qt_add_qml_module`),UI 通过 `import NexusAI.ViewModels` 直接使用 C++ 单例。
2. **`src/main.cpp`** —— 整个应用的组装点,手工依赖注入:服务实例化(:91-93)、RAG 与嵌入接线(:101-112)、知识库工具注册(:114)、Agent 依赖注入(:116-118)、知识库持久化与启动恢复(:135-204)、设置→Provider 应用(:207-249)。看懂这个文件,就知道每个对象是谁、归谁所有、何时换配置。
3. **`src/core/tools/ITool.h` + `ToolRegistry.h/.cpp` + `Sandbox.h`** —— 工具体系最小闭环:工具接口(ITool.h:45-50)、三级安全策略(:9-13)、注册表(内建 5 个工具 `ToolRegistry.cpp:249-259`,另在 `main.cpp` 注册知识库检索、`web_search` 联网搜索与 MCP 动态工具)、路径沙箱。
4. **`src/infrastructure/llm/IAIService.h` + `LLMServiceBase.h`** —— Provider 契约:4 个信号、每请求上下文(`LLMRequestContext`)、子类要实现的 8 个协议钩子(LLMServiceBase.h:65-84)。
5. **`src/core/agent/AIAgent.h` + `AIAgent.cpp`** —— 心脏,见第 5 节精读指南。
6. **`src/viewmodels/AgentViewModel.h` + `TraceModel.h`** —— MVVM 桥:QML 单例模式、Q_INVOKABLE 动作面(AgentViewModel.h:168-191)、无 Agent 时的内置模拟管线。`TraceModel` 用按节点 id 的 diff(追加→rowsInserted、原地改→dataChanged)避免流式期间 delegate 全量重建。
7. **`src/ui/main.qml` + `pages/AgentChatPage.qml`** —— UI 组装:三栏布局(main.qml:22-111)、四个对话框、全局快捷键(main.qml:277-300)、trace 列表与输入台。
8. **`tests/`** —— 行为规格书。`test_agent.cpp` 的几十个用例就是 ReAct 循环的可执行规格;`test_provider_lifecycle.cpp` 用本地 FakeSseServer 走真实 HTTP 验证 Provider 生命周期。

## 4. 一条消息的旅程(端到端数据流)

```
用户在 InputConsole 按 Enter(src/ui/components/InputConsole.qml:85)
  → AgentViewModel.startTask()          src/viewmodels/AgentViewModel.h:175
  → AIAgent.startTask()                 src/core/agent/AIAgent.cpp:205
      新会话:生成 sessionId、写 system prompt、epoch+1
  → processIteration()                  src/core/agent/AIAgent.cpp:359
      折叠旧工具轮次 → 上下文压缩 → 发 thinking 轨迹节点 → 组装 tools 数组
  → IAIService.chatComplete()           (当前活跃的 OpenAI/Anthropic/Ollama 实现)
      SSE/NDJSON 逐块返回
  → streamingChunk → 100ms 节流刷新 trace 节点   AIAgent.cpp:658-676
  → onLLMResponse()                     AIAgent.cpp:453   ← 循环控制中枢
      ├─ 无工具调用 → finishTask(最终答案)
      ├─ 强制收尾/重复调用 → 封口并结束
      └─ 有工具调用 → processNextToolCall()
            ├─ Safe 工具 → dispatchToolExecution(AIAgent.cpp:799)
            │     QtConcurrent 工作线程执行,QFutureWatcher 回 GUI 线程
            │     epoch 校验通过 → finishToolExecution → 结果回灌消息
            ├─ RequiresConfirm → 挂起循环(AIAgent.cpp:782)
            │     toolConfirmRequired 信号 → QML ToolConfirmDialog
            │     用户批准/拒绝 → approveToolCall(AIAgent.cpp:897) 恢复循环
            └─ Dangerous/未知 → 拒绝并回灌错误,让模型自我纠正
      工具结果全部回灌后 → processIteration() 再来一轮(LLM 请求)
  → finishTask():保存 assistant 消息、发 responseReady
  → QML trace 列表增量渲染(AgentVM.traceModel)
```

关键点:**每轮 LLM 响应都会回到 `onLLMResponse`**,所有循环控制(预算、防重复、封口)都汇聚在这个函数;工具永远在 worker 线程跑,GUI 线程只做调度和渲染。

## 5. 五个最值得精读的位置

1. **`src/core/agent/AIAgent.cpp:453` `onLLMResponse`** —— 整个 ReAct 循环的分歧点:requestId 丢弃(ARCH-402)、强制收尾、重复调用终结器(:561)、tool_call_id 重生成(FIX-401)全在这。
2. **`src/core/agent/AIAgent.cpp:692` + `:727`** —— `collapseOldToolRounds`(旧工具轮次折叠)与 `sealUnansweredToolCalls`(悬空 tool_calls 封口)。两段代码保护的是同一个不变量:**发给模型的历史必须始终是合法的 OpenAI 序列**。理解了这个不变量,就理解了主循环一半的复杂度来源。
3. **`src/core/rag/DocumentRetriever.h:42-70` `addDocument`** —— 嵌入一致性设计:一个文档要么全部真嵌入、要么全部伪嵌入,绝不混维度;检索时按存储模式重新生成查询向量(:123-141);`addPrecomputedDocument`(:76-94)则从持久化分块零嵌入重建整个文档(Batch 6)。
4. **`src/core/tools/Sandbox.h:36-86` `validatePath`** —— 读/写两种白名单(读不含 Home,写含)、FullDisk 显式开关(:84)、边界感知前缀匹配(:118-125)。
5. **`src/main.cpp:207-249` `applySettings`** —— 唯一的"设置→运行时"同步点。只有活跃 Provider 收到 profile(main.cpp:219-230,注释解释了为什么不能广播),读沙箱策略也在这里跟随设置(main.cpp:233-235)。

## 6. 代码里的约定

- 命名空间统一为 `NexusAI`;类注释密度很高,**先读注释再读代码**——大量注释记录了"为什么这么写"(如 `AIAgent.cpp:26-29` 解释历史折叠的动机)。
- 源码注释中的编号(`ARCH-402`、`FIX-301`、`FIX-401`、`FIX-503`、`SEC-502`、`P0/P1`)来自 `docs/5-完善计划.md` 的审计批次,遇到时可回查该文档对应条目。
- 核心枚举(`AgentState`、`ToolLevel`)刻意不做 QML 注册,经 ViewModel 以 int 常量暴露(`AgentViewModel.h:32-41`),保持 core 零 QML 依赖。
- 中文场景是第一公民:Token 估算按 CJK 加权(`TokenEstimator.h:18-33`),分块按中英文句界切(`DocumentRetriever.h:183-187`)。
