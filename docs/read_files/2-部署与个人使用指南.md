## 1. 前置条件

| CMake | ≥ 3.24 | `CMakeLists.txt:1` |

| 构建器 | Ninja(推荐)或任意 CMake 生成器 | |

**源码位置**:`\\192.168.10.234\ai-agent`(局域网共享;`\\MATRIX\3project\qt\ai-agent` 为同一工程的旧路径,已弃用)。

Qt 工具链(qt 工具与 DLL 目录)需要在 PATH 中,或使用 Qt 官方安装器附带的命令行环境(Qt 6.x → MinGW/MSVC kit)。

## 2. 从源码构建

```bash
# 1) 配置(首次;加 -DBUILD_TESTS=ON 一并配置测试)
cmake -B build -G Ninja -DCMAKE_BUILD_TYPE=Release -DBUILD_TESTS=ON

# 2) 编译
cmake --build build

# 3)(可选)跑测试
ctest --test-dir build --output-on-failure

# 4) 运行
build\nexus_ai.exe
```

要点:

- 可执行文件是 `build/nexus_ai.exe`(`WIN32_EXECUTABLE`,无控制台窗口,`CMakeLists.txt:153-157`)。
- **没有安装包/部署目标**:仓库未内置 `install` 规则或 windeployqt 步骤。把 exe 拷到别的机器时,需要用 `windeployqt build\nexus_ai.exe` 收集 Qt DLL,或在装好 Qt 的环境里运行。
- 测试为可选目标(`BUILD_TESTS`,默认 OFF,`CMakeLists.txt:170-179`);18 个套件经 ctest 驱动(含 `test_embedding` 嵌入分页/进度、`test_web_search` 联网搜索、`test_episodic` 情景记忆等)。
- 测试验证记录:2026-09-25 全量 ctest **18/18 通过**(功能增强 T5–T9 / T14 交付后)。

## 3. 首次启动

未配置任何模型 profile 时,应用运行在**内置演示管线(模拟模式)**:AgentViewModel 不接真 Agent,用定时器模拟"思考 → 工具调用 → 回答"的完整轨迹(`AgentViewModel.h:19-23`、`main.cpp:285-289`),可以零配置体验全部界面。正式使用前在设置中添加 profile 并确认**模拟模式已关闭**(默认关闭)。

## 4. 配置模型

打开设置:`Ctrl+,` 或侧边栏齿轮。

1. **新建 profile** → 选择 Provider 类型(三选一)。
2. 填写端点与模型。默认值如下(`SettingsService.cpp:27-37`):

| Provider | 默认 baseUrl | 默认模型 | API Key |
|---|---|---|---|
| OpenAI 兼容 | `https://api.openai.com/v1` | gpt-4o-mini | 必填(本地端点 localhost/127.0.0.1 可留空) |
| Claude | `https://api.anthropic.com` | claude-sonnet-4-5 | 必填 |
| Ollama 本地 | `http://localhost:11434` | qwen2.5:7b | 不需要 |

3. 保存后,用聊天输入框下方的 **ModelSelector** 在多个 profile / 模型间切换,切换即时生效(设置变更由 `main.cpp:207-249` 同步到运行时,无需重启)。

实践提示:

- **OpenAI 兼容代理**:baseUrl 填到 `/v1` 为止(如 `https://your-proxy.example.com/v1`);不要给 Ollama/Anthropic profile 填带 `/v1` 的地址——主程序只把 profile 下发给对应 Provider(main.cpp:214-218 注释记录了这个坑)。
- **Ollama**:先 `ollama serve` 并 `ollama pull qwen2.5:7b`(或你想用的模型);本地模型响应慢是正常的,超时上限 300 秒。
- **知识库嵌入**同样依赖 Ollama:不用知识库可不装;离线时导入的文档会自动降级为本地伪嵌入(检索质量有限,界面上有"降级"角标,可在嵌入服务恢复后点"重新嵌入")。
- **嵌入模型可更换**:设置中的嵌入模型项(默认 `nomic-embed-text`)更改后,知识库会自动在后台全量重嵌(面板显示进度);重嵌完成前检索结果可能暂时不全。
- **连通性自检**:设置里的连接测试(ConnectionTester)会发一条最小请求验证 profile 可用。

## 5. 安全相关设置

- **`允许全盘读取`(allowFullDiskRead)**:默认**关闭**。关闭时 Agent 的 `read_file`/`list_dir` 只能读 文档/下载/桌面/AppData 白名单目录;开启后回到"全盘可读(系统目录仍禁止)"的旧行为。没有明确需要建议保持关闭(见 `SettingsService.h:54-57`、`Sandbox.h:82-85`)。
- **`仅本地模式`(localOnlyMode)**:默认**关闭**。开启后,知识库检索(云端模型时)、`web_search`、以及全部 MCP 服务器工具(`mcp__*`)会被禁用,模型不再看到它们的 schema。处理敏感内容时建议开启。
- **联网搜索**:`web_search` 默认使用 **DuckDuckGo**(免 API key)。国内网络下 DuckDuckGo 可能返回人机验证页,此时会明确提示「被反爬拦截」而不是「没找到结果」——此时请配置代理,或在设置中心 → 工具 → 联网搜索改用 **智谱 Web Search** 或 **DeepSeek Search**(均需各自的 API key)。调用前会弹确认框,未确认不外发。
- **MCP 服务器接入**:外部 MCP 工具以 `mcp__<server>__<tool>` 注册;系统提示词将 MCP 返回内容标注为**不可信数据**,工具描述截断 ≤1024 字符;工具数上限为单服务器 32 / 全局 64,超限禁用并告警。详见 README「MCP 安全注意事项」。
- **文件写入与命令执行**永远需要你在弹窗中逐次批准;Dangerous 级工具从不提供给模型(内置工具不含此级别,删除等破坏性操作经 `shell_exec` 确认执行)。
- API Key 在 Windows 上经 DPAPI 按用户加密存储(注册表),同机同用户才能解密。

## 6. 数据与日志位置

| 内容 | 位置 |
|---|---|
| 模型 profiles、界面设置 | 注册表 `HKCU\Software\NexusAI\NexusAI`(QSettings) |
| 会话/消息/轨迹/审计/知识库文档与分块向量 | `%APPDATA%\NexusAI\NexusAI\nexusai_memory.db`(SQLite) |
| 运行日志 | `%LOCALAPPDATA%\NexusAI\NexusAI\logs\nexus-YYYYMMDD.log`,按天轮转保留 7 天(`Logger.h:8-9`);审计日志也可在应用内 `Ctrl+L` 查看 |

> **注意**:日志与数据库的根目录**不同**——日志走 `QStandardPaths::AppLocalDataLocation`(`%LOCALAPPDATA%`,Local),数据库走 `QStandardPaths::AppDataLocation`(`%APPDATA%`,Roaming)。以 `Logger::logDir()`(`Logger.cpp:139-141`)与 `SqliteMemory`(`SqliteMemory.cpp:51`)实现为准。

## 7. 备份与迁移

- **完整备份**:备份数据库文件 + 导出注册表键(`reg export HKCU\Software\NexusAI\NexusAI nexusai-settings.reg`)。
- 迁移到新机器:数据库可直接拷;注意 API Key 是 DPAPI 按用户加密的,**跨机器/跨用户不可解密**,需在新机器重新填写。
- 知识库文档原文**和分块向量**都存在数据库中;重启恢复时,内容与嵌入模型都未变的文档直接从持久化向量重建、**零嵌入请求**,否则自动重嵌并回写(`main.cpp:153-204`)。恢复期间删除/清空知识库是安全的(有恢复代际保护,不会复活已删文档)。
- 旧版本数据库(无向量分块)首次启动会自动迁移 schema:旧文档标记为待重嵌,后台补齐向量,无需手工处理。

### 7.1 没有图形入口的新设置键

以下设置项目前**尚未提供设置中心图形入口**,需直接写入注册表键 `HKCU\Software\NexusAI\NexusAI`(QSettings):

| 配置键 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `webSearch/provider` | REG_SZ | `duckduckgo` | 搜索服务标识:`duckduckgo` / `zhipu` / `deepseek` |
| `webSearch/zhipuApiKey` | REG_SZ | 空 | 智谱搜索 API key;DPAPI 密文(`dpapi:v1:` 前缀),明文不会生效 |
| `webSearch/deepseekApiKey` | REG_SZ | 空 | DeepSeek 搜索 API key;同上 |
| `memory/episodicMemoryEnabled` | REG_DWORD | `0` | 长期记忆开关,`1` 开启 |

> 这些键的图形入口在规划中(见 `docs/12-NexusAI功能增强任务规划.md` §19 L1)。因 API key 需 DPAPI 密文,当前无 UI 时手动写入不便,建议等待图形支持。

## 8. 故障排查

| 症状 | 排查 |
|---|---|
| 发消息立即报 "No LLM service configured" | 没有配置任何 profile,或 activeProfile 的 provider 为空;去 `Ctrl+,` 添加并激活 |
| 本地 Ollama 连不上 | 确认 `ollama serve` 在跑;应用已对 localhost 自动绕过系统代理(`main.cpp:37-47`),若仍失败检查防火墙 |
| 走代理的网络环境请求失败/被劫持 | 应用按系统代理出网(仅 localhost 例外);确认代理对 API 域名放行 |
| 回答里 token 用量与官方对不上 | 用量为本地估算(CJK 加权),非官方计数;流式响应期间亦为估算 |
| 知识库检索质量差 | 看文档条目是否有"降级"角标(导入时嵌入服务不可用);恢复 Ollama 后点该文档的"重新嵌入"。刚更换过嵌入模型时,自动重嵌期间结果可能暂时不全 |
| 工具执行被拒绝 | 两种可能:路径出白名单(看 §5)、用户拒绝;详情看 `Ctrl+L` 审计日志 |
| 界面异常/崩溃 | 查 `%LOCALAPPDATA%\NexusAI\NexusAI\logs\` 当天日志;文件日志级别可调 |
| 长会话变得迟钝/报上下文超限 | 到「模型配置」页给该配置设「上下文预算覆盖」调低,让压缩提前触发;或开新会话 |
| 上下文预算到底用了哪个值 | 「模型配置」页在预算字段下方显示当前生效值与来源:配置覆盖 > 模型能力表 > 全局默认(128000) |

## 9. 日常运维备忘

- 日志只保留 7 天,无需手工清理;数据库会随使用增长,知识库大文档(>512 块)会被拒绝导入,单会话历史超预算自动压缩;更换嵌入模型会触发一次后台全量重嵌。
- 升级版本:重新构建覆盖 exe 即可;数据库/注册表向后兼容(旧单 Provider 配置会自动迁移为 profile)。
