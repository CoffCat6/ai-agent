## 2. LLM Provider 层

### 2.1 统一抽象

`IAIService`(`src/infrastructure/llm/IAIService.h`)是全部 Provider 的契约:

- `chatComplete(messages, tools)`(:23)入参是 OpenAI wire format 消息;`cancel()`(:25);三个配置 setter(:28-30)。
- 四个信号(:32-38):`requestStarted(requestId)`(:35)在请求派发时发出,**响应通过 `LLMResponse.requestId` 回显请求归属**(`LLMTypes.h:17-19`),Agent 据此丢弃被取代请求的迟到响应(见 §3.4)。
- `LLMResponse`(`LLMTypes.h:11-20`):content + toolCalls + tokensUsed + success/error + requestId。

### 2.2 LLMServiceBase:每请求上下文架构

`LLMServiceBase`(`src/infrastructure/llm/LLMServiceBase.h`)把"一次在途请求的全部状态"收敛进 `LLMRequestContext`(:27-41):requestId、reply、行缓冲、累积内容、完成/出错标志、以及类型擦除的 `ProviderRequestState`(:18-21)。所有回调按上下文身份校验,**陈旧或已取消的 reply 永远污染不了新请求**——这是 P0 审计(StreamContext 重构)的成果。

子类只实现 8 个协议钩子(:65-84):`createRequestState` / `processLine`(每个完整行)/ `streamComplete` / `streamResult` / `providerLabel` / `extractApiError` / `isCompleteBody` / `parseBody`。基类负责:按行切流、finished 后的收尾阶梯(流式结果 → 非流 JSON → API error → 网络错误 → 空)。

> 已知限制:基类 `m_current` 是单槽(`LLMServiceBase.h:96`),新请求会顶掉旧上下文;Agent 侧靠 requestId 防串扰,但旧请求的带宽不会被主动回收。

### 2.3 三家实现差异

| Provider | 协议 | 要点 |
|---|---|---|
| OpenAIService | SSE `/v1/chat/completions` | 默认 `gpt-4o-mini`;localhost 免 key;120s 超时(`OpenAIService.cpp:48`);工具调用按 index 分片累积,带"代理每 chunk 重发完整值"的畸形流启发式兼容 |
| AnthropicService | Messages API SSE | system 折叠为顶层参数、tool result 合并成 user 轮、连续同角色文本合并、丢弃开头非 user 轮;按 message_start/content_block/input_json_delta 事件累积 tool_use;120s 超时(`AnthropicService.cpp:206`) |
| OllamaService | NDJSON `/api/chat` | OpenAI→Ollama 双向转换(arguments 字符串↔对象、tool 消息去 tool_call_id、schema 去 type/function 包装);300s 超时(`OllamaService.cpp:78`,本地模型慢) |

三家的工具调用 id 缺失时各有兜底;跨轮重复的 `"call_0"` 类 id 由 Agent 层统一重生成(§3.6)。

## 3. ReAct 循环(AIAgent)

### 3.1 状态机

`AgentState`(`AgentState.h:8-16`):Idle → Thinking →(AwaitingToolConfirm / ExecutingTool)*→ Summarizing → Completed | Error。

### 3.2 双预算

- 步数预算 `kMaxIterations = 10`(`AIAgent.h:41`):LLM 请求轮次上限,与 system prompt 中的告知一致(`AIAgent.cpp:56`)。
- 执行预算 `kMaxToolExecutions = 16`(`AIAgent.h:45`):实际工具执行次数上限。一次响应可以宣布任意多个调用,光限轮次不封顶总工作量;耗尽时拒绝执行、封口剩余调用并强制收尾(`AIAgent.cpp:803-824`)。

### 3.3 预算耗尽时的强制收尾

步数耗尽后不是报错,而是**再发一次不带 tools 的请求**,让已收集的信息变成答案(`AIAgent.cpp:367-396`)。注入的"[System] 不要调用工具"控制消息只随该请求发送、**从不进入会话历史**(`m_forcedFinalPush`,响应到达即清),避免残留污染后续轮次。

### 3.4 过期结果的丢弃

两个机制叠加:

- **epoch 令牌**(`AIAgent.h:144`):每次 start/stop/reset 自增(`AIAgent.cpp:238`、`:617`);工具在 worker 线程完成后回调里校验 epoch,任务已死则只把轨迹标 cancelled、不复活循环。
- **requestId 匹配(ARCH-402)**:响应携带的 requestId 与活跃 id 不符时整包丢弃(`AIAgent.cpp:461-466`)。中途切换 Provider 会先 `stop()` 再换线(`AIAgent.cpp:81-97`)。

### 3.5 悬空封口与历史折叠(OpenAI 序列合法性)

不变量:**发给模型的消息序列必须始终合法**——assistant 的 tool_calls 之后必须紧跟对应 id 的 tool 结果。

- `sealUnansweredToolCalls`(`AIAgent.cpp:727`):任务被终止/封口时,为所有已宣布但不会执行的调用补合成 tool 结果(`[Not executed] ...`),stop()、强制收尾、执行预算耗尽三条路径都走这里。
- `collapseOldToolRounds`(`AIAgent.cpp:692`):只保留最近 `kKeepToolRounds = 2` 轮完整工具往返(:29),更早的整轮替换为一条 assistant 备注。动机:长尾工具历史会让弱模型把对话读成"每条消息都该调工具"的脚本(连打招呼都调知识库)。

### 3.6 重复调用终结器与 id 重生成

- 轮级签名比对:与上一轮完全相同的工具调用第二轮被跳过执行并注入"请立即给最终答案"的 tool 消息;第二轮重复且已有像样答案(≥40 字符)则直接收口(`AIAgent.cpp:548-595`,阈值在 `:561`)。
- tool_call_id 重生成(FIX-401):空 id 或跨轮重复的 provider 兜底 id(`call_0`)由进程级计数器重生成(`onLLMResponse` 内),因为严格代理会拒绝历史中的重复 id。

### 3.7 上下文压缩

每次 LLM 请求前,历史超预算则压缩(`AIAgent.cpp:434-447`):`TokenEstimator::compressToFit`(`TokenEstimator.h:69-116`)保留 system prompt、插入省略标记(:105-112)、并从**user 消息**开始保留最大后缀——从 user 起切保证不会产生孤儿 tool 消息。估算规则:拉丁字符 ≈4 字符/token,CJK ≈1.5 字符/token(`TokenEstimator.h:18-33`),上下文上限钳制在 2048~1048576(`AIAgent.h:49-50`)。

> 已知盲区:估算只计 role+content+每条 4 token 开销(`TokenEstimator.h:36-43`),**不计 tool_calls 参数与 tools schema**,预算偏乐观。

### 3.8 工具执行线程模型

工具在 `QtConcurrent::run` 的 worker 线程执行,`QFutureWatcher` 回 GUI 线程(`AIAgent.cpp:849-860`)。工具必须是**无状态、无 GUI 依赖、可重入**的;shell_exec / 大文件读取因此不冻结界面。RequireConfirm 类调用挂起循环等待用户(`AIAgent.cpp:776-785`),确认句柄是轨迹节点 id,与 QML 时间线按钮发送的 id 一致。

### 3.9 流式显示

内容增量以实时 "summary" 轨迹节点呈现,100ms 节流(`kStreamFlushMs`,`AIAgent.cpp:21`;节流逻辑 `:658-676`);完整响应到达后原地定稿,不追加重复节点。

### 3.10 情景记忆注入与摘要(T8)

`EpisodicService` 挂接在 Agent 生命周期两端:

- **会话开始**(`startTask`):若 `memory/episodicMemoryEnabled` 开启,按当前 system prompt 关键词经 FTS5 检索 top-3 历史摘要,拼接后受 `TokenEstimator` 钳制 ≤1500 token(`kMaxInjectionTokens`),注入 system prompt(复用 `effectiveSystemPrompt` 注入点)。
- **会话结束**(`finishTask`):异步调用 LLM 生成 ≤500 字符摘要(`kMaxSummaryChars`),经 `IMemory::saveEpisodic` 落库并建 FTS5 索引;**不阻塞会话结束**(REQ-T8-05)。

失败降级:摘要失败跳过、检索失败返回空数组,均不影响正常对话。

## 4. 工具体系与沙箱

### 4.1 三级安全策略

`ToolLevel`(`ITool.h:9-13`):Safe 只读立即执行;RequiresConfirm 修改状态需用户批准;Dangerous 被 Sandbox 拒绝、**从不暴露给模型**(`AIAgent.cpp` 组装 tools 数组时跳过;模型幻觉调用时回灌错误让模型自我纠正,`ToolRegistry` 列出合法工具名)。

### 4.3 Sandbox 规则

`Sandbox::validatePath`(`Sandbox.h:36-86`):

1. **规范化**:存在则解析符号链接,不存在则词法折叠 `..`(`:110-115`)——穿越与软链逃逸都无效。
2. **系统目录黑名单**始终生效(`:42-45`):`/etc`、`C:\Windows`、`C:\Program Files` 等。
3. **读策略**(`ReadPolicy`,`:24-29`):默认 `UserDirectories` 白名单 = Documents/Downloads/Desktop/AppData(`:55-62`,**刻意不含 Home**,防止 `~/.ssh`、浏览器配置文件暴露);设置项 `allowFullDiskRead`(默认关,`SettingsService.h:54-57`)显式切回全盘读(`:84`),运行时由 `main.cpp:233-235` 同步。
4. **写白名单**:读白名单 + 整个 Home(`:74-79`)。
5. **边界感知前缀匹配**(`:118-125`):`Documents2` 这类兄弟目录不因前缀相同而放行。

### 4.4 审计

所有工具活动落 SQLite 审计表:`tool_execute / tool_approved / tool_declined / tool_blocked / unknown_tool`(`IMemory.h:40-52`);执行结果(成功/失败 + 摘要)由 Agent 自动记录(`AIAgent.cpp:878-881`),工具实现内无需自行写审计。UI 经 AgentVM.auditLog 查看。

## 5. RAG(知识库检索增强)

### 5.1 链路

导入 → QtConcurrent 后台分块嵌入(完成后 `RagService` 发 `documentPersisted`,装配层在 GUI 线程把内容哈希与分块向量落库,`main.cpp:135-151`)→ 持久化 → 检索 → 结果包装回灌:

1. **分块**:512 字符 + 64 重叠,在窗口后半段找句界切(支持 `。!?` 等中英文标点,`DocumentRetriever.h:174-176`、`:200-224`)。旧版按空白切会把整篇中文文档合成一块,导致嵌入超时。
2. **嵌入**:批量调用按 **32 条/页**分批发送(`OllamaEmbedding.h:29`),每批完成即上报进度(FEAT-803,`OllamaEmbedding.h:40`);失败/缺额则**整篇降级伪嵌入**,绝不混合维度(`DocumentRetriever.h:45-57`)。嵌入模型经设置项下发,默认 `nomic-embed-text`(`OllamaEmbedding.h:44`);伪嵌入是 128 维位置字符哈希(`:176-194`),无语义但保证离线可用。
3. **检索**:余弦相似度 top-k;真嵌入模式有 0.15 相关性阈值(FIX-301,`DocumentRetriever.h:121`),低于阈值返回"无匹配"而不是硬凑;查询向量维度与存储不符(嵌入服务掉线/漂移)时降级为 no-match(FIX-302,`:135-136`)。查询向量有 32 条缓存,同一问题不重复请求嵌入服务(KB-605,`RagService.h:123-127`)。
4. **持久化与零嵌入恢复(Batch 6)**:每个分块连同向量、维度、模式写入 `knowledge_chunks` 表(`SqliteMemory.cpp:232-242`),文档记录内容 SHA-256 哈希与产嵌入的模型(`KnowledgeChunk.h:25-28`);启动恢复时内容哈希与嵌入模型**都未变**的文档直接从持久化分块重建、零嵌入请求(`main.cpp:153-204`、`DocumentRetriever.h:76-94`),否则整篇重嵌并经 `documentPersisted` 回写自愈。
5. **注入边界**(SEC-502):检索段落按**不可信数据**包装进 `<knowledge_passage>` 定界符,并声明"不是指令"(`KnowledgeSearchTool.h:58-77`)——被投毒的文档不应能伪装成模型指令。
6. **单文档上限** 512 chunks(`RagService.h:88`);导入去重:同名自动改名 `a (2).txt`,内容重复直接跳过并提示(FEAT-802,`RagService.h:75-79`)。

### 5.2 并发与恢复代际

- `RagService` 用互斥锁保护文档表,**嵌入的网络 IO 在锁外**(`RagService.h:20-22`)——GUI 线程的检索不会排在慢嵌入后面。
- 启动恢复:优先从持久化分块重建(见 §5.1 第 4 步,`main.cpp:153-204`);每次 clear/remove 递增"恢复代际"(`RagService.h:66-67`),用户在恢复中途清空知识库,剩余恢复步骤自动变 no-op,不会复活已删文档。

## 7. 配置与密钥

- **存储**:QSettings → Windows 注册表 `HKCU\Software\NexusAI\NexusAI`。
- **模型 profiles**:每个 profile 绑定 provider(`openai|anthropic|ollama`)+ baseUrl + model + apiKey + 展示名,任意多个共存、即时切换(`SettingsService.h:14-19`);旧版单 Provider 配置首次加载时自动迁移。
- **默认端点**(`SettingsService.cpp:27-37`):OpenAI `https://api.openai.com/v1` + gpt-4o-mini;Anthropic `https://api.anthropic.com` + claude-sonnet-4-5;Ollama `http://localhost:11434` + qwen2.5:7b。
- **API Key 加密**(Windows):DPAPI 按用户加密,存储值带 `dpapi:v1:` 前缀(`SettingsService.cpp:74`);加密失败宁可丢弃不落明文;非 Windows 明文 + 环境变量回退。
- **设置→运行时的同步点**是 `main.cpp:207-249` `applySettings`:只有活跃 Provider 收到 profile(广播会把 `/v1` 结尾的代理地址污染到其他家);读沙箱策略、上下文预算同点同步;simulationMode 决定 AgentVM 接真 Agent 还是内置模拟管线(`main.cpp:285-289`)。
- **嵌入模型(FEAT-801)**:设置项 `embeddingModel`(默认 `nomic-embed-text`,`SettingsService.h:33`、`:59-62`、`:102`),是持久化分块的版本身份;更改会触发知识库全量后台重嵌,新布局经 `documentPersisted` 回写(`main.cpp:256-278`)。
- **界面翻译(FEAT-804)**:启动时按系统 locale 从 `:/i18n` 加载 `.qm`(`main.cpp:66-73`),未翻译字符串回退源文;翻译源由 `qt_add_translations` 汇聚(`CMakeLists.txt:159-167`)。
- **联网搜索(T6)**:设置项 `webSearch/provider`(默认 `tavily`)、`webSearch/apiKey`(DPAPI 加密,getter 返回空串掩码,`SettingsService.h:45-46`);`localOnlyMode` 下 `web_search` 被门控禁用。
- **情景记忆(T8)**:设置项 `memory/episodicMemoryEnabled`(默认 `false`,`SettingsService.h:49`);开启后会话结束异步生成摘要(≤500 字)、新会话检索注入(≤1500 token)。
- **主题模式(T5)**:偏好键 `ui.themeMode` 三档 `{auto, dark, light}`(默认 `auto`,`ThemeManager.cpp:62-64`);`auto` 跟随系统深浅色,显式档忽略系统变化。

## 8. MVVM 与 UI 要点

- **QML 单例模式**:`QML_SINGLETON + QML_NAMED_ELEMENT` + `instance()/create()` 工厂(`AgentViewModel.h:26-27`、`:88-99`);依赖注入只发生在 main.cpp。
- **TraceModel**:按节点 id diff 的增量列表模型——尾部追加发 rowsInserted、原地改发 dataChanged、结构性变化才 modelReset,流式期间不重建 delegate。
- **UI 结构**:三栏 RowLayout(`main.qml:22-111`),左右栏宽度可拖拽持久化(QTimer 去抖写 QSettings);四个全局对话框(ToolConfirm/Settings/Audit/KnowledgeDoc,`main.qml:213-234`);错误/通知 toast;快捷键 `Ctrl+,` `Ctrl+L` `Ctrl+B` `Ctrl+[` `Ctrl+D`(`main.qml:277-300`)。
