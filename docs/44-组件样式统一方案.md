**一句话方案**：把“科技极简”的既有视觉基准（32 高、6 圆角、品牌色焦点环、hover 用 `surfaceHover`）从 `AppButton` 这类自绘组件，下沉成一份全应用生效的 Qt Quick Controls 样式；业务 QML 不再各自拼控件外观，只保留少量业务特例。

**不改变的事实**：`AppButton`（204 处引用）、`IconButton`、`AppScrollBar`（28 文件 / 35 处）都是自绘组件，**不受** `QQuickStyle` 影响，本方案不改它们（`src/ui/components/AppButton.qml:4-5`、`src/ui/components/AppScrollBar.qml:10`）。

## 1. 目标与范围

### 1.1 目标

1. **统一**：原生 `Button / ComboBox / TextField / Switch / CheckBox / RadioButton / SpinBox / Slider / Menu / ToolTip / ScrollBar` 等控件的高度、圆角、间距、字号与四态，消除各页面各写一套的参差。
2. **可辨识**：hover / pressed / focus / disabled 四态在同一套 token 下可预测；键盘焦点必须可见。
3. **克制**：只做底色、1px 边框、2px 焦点环、必要的短动效；**不加阴影、模糊、发光**（延续 `docs/19 §5.4` 的零特效分层策略）。
4. **低风险**：业务 QML 基本不动；样式可按控件粒度回退 Basic；现有 QML 测试套件不受影响。
5. **可验证**：尺寸、颜色、对比度、qmllint、ctest 均有量化门禁。

### 1.3 明确不做

| 不做项 | 原因 |
|--------|------|
| 不引入阴影 / 模糊 / 发光特效 | 延续 `docs/19` 的零特效策略；`ThemeProvider.h:95-109` 的 `elevation*` 令牌当前未接入渲染，本方案不启用 |

## 2. 设计规范

### 2.1 规格常量（落在 `NexusMetrics.qml`，不污染 Theme）

`NexusMetrics.qml` 是一个普通 `QtObject` 组件（**不是** `pragma Singleton`，也不写入 `qmldir`）：控件文件通过同目录隐式导入，以 `NexusMetrics { id: metrics }` 实例化后引用 `metrics.heightControl` 等常量。选择实例化而非单例，是为了避开 qmldir singleton 声明与 qmlcachegen 预编译的耦合风险（实测结论见 §10 V4）。

### 2.2 四态语义表（所有控件共用；个别控件在 §2.3 注明例外）

| 语义 | 字段 / 选项类（TextField、ComboBox、SpinBox、ItemDelegate） | 中性按钮（Button、ToolButton） |
|------|------------------------------------------------------------|-------------------------------|
| **默认 S0** | 底 `bgPrimary`（暗 #0A0A0F / 亮 #F5F7FA）+ 1px `borderSubtle`（暗 #2A2A3A / 亮 #E5E8EB）+ 字 `textPrimary` | 底 `surfaceHover`（暗 #1C1C26 / 亮 #EBEDF0）+ 1px `borderSubtle` + 字 `textPrimary` |
| **悬停 S1** | 底 `surfaceHover` + 1px `cardBorder`（暗 #3A3A52 / 亮 #CBD2DA） | 暗：`Qt.lighter(surfaceHover, 1.20)` ≈ #2E2E3D；亮：`Qt.darker(surfaceHover, 1.07)` ≈ #DCDDE0（以 `NexusStyle/Button.qml:35-50` 函数为准） |
| **按压 S2** | 底 **`controlBackgroundPressed`**（新，暗 #20202C / 亮 #DEE2E7）+ 1px `cardBorder` | 暗：`Qt.lighter(surfaceHover, 1.45)` ≈ #37374A；亮：`Qt.darker(surfaceHover, 1.14)` ≈ #CED0D3 |
| **焦点 S3** | 2px `brandPrimary`（暗 #00F0FF / 亮 #0052D9）边框；不改变控件尺寸 | 2px `brandPrimary`；品牌填充按钮改用 2px `bgPrimary` 内/外环，避免同色不可见 |
| **禁用 S4** | 底 **`controlBackgroundDisabled`**（新）+ 1px **`controlBorderDisabled`**（新）+ 字 **`controlTextDisabled`**（新） | 整体 `opacity: 0.5`（沿用 `AppButton.qml:30` 口径） |
| **品牌填充 S0'** | 底 `brandPrimary`，前景/图标 `bgPrimary`（暗底对亮青 14.0:1，亮底对蓝 6.1:1） | 同左 |
| **品牌悬停 S1'** | 底 **`controlBrandHover`**（新，暗 #33F3FF / 亮 #1A63DD） | 同左 |
| **品牌按压 S2'** | 底 **`controlBrandPressed`**（新，暗 #00C4D1 / 亮 #0047BE） | 同左 |
| **选中标记** | `brandPrimary`（3px 左侧条 / 12px 勾选符号） | `brandPrimary` |

> **为何禁用态不用 `opacity`？** 父级已有透明度时再乘 0.5 会“灰上加灰”，且不同页面背景导致禁用态深浅不可控。字段类改用显式填充/边框/文本三 token，可让 42 个对话框内的输入框表现一致。Button 保留 `opacity` 是为了与 204 处 `AppButton` 的既有观感对齐。

## 3. Theme token 扩展清单

### 3.1 新增 token（6 个）

| # | 名称 | 类型 | 暗色值 | 亮色值 | 用途 | 为什么现有 token 不够 |
|---|------|------|--------|--------|------|----------------------|
| T1 | `controlBackgroundPressed` | QColor | `#20202C` | `#DEE2E7` | 字段/选项/中性控件的按压底色 | 现有只有 `surfaceHover` 一档悬停；按压若继续用 `surfaceHover` 会与 hover 无法区分，逐文件写 `Qt.lighter/darker` 会漂移 |

### 4.3 CMake 资源注册（主方案）

**任务 #1 已验证的接入结论**：`QQuickStyle::setStyle()` 只接受“样式名”，含 `/` 的路径会被 Qt 拒绝（告警 `Style names must not contain paths`）并回退 Windows 原生样式。因此不能用 `setStyle(":/NexusStyle")`；正确做法是把 qmldir + 控件 QML 放到 `:/qt/qml/NexusStyle/`，再 `setStyle("NexusStyle")`。当前已落地：`src/main.cpp:258-263`、`CMakeLists.txt:424-440`。

> 注：当前实现改为 `file(GLOB ... CONFIGURE_DEPENDS)` 自动收集样式目录 `*.qml`，新增控件无需再改 CMake；`qmldir` 仍逐行登记以保留单控件回滚能力。

在现有 `qt_add_resources(nexus_ai "nexus_style" ...)`（`CMakeLists.txt:431-438`）基础上补齐文件清单，并抽成函数供测试 target 复用：

```cmake
# ── NexusStyle：自定义 Qt Quick Controls 样式（纯 QML） ──
# PREFIX 必须是 /qt/qml/NexusStyle：Qt 6 的默认 QML 导入根是 :/qt/qml，
# setStyle("NexusStyle") / import NexusStyle 都从这里解析。
# BASE 必须设置，否则 alias 会保留 src/ui/style/... 的源相对路径
#（同类坑见 app icon 的 BASE 注释，CMakeLists.txt:426-462）。
set(NEXUS_STYLE_DIR "${CMAKE_CURRENT_SOURCE_DIR}/src/ui/style/NexusStyle")
# 每控件一文件：GLOB + CONFIGURE_DEPENDS 让新增 *.qml 自动进入资源。
# NexusMetrics.qml 也在其中（控件靠同目录隐式导入引用，不登记 qmldir）。
file(GLOB NEXUS_STYLE_QML_FILES CONFIGURE_DEPENDS "${NEXUS_STYLE_DIR}/*.qml")

# 同一函数供 app 与 QML 测试 target 复用：资源必须编进每个消费进程，
# 否则测试进程里 :/qt/qml/NexusStyle 不存在，setStyle("NexusStyle") 会失败。
function(nexus_add_style_resources target)
    # QT_RESOURCE_ALIAS 是源文件属性：多 target 复用时旧值会被复用，必须
    # 显式把每个文件钉成其文件名，否则 :/qt/qml/NexusStyle/Button.qml 缺失。
    foreach(_style_file "${NEXUS_STYLE_DIR}/qmldir" ${NEXUS_STYLE_QML_FILES})
        get_filename_component(_style_name "${_style_file}" NAME)
        set_property(SOURCE "${_style_file}" PROPERTY QT_RESOURCE_ALIAS "${_style_name}")
    endforeach()
    qt_add_resources(${target} "nexus_style"
        PREFIX "/qt/qml/NexusStyle"
        BASE "${NEXUS_STYLE_DIR}"
        FILES "${NEXUS_STYLE_DIR}/qmldir" ${NEXUS_STYLE_QML_FILES})
endfunction()

nexus_add_style_resources(nexus_ai)

# qmllint 门禁：样式文件不在 QML_FILES 中，configure 阶段生成独立 rsp
# （--bare + -I <build> 解析 NexusAI.ViewModels + -I <Qt qml> + 全部样式路径）。
```

- 资源别名必须为 `:/qt/qml/NexusStyle/qmldir`、`:/qt/qml/NexusStyle/Button.qml`；`:/NexusStyle/...` 不是可导入模块路径。
- 建议仿 `cmake/CheckIconResources.cmake` 增加 configure-time 检查：断言生成的 `.qrc` 含 `alias="qmldir"` 且前缀为 `/qt/qml/NexusStyle`，防止路径再次静默漂移（依据：`CMakeLists.txt:426-440` 记录的 icon 资源踩坑）。
- 测试 target 同样调用 `nexus_add_style_resources(<test_target>)`；**不要**把 qrc 放进纯静态库再由测试链接——静态库中的 qrc 初始化对象可能被链接器丢弃（**推测/需在任务 #4 验证**），直接挂到每个可执行 target 最稳。

**备选方案（若后续需要 qmlcachegen 预编译 / qmllint 自动覆盖）**：独立 QML 模块

```cmake
qt_add_library(nexus_style STATIC)
qt_add_qml_module(nexus_style
    URI NexusStyle
    VERSION 1.0
    QML_FILES ${NEXUS_STYLE_QML_FILES})   # 只列 *.qml；qmldir 由 qt_add_qml_module 生成
add_dependencies(nexus_style nexus_viewmodels)   # 样式 import NexusAI.ViewModels（Theme）
target_link_libraries(nexus_ai PRIVATE nexus_style nexus_styleplugin)
```

对应 `QQuickStyle::setStyle("NexusStyle")`（与主方案同名，切换成本低）。优劣对比：

| 维度 | 主方案：qrc 目录 `:/qt/qml/NexusStyle` | 备选：`qt_add_qml_module` 模块 |
|------|----------------------------------------|-------------------------------|
| 接入复杂度 | 低（`qt_add_resources` 即可；当前已落地） | 中（多一个库/插件 target、依赖排序） |
| `setStyle` 参数 | `"NexusStyle"`（**路径形式已被任务 #1 证伪**） | `"NexusStyle"` |
| qmlcachegen 预编译 | 否（资源文件不进 QML_FILES） | 是 |
| qmllint 门禁覆盖 | 已扩展（§5.5：独立 `nexus_style.rsp`） | 自动覆盖（生成 `.rsp`） |
| 跨模块 import Theme | 运行时解析，风险低 | 编译期解析，需 `-I build`（已有 `CMakeLists.txt:20-23`） |
| 与 `nexus_ai` 模块关系 | 独立 URI，完全解耦 | 独立 URI，完全解耦 |

### 4.6 `NexusMetrics.qml` 形态（集中出口，减少 17 个控件文件的漂移）

`NexusMetrics.qml` 是普通 `QtObject` 组件，**不是** `pragma Singleton`，也不在 `qmldir` 登记。控件文件通过同目录隐式导入实例化它：

```qml
import QtQuick

// 规格常量的唯一出口；颜色不在此处，一律走 Theme token。
// 用法（同目录隐式导入，无需 import）：NexusMetrics { id: metrics }
QtObject {
    readonly property int heightControl: 32
    readonly property int heightOption: 30
    readonly property int heightTextAreaMin: 64
    readonly property int widthSwitchTrack: 36
    readonly property int heightSwitchTrack: 20
    readonly property int sizeSwitchThumb: 16
    readonly property int sizeCheckIndicator: 16
    // ... 滑块/滚动条/焦点环等常量
}
```

控件内写法：

```qml
NexusMetrics { id: metrics }
height: metrics.heightControl
```

> **已验证（§10 V4）**：同目录隐式导入可用，且无需 `pragma Singleton`；qmllint 对该文件无依赖解析问题。此结论已替代早期“待验证”的备选方案（不再需要在控件顶部加 `import "."` 或注册 singleton）。

### 5.2 TextField 局部 `background` 覆盖

全仓 21 个文件存在 `background: Rectangle`（`grep -rln` 实测）。分类处理：

| 类别 | 代表位置 | 处理策略 | 批次 |
|------|----------|----------|------|
| 仅为复述“6px 圆角 + 焦点 2px 品牌色 + surfaceHover 底”的重复覆盖 | `McpServerEditor.qml:183,220,238,262,280`；`OnboardingDialog.qml:478,503,527`；`PreferenceControl.qml:166-171`；`SettingsField.qml:114`；`ParamSelectRow.qml:139-144` | **保留不动（P0）**；B1 视觉验收后可选清理，删除后自动吃到新样式 | B1（可选） |
| 业务有意的特殊底（如 `bgPrimary` vs `surfaceHover`） | `ParamSelectRow.qml:139-144`（`bgPrimary`）vs `PreferenceControl.qml:166-171`（`surfaceHover`） | 保留差异；若视觉验收要求完全统一，再按页面统一到样式默认 | B1 之后 |

| Dialog/Popup 的 `contentItem` 内 TextField | `InputConsole.qml:1139,1201,1304,1410` | 不动；仅四态颜色可由样式兜底（实例未覆盖时） | — |

**优先级规则**：QML 实例显式赋值的 `background` / `contentItem` / `delegate` / `indicator` 只**替换对应的槽位**，不是整控件替换。因此：
- 局部 `background` 覆盖**不会**导致新样式“完全不生效”：`padding` / `implicitHeight` / `implicitWidth` 等由样式模板计算的属性仍然生效，控件高度与内边距继续走统一样式公式，只是底色/边框由业务覆盖；
- 代价是被覆盖的控件不吃样式层的 hover/press 底色，需要业务自行维护（`contentItem` / `delegate` 覆盖同理，只影响被替换的内容对象）；
- **兼容处理**：TextField / TextArea 的上下 padding 已恢复为 `6`（此前收口为更小值），以兼容全仓 29 处局部 `background` 覆盖的既有高度，避免这些输入框在样式生效后变矮；
- 局部覆盖按本节分类**保留**，不属于回归缺陷，也不作为“样式不生效”的证据。
